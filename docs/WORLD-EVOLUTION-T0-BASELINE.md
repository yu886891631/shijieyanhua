## 4. 本轮确认的关键风险

| 风险 | 源码证据/原因 | 新系统必须采取的措施 |
| --- | --- | --- |
| 关闭插件不保证旧启动路径只读 | `index.ts` 的启动/CHAT_CHANGED 调 `retryPendingWorldbookSync`；后者只看 `worldbookAutoSync`，未检查 enabled/实际 pending；旧设置缺省同步为 true | T0 不加载旧入口；T8/T10/T12 的恢复也经过模式、有效身份、权限和所有权门槛 |
| 测试包说明不能强制模拟 | `world_evolution_api_test_mode` 没有源码消费者；手动/自动/重试仍可走真实路由 | 模拟必须使用明确假适配器；不依赖 UUID、说明文字或未消费配置字段 |
| 删楼/swipe 监听可能写旧库 | 数据库入口始终注册 mutation scheduler，不依赖 enabled | T0 不触发实际删楼/swipe、不加载监听；后续启停与旧入口接管需核对 |
| “任一成功”不等于全部前置完成 | 旧工作流 hasSuccess/轮询只看任一任务成功；无工作流约 6.4 秒后兜底 | T7/T8 对每个必要来源验证当前 message/swipe 和完成证据，未知/失败不自动放行 |
| 外部导出读取不代表兼容真实行 | 现有适配器接受 rows/data/items；参考库为 `sheet_*.content` 表头＋二维行 | T7 使用真实形态固定样本和映射预览，不把表名当候选姓名 |
| 切聊天/运行中取消存在旧路径缺口 | 队列 runner 只传 messageId，执行重新取当前 chat；cancel 只移除未运行任务 | 新运行冻结身份并传播取消；过期结果不提交，不沿用旧闭包 |
| 无聊天身份检查不足 | `getCurrentChatKey()` 可返回 `unknown_chat`，旧入口只检查空字符串 | 未知身份禁止正式存档/自动生成，不能放进一个公用 unknown 世界 |
| 世界书保留另一聊天条目不等于隔离 | 旧投影按 chatKey 保留条目；锁是 JS 实例内 Map，没有主 AI 捕获版本证明 | T0 声明能力门槛；T12 无法证明隔离时阻断投影 |
| 重试可能叠乘 | 队列整轮重试＋客户端重试＋备用路由 | T7/T8 每次发送消费全链共享额度，取消/超时结果明确，不能承诺撤销已收费请求 |

上述是静态路径确认，不表示本轮已经发生用户数据覆盖。没有为验证风险去执行这些真实路径；旧版修复也没有混进 T0。

## 5. 前置来源的可行性边界

### MVU

`Mvu.getMvuData` 可读取目标楼层数据。`VARIABLE_UPDATE_ENDED` 的本地声明包含新旧变量，但没有稳定 message/swipe 或持久化确认凭证。旧引擎仅取快照、失败返回 null，没有证明前置更新已完成。

新适配器必须等待可用接口，并只读捕获对应来源身份/数据指纹；不调用解析、替换变量等写方法。单个结束事件或“取到了 stat_data”都不能独自当作本轮正式完成证明。

### SP·数据库

现有桥可用 `AutoCardUpdaterAPI.exportTableAsJson()` 取当前表和注册更新回调。参考实现导出内存数据；更新回调有 `{persisted}` 区分，且支持注销。导出/回调本身未充分证明目标消息/swipe 的对应提交。

真实形态样本来自参考库 `tests/integration/sqlite-full-chain.test.ts`、`tests/data/sqlite/sync-bridge.test.ts`，不是当前人工 `rows` mock。T7 至少覆盖表头＋二维行、中文列、native/sqlite 差异、未知格式及来源身份；读取禁止写回。

### 工作流助手

现有完成事件提供 chatKey、messageId 与任务结果，但 `hasSuccess` 只是至少一个任务成功。T8 需要各必要任务状态，不沿用任一成功放行逻辑；旧 swipe/旧剧情事件不放行当前运行。

未安装/停用来源可明确不参与；已启用但能力未知的来源不能用超时假装完成。具体适配与支持模式由 T7/T8 实现，不在 T0 假称已经接通。

## 8. T0 隔离脚手架与测试记录

新增文件：

- `src/世界演变/rebuild/t0-sandbox.ts`。
- `src/世界演变/rebuild/t0-sandbox.test.ts`。

脚手架的边界：

- 模式固定为 `fixture-only-memory`，范围前缀 `world-evolution:t0:sandbox:`；没有 live 模式工厂或真实回退分支。
- 假 API 只消费显式成功/失败 fixture；失败或耗尽不会联网重试。
- 假 JSON 存档和假世界书只保存在各工厂闭包内存，读写必须提供对应 scope/worldId；不同实例不能混用范围。
- 构造、请求、读写和返回结果均隔离克隆；调用者改原对象或读出对象不改变内部状态。
- 不导入现有 engine/store/入口，不访问 IndexedDB、localStorage、MVU 或任何宿主全局函数，不读取旧凭据。
- scope 的实例序号只在本次模块生命周期内有效，不是跨刷新/跨 iframe 的正式世界身份、运行所有权锁或安全认证协议。
- T0 的 fixture 数据是测试用 JSON；本模块不是 T13 的不可信导入验证器。生产身份在 T2/T4 固定；SQLite、原子提交、耐久保存和跨刷新恢复分别由后续阶段实现。
