# T13：旧数据迁移与备份向导

日期：2026-10-09。范围：本地 SQL 重建组件、模拟存档/宿主、只读 IDB 接口夹具和 Vue 工作台；不操作实际聊天、API、IndexedDB 或世界书，不自动开始 T14。

状态：T13 本地实现与模拟验证完成；实际宿主迁移、页面安装和发布未执行。

## 1. 用户能做什么

一个独立的“备份与迁移”工作台，将不同后果的操作分开：

1. 备份当前世界：完整世界、当前资料快照、模板、历史审计分别导出。
2. 迁移旧资料：早期 A0.0.5 实体 JSON，或 alpha.11 七张表的 JSON / 明确选择的只读旧库快照。
3. 恢复指定世界：来源聊天、世界、分支必须和目标一致，追加新检查点，不覆盖提交链。
4. 导入独立世界：目标须已经具有不同世界身份，不把外部聊天身份变成当前身份。
5. 导入模板：使用同一 T6 原子迁移规则，缺值、类型冲突或保护字段需先处理。
6. 检查历史审计：验证新版封存账本，不执行里面的 SQL、不保存资料、不继续模型请求。
7. 清空当前世界：单独的粉色确认入口，只追加当前分支的空资料版本。

流程是“选来源 → 只读预检 → 看映射/冲突/限制 → 导出当前完整备份并确认已另存 → 确认目标 → 保存 → 独立读回报告”。更换文件、改变替换/引用选项或切换向导会取消旧预览确认。关闭或刷新不自动迁移、续跑、补种或清空。

“备份生成”不等于文件已保存到外部。Vue 通过 `export`
事件交出 JSON 与文件名；下载宿主由 T15 接线，不为测试覆盖浏览器下载行为。只有当前版本完整备份、且用户确认已经另存，才满足保存/清空前置条件。快照/模板/历史文件不能冒充完整回退备份。

## 2. 新版文件协议与隐私

统一 JSON 包装：`world-evolution-transfer`、版本 1、独立
`kind`、载荷和 SHA-256 内容指纹。指纹用于检测损坏，不是原作者签名、身份授权或服务端 CAS。

| kind     | 内容                                          | 导入后果                                         |
| -------- | --------------------------------------------- | ------------------------------------------------ |
| world    | 已验证 T4 完整存档，含模板/资料/历史/来源材料 | 当前快照追加到目标世界；来源历史仍是独立审计材料 |
| data     | 来源范围、当前模板/资料与演变进度             | 同样检查来源范围，不携带外部活跃锚点或队列       |
| template | 当前模板及结构参数                            | 同一 T6 预检和事务，不装入示例行                 |
| history  | 完整封存 T4 存档                              | 只读审计，不重放 SQL 或模型                      |
| legacy   | 旧原始 JSON、原始摘要、凭据脱敏数量           | 可重新预检迁移，不直接恢复为活跃旧库             |

完整恢复文件可能含非公开历史；必须由本地可信权限回调允许，并由用户单独确认。不会以“隐藏了页面字段”为借口把完整私有历史自动下载、写日志或发送给主 AI。

不导出 API 配置或 Key。旧原件中的已知凭据字段和可信配置提供的密钥字符串会脱敏；非凭据的未知字段、空串、0、false、嵌套资料和旧账本保留。脱敏是幂等的，并说明不再是含凭据原件的字节级副本；原件仍在原来源。本实现不声称能自动识别所有自然语言中暗藏的未知凭据。已签封新版存档若被已知凭据污染，拒绝导出/保存，不重写内容破坏原历史指纹。缓存导出与页面反馈也重新检查当前保护字符串。

## 3. 旧版迁移：明确的基线，而不是假历史

读取真实旧源码确认形态：

- alpha.11：`meta + rows{npc,organization,location,society,environment,event,plan} + floorRuns/revisions/checkpoints/projections`。旧 JSON 导出没有统一新版文件包装；IDB 库名
  `acu-world-evolution-db`，数据库版本 4。
- A0.0.5：`chatKey + entities{…} + events[] + scheduledEvents[]`，及旧检查点/运行记录等。
- 未识别的任意对象不会被猜成一个 NPC；其他版本、坏行、重复来源身份、跨聊天行或未知可见性会停止，不静默过滤掉坏记录。

旧七张表重新划入宏观/微观组。新行 ID 由“旧聊天 + 旧表 + 旧 ID”的稳定摘要生成，与姓名、行序或版本无关；同名不同人、不同表同 ID 不合并。已确认的
`locationId / organizationIds / memberIds / actorIds / relationIds / relatedIds`
映射为验证后的引用；早期参与者姓名必须精确唯一。悬空/歧义关联默认停止；用户可明确选择只保留原文，但不建立假目标或假关联。

迁移采用保守的资料基线：名称、已验证关联、旧状态原文、只读“旧版完整资料”列。旧 JSON 字段语义、历法和自定义属性不能仅凭一个字段名无损猜成新版类型；因此不自动把任意 JSON 转成默认表的几十个业务列。事件、计划、旧状态、未知属性保留在原文和封存材料中。后续如需直接用于演变，应在 T6 明确拆列、映射和启用，不能误以为迁移已完成全部语义转换。

旧历史可能缺少原输入、类型、SQL、参数和提交证明。无论旧历史是否看似完整，都不制造空 SQL、“成功处理过本楼”或假可重放记录。只建立一次当前资料迁移基线，将原始历史/坏检查点/未知字段保留为审计材料，并明确限制；旧进度重置为空。旧世界同步状态、世界书 UID 和投影清单不作为新所有权；迁移表的演变和世界书导出默认关闭。

旧库不被修改、删除、升级或自动创建。只有明确调用只读适配器时才列出已有库，并以一个 `readonly`
事务按选中聊天索引读取；缺少列库能力、库消失、版本/表/index 不支持、读取失败或超限均停止。列库后出现新建/升级请求时中止事务，不初始化旧库。真实浏览器尚未调用此适配器。

## 4. 同一正式事务与恢复

所有保存调用同一 T4 服务；模板、schema、资料、进度和迁移证据一起成功或保持原世界。写入前还需当前权威 head、模板版本、真实助手锚点、允许的宿主能力、明确确认及当前备份。候选先在真正的临时 SQLite 中完整装入/导出验证，导入文件中的 SQL/HTML/JS/EJS 一律当数据，不执行。

提交可选 `transfer`
证据由严格协议和整条提交指纹覆盖：操作种类、来源摘要、原始/脱敏材料、材料摘要、稳定映射、限制及进度处置。映射须指向已保存行；材料损坏不能只重新签封外层提交来掩盖。旧 T0–T12 存档没有该可选字段，原行为保持兼容。

- 已有资料不静默覆盖。单独选“替换”仍受旧权限约束，不能通过导入的新模板解锁原来的锁定行/字段或用户不可见内容。
- 无助手锚点：保持草稿，不编造剧情楼层。
- 明确保存失败：旧世界不变；同一已准备载荷可重试，不重新规划另一笔迁移。
- 回执未知：查询确认，不重复 SQL/迁移/模型调用。
- 当前 head 改变：旧预览和旧备份失效，重新检查。
- 重复旧迁移/独立复制：检查已封存来源摘要，幂等跳过，不覆盖迁移后修改。
- 明确恢复同一备份：以后仍可再次选择恢复，不把用户的新恢复意图误判为重复迁移。
- 新版快照恢复：精确保留十进制、false、空值、自定义表和已验证进度；没有活跃外部请求队列，无自动续发。

T10 宿主路径只接受已验证的持久网关、当前恢复状态和可信写入许可；普通内存 getter 不替代这些能力。已有世界/分支的初始化、独立身份创建、实际下载和生产入口统一安装仍由 T15 接线。

## 5. 清空、投影与回退边界

清空只追加当前分支的空业务资料版本并重置演变进度，保留模板和历史。原剧情、其他变量/插件、旧库、其他聊天/世界/分支不动；刷新以正式空版本为准，不从旧缓存或旧库自动补种。允许删除的行可连同只读资料列一起删除，但锁定字段/行、非公开权限等保护仍不能绕过。

此向导不会写世界书。保存/恢复/清空后，T12 仍需以新 head 单独检查投影：新系统托管孤儿可在获准同步中清理；归属不明的旧
`WorldEvolution-*`
启用条目仍导致隔离阻断，不能仅凭导入材料中的 UID/名字接管或删除。旧条目的实际识别、人工选择/停用与已验证宿主驱动验收是生产接线关口，不在本阶段偷偷执行。

回退不等于直接重新打开旧写入器：先保留新世界完整备份与旧材料，停止两个写入器同时运行。新格式不能被旧插件直接读取；原件虽然保留，不自动成为新世界权威。旧原件在迁移后被旧插件继续写入，属于另一份发生分歧的存档，不静默合并或覆盖。

## 6. 限制与验证记录

文件/JSON 上限 4,000,000 字符，沿用 T2 深度 64、节点 100,000 的纯 JSON 校验；旧行/映射上限 5,000、单行旧资料文字上限 200,000、旧身份上限 512 字符。只读 IDB 取得的行及审计记录合计也限 5,000；请求超限停止而非截断。T4 仍至多 32 个完整提交检查点；不宣称无限历史，反复封存完整来源可能先达到总 JSON 上限。
