# T6：结构参数、DIY 与原子迁移（本地沙盒）

日期：2026-10-07。阶段范围仅 T6；保留 alpha.16 正式入口，不自动推进 T7，不提交或推送 Git。

## 1. 本阶段做到了什么

“世界资料”现在有同一个本地工作台的两个子页：数据填写、结构与参数。T5 负责记录，T6 负责表结构与表级配置，两者共用 T4 提交服务及同一模拟存档，没有另建一套可变数据库 schema。

可以新增业务表、加字段、改显示名、排序和分组；修改类型、必填、NULL、默认值、枚举、引用、只读和显示；填写五类表级规则，配置人工/AI 操作权限、运行频率、预算、上下文、API 继承和世界书导出选项。全局、阶段、表级参数都写入规范 T2 模板，不只存在于表单里。

本阶段尚未接入现有酒馆入口。用户当前已导入的控制台不会自动出现这些子页。API 仅保存预设 ID 引用；实际请求组装/冻结在 T7，世界书上传在 T12，真实宿主存档在 T10。这里的“保存”仍是模拟网关确认，不是实际聊天或角色卡世界书写入。

## 3. 普通用户的操作路径

1. 先保存或取消数据填写草稿，返回当前世界；历史快照保持只读。
2. 切到“结构与参数”，选“微观世界 → NPC”。
3. 新字段 ID 写 `age`，名称写“年龄”，点“添加字段”。ID 建立后固定。
4. 把类型选成整数，按需设置必填/允许空值、范围与新记录默认值。
5. 不需要给已有 NPC 补年龄时，保留可选，不设旧资料补充值。
6. 要改成必填时，明确选择“未提供值时补充”；新记录默认值不会自动补入旧记录。
7. 点“校验并预览迁移”，检查类型/引用/删除/前后资料报告。
8. 勾选“确认当前模拟世界范围与差异”，保存当前模拟世界，等写入及读回确认。
9. 返回数据填写，新增字段已可填写，之后仍经受限 SQL、校验与统一提交保存。

新增表在宏观/微观组选择后进入同一流程。新表为空，不补种示例资料。普通改名、排序、组别变化不会把 NPC 变成另一条记录，引用使用稳定
`tableId + rowId`。

字段“界面隐藏”仅控制数据页显示，结构页仍可配置它；不等同于禁止 AI 读取。表与字段的用户读取权限为 false 时，本阶段采取保守策略：整个结构工作台不展开其模板，也不提供绕过限制的编辑。非公开行仍参加内部完整性校验，但报告不泄露其值、记录 ID、数量或受影响详情。

## 4. 迁移契约

流程：旧完整状态 → 规范模板草稿 → 纯迁移预检 → 新临时 SQLite 完整载入/导出 → 私有 T4 迁移提交 → 同一模拟存档 CAS 写入 → 读回确认 → 更新两页正式视图。

- 模板身份、世界/分支身份、行 ID、来源、行锁、可见性和已有版本元数据由旧状态保留。
- 当前世界的任何结构或参数变化都递增模板版本；整个提交只推进一次资料 revision。
- 新可选字段在旧行中保持“未提供”；不把缺失变成 NULL，不套用新默认值。
- 新必填字段需显式补缺失；已有 NULL 原样保留，不被补充值替换。已有字段也不能用“无来源”伪装缺失来批量覆盖旧值。
- 映射限制在同一稳定表内；同一目标字段只允许一条方案。跨表合并、拆表和任意脚本转换不在首版范围。
- 转换白名单：原样保留、完整十进制文字转整数/数值、标量转文字。拒绝截断、空白、指数、溢出、负零、舍入或下溢。
- 普通数值保留 T2 的 IEEE-754 语义；15 位有效数字及 T3 字面量往返预检不意味着二进制浮点具备精确十进制算术。
- 枚举、类型、引用和范围不兼容时报告冲突，不自动删值。需要逐行不同的替换时，先在数据页明确修改并保存，再迁移。
- 删除表/字段需明确移除确认，报告公开移除数量，旧模板和资料留在原账本。
- 引用指向被删除表/记录时整批失败；没有隐式级联删除，也不把 `onDelete: clear` 当成迁移时的自动清空许可。
- 行/字段/表锁、只读和原人工权限阻断业务值修改。不能在本次模板里解锁/授予权限后绕过原基线。
- 已有时间值不可因更换历法纪元、历法 ID 或每日长度而被静默重新解释。历法显示改名可保留原时间。
- 保留至少一张有用户可显示字段的表；不建立让工作台完全不可访问的空结构。

临时 SQLite 校验使用可信编译的完整 schema 和全部候选数据，执行零行只读查询作为真实内核验证。结果必须保持候选快照完全一致，不能把注入执行器返回的任意改值当作迁移结果。表单仍可能有暂时无效的草稿；不会因未填完就改正式结构。默认/补充值输入未通过本地类型校验时，页面阻止预览/保存，而非悄悄采用旧输入值。

## 5. 保存范围与默认模板

“保存当前模拟世界”保存该世界的模板与数据；不会更新新世界默认模板。“仅保存新世界默认模板”保存独立的模板存档；不会更新当前或其他已有世界的资料、结构或版本。

两者使用不同的权威和确认。默认模板有自己的 revision、指纹和 CAS，保存失败不留下半份默认值。相同模板身份下，默认模板定义版本递增；模板不含业务行。仅显式创建新世界时复制默认模板并建立空表。默认模板不得携带旧世界记录的非空引用默认值，避免新世界继承悬空 ID。默认版本已被其他操作改变时拒绝覆盖；“读取默认版本（不套用）”只更新版本确认，不套用结构，不展示另一范围的非公开定义。

沙盒重开需调用方分别保留 `exportStorage()` 与 `defaults.exportStorage()`；分别传入
`storage`、`defaultStorage`。本阶段没有通过 localStorage、实际聊天或脚本变量冒充全局持久化。草稿仅在当前工作台实例内保留，切页不会丢弃；关闭或刷新不自动保存。

## 6. 高级 DDL 的两种支持范围

### 简单结构声明

```sql
CREATE TABLE we_market (f_name TEXT NOT NULL, f_stock INTEGER DEFAULT 0, f_note TEXT) STRICT;
ALTER TABLE we_npc ADD COLUMN f_age INTEGER;
ALTER TABLE we_npc DROP COLUMN f_identity;
DROP TABLE we_market;
```

只支持规范 `we_` 表名和 `f_` 业务列、TEXT/INTEGER/REAL、NULL/NOT
NULL、静态字面量 DEFAULT，要求分号。新表组别取界面的宏观/微观选择。新表/列初始显示名来自 ID，可随后在 GUI 改名。添加字段不会自动加入读取/导出字段集合；用户明确勾选。移除字段同步移除它自身的上下文/导出选项，外部引用或关联设置不静默删除，必须自行解决。

明确拒绝：系统列、物理身份 RENAME、触发器、索引、视图、BLOB、任意 CHECK/FOREIGN
KEY、函数、表达式默认值、ATTACH、PRAGMA 或普通 DML 混入 DDL。普通输入限 20000 字符/32 条/4000 token。

### 完整无损交换

导出内容第一行为 `-- WE-T6-TEMPLATE`
加规范 JSON，后面是从该模板可信编译的完整物理 DDL。这保留所有十种字段类型、精度、枚举、关系、权限、规则和继承参数，避免从 TEXT 猜测列表/时间/引用语义。导入时要求模板头的规范表示和派生 DDL 精确一致，限 100 万字符；重复/非规范头或追加 SQL 都被拒绝。

完整交换中的 CHECK 等仅是模板的固定派生产物，不意味着开放普通用户任意 CHECK 语法。两种入口均转成同一模板草稿，再走迁移预览和 T4 保存；从不直接执行输入的 DDL，也不维持第二份 schema。另外提供严格规范模板 JSON 高级编辑，仍走同样的版本/资料/权限/临时库校验，不接受业务快照替换。

## 7. 失败、并发与恢复

- 数据草稿/只读历史/其他未确认生成占用时，结构编辑阻断；结构草稿存在时，数据页不能填写、重载或接管核对。
- 干净结构页在下一次编辑前采用已确认的新资料基线；已有结构草稿绝不自动重基覆盖新版本。
- 预检、SQLite 或迁移保存失败时不推进正式状态，保留草稿和错误。
- 保存确认丢失时旧正式视图保留，编辑/重复保存被阻止；核对确切提交身份后再切换，不重复执行迁移。
- CAS 冲突不覆盖其他提交；取消草稿后载入最新确认状态。
- 保存后采用新列/新表；T5 当前选中表被删除时自动退回可查看表。新列加入显示，已主动隐藏的旧列不被强行重开。
- 旧检查点同时带旧模板和旧资料。T4 显式恢复能找回删除字段的值与旧类型，迁移历史重放使用已验证快照，不重跑 AI 或 DDL。
- 旧存档、新默认模板和迁移结果均为有限 plain JSON；getter/toJSON、恶意对象、超限和非法结构不执行代码。

旧状态恢复已通过服务级测试，T6 不新增一个绕过“楼层记录”确认的恢复按钮。真实宿主的删楼/刷新/多写入器等生命周期仍属于 T10，不把沙盒恢复称为真机验收。
