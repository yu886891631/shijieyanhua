  openT10CompatibilitySession 复用既有整轮校验、预算登记与查询恢复，不能用导入 JSON 标志跳过模式边界。

API 配置的读取方式仍由 runtime.readApi 提供；既有 API 配置页及其持久化模块保留。新真实共享会话已有配置端口和显式挂载函数，但尚未挂入现有脚本。当前 T15 隔离包的 API 编辑仍是独立内存配置，不会自动启用真实路由。

sent 是保守占用的发送次数，不是已收费证明；登记后若发送边界拒绝，预算也不退回。预设 maxRetries 可进行受预算约束的重试；这与“自动重新生成整轮”不同。超时或取消不能证明服务商未计费。

## 7. 2026-10-10 兼容保存、读回与恢复实现

### 7.1 支持契约

- 只支持已保存、当前已加载的单角色卡聊天；不支持群聊、临时聊天或缺失聊天文件。
- 同一聊天只用一个活动页面；不要同时启用旧世界演变写入脚本与新接线实例。
- 父窗口共享所有权可拒绝同一页多个新脚本实例；它不是跨标签页、跨设备或所有插件的锁。其他标签页/插件若在检查后以旧整份聊天覆盖，本方案不能保证阻止它。
- 运行顺序必须串行：剧情及前置插件完成持久保存，再开始世界演变。前置完成证据的真实适配仍待下一段接线，不能把普通生成结束或固定延迟当作证据。
- 保存只修改 chat_metadata.variables.world_evolution_sql_t10 和消息各 swipe 的同名命名空间。正文、swipes、原始头部、integrity、其他元数据、MVU/TavernDB/用户字段不由本驱动修改。
- 兼容驱动标记 compatibility-host / optimistic-single-page /
  atomicDocumentCas=false；严格网关继续拒绝它，避免界面/JSON 配置误把兼容写入称为原子保存。

### 7.2 保存边界

1. 读取服务端实际 JSONL，同时保留原始整文档指纹与规范化 T10 视图；不拿内存 getter 当保存证明。
2. 写前再次独立读取并比较整文档指纹；比对当前酒馆内存的全部消息和 chat_metadata。未保存的其他插件变化不被覆盖，直接停止。
3. 验证 T10 存档、稳定 ID、预算记录和提案；提案若改动非自有字段，拒绝写入。
4. 先验证内存目标可写，再同步自有数据到原有消息/元数据对象，保留其他字段。随后正常酒馆保存不会仅因本插件仍留旧内存而把刚存的数据恢复成旧版。
5. 同步授权复核后 POST
   /api/chats/save，携带宿主 CSRF、force=false；没有强制覆盖、宿主弹窗自动确认或保存自动重试。端点/函数在构造时固定，不能在运行中改成外站。
6. 保存返回后独立读取整份 JSONL，确认内容与拟保存原始文档一致，并复核目标、事件版本和当前内存。T4 服务仍再查正式提交，确认前不推进页面中的正式表格。

每次兼容写入有 15 秒截止信号，贯穿前置读取、保存和读回；超时不是“肯定没有写入”。这依赖 fetch 遵守取消信号，不承诺撤回服务端已经执行的保存。

### 7.3 冲突与不确定结果

- 写前冲突、身份变化、撤销或不能确认原档：停止本实例的后续写入，不盲目重试或自动再生成。
- 已进入保存发送边界后的网络失败、非成功回执、取消、超时、事件变化、读回失败或内容不符：统一按保存结果不明处理，仅允许查询恢复，不回滚酒馆内存，也不伪称服务器撤销成功。
- T4 查询确认可找回实际已保存提交并更新正式视图；这不会自动重新授权当前实例写入。
- 每次真实模型发送前先保存并读回预算登记；预算保存不明时连第一条模型请求也不发送。登记计数是保守占用，不是供应商收费证明。
- 刷新后有未完成运行记录时，只读显示 interrupted/stale，不自动续发 API。重新运行必须明确处理上一轮状态，不能重置计数偷偷再发。
- close/pagehide 撤销并清理事件监听；在尚有保存结果待处理时保留同页所有权到请求结束，避免立即启动第二个写入者。

- 完成候选仍不等于保存成功。刷新通过兼容宿主独立读取服务端 JSONL，核对当前剧情、稳定身份、事件 epoch、所选来源字段与候选结果，再生成持久证明。
- 首次查询、再次查询或来源通知撤销后，不能沿用旧的 ready 状态。前置在模型请求期间变化，会取消所属整轮；迟到模型返回不提交、不进入微观、不写世界书。
- MVU 来源选择从当前 active
  swipe 的变量读取；数据库选择从当前消息的实际保存字段读取。来源映射由接线方显式提供，不能用任意缓存或样例字段冒充用户实际表格。

MVU 原生观察器在 `await waitGlobalInitialized('Mvu')` 后才访问对象。先观察 `COMMAND_PARSED`
的变量对象、当前原文和唯一目标消息，再观察同一对象的
`VARIABLE_UPDATE_ENDED_for_zod`。它只是一份完成候选，因为 MVU 在该事件之后仍会移除内部字段、写变量和更新消息。适配允许源码明确的占位状态栏/状态标签后处理，之后仍必须独立核对保存结果。旧版本没有对应事件或目标不唯一时不放行；也不据此宣称每条自然语言要求或变量命令的语义都正确。

也没有提供本轮全部批次终态、当前 swipe 和完整成功结果。`triggerUpdate`
的返回只覆盖显式 API 调用，不能冒充数据库自身所有自动/页面流程的终态。

因此当前原生数据库观察器明确保持“无法验证整轮完成”。必要数据库来源启用时，真实演变仍被阻断，不用生成结束、固定延迟、表格变化或某一个批次完成来解除。测试里的受控完整数据库回执是注入的假源，不能拿它声称原生自动链已经打通。

剩余实质工作是提供可核对的数据库整轮终态适配：来源开始/目标、明确计划或运行身份、全部批次成功/失败/跳过、最终保存结果。需要从真正的流程收口处取得，不能只给旧更新通知换名称。本段没有擅自修改第三方数据库插件。
