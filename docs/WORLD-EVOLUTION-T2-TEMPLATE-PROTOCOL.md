# 世界演变重构 T2：模板协议与默认表组

日期：2026-10-05。依据：总实施计划 T2、第 15.2–15.6 节，以及 T1 页面交互契约。

本阶段把“每张表是什么、能填什么、谁能读取/修改、如何继承配置”做成同一份可校验模板。不是 SQL 执行器、真实填表工作台或酒馆存档服务。

## 1. 交付和隔离范围

- 规范模板、字段、关系、配置和数据载荷类型；严格验证，不静默纠错或吞掉不支持的结构。
- 七张默认表、环境＋NPC 最小模板、自定义业务表以及独立的固定虚构资料。
- 字段值、空值、精度和 SQLite 单元格物理编码规则；这里只做纯转换，不执行 SQL。
- 字段输入控件和权限描述、只读模板预览；不接旧控制台或创建第二个生产入口。
- 模板变更识别与迁移需求报告，不在本阶段执行结构迁移。
- 测试均使用本地数据，旧聊天、API 配置、数据库、世界书、导入包和发布地址不变。

模板工厂不携带示例业务行。采用模板不等于加入演示 NPC；恢复资料不调用初始化默认值，也不补种示例。

## 2. 默认两组表

| 表组     | 表   | 职责及主要资料                                 |
| -------- | ---- | ---------------------------------------------- |
| 宏观世界 | 社会 | 区域制度、秩序、经济、舆情、冲突与持续影响     |
| 宏观世界 | 环境 | 天气、资源、灾害、风险、适用时间及影响区域     |
| 宏观世界 | 地点 | 地理层级、通行、设施、控制关系与现场条件       |
| 微观世界 | NPC  | 身份、位置、状态、认知、目标、关系、行动与限制 |
| 微观世界 | 组织 | 成员、资源、目标、立场、关系与行动安排         |
| 微观世界 | 计划 | 执行者、触发条件、期限、阶段、阻碍与完成状态   |
| 微观世界 | 事件 | 已发生事实、时间、地点、参与者、结果与关联资料 |

默认字段数依次为 15、16、15、16、13、15、13。字段有各自的类型、说明、约束、默认值及读取/写入权限，不只是表头名称。

宏观是微观行动的先决条件，不代表宏观每轮必须更新、必须使用更多 token，或宏观资料天然公开。组织、事件的反向影响默认供下一轮宏观参考，首版不做同轮无限反馈。

表用途不由中文显示名决定。允许新增业务表，稳定身份和用途保持可识别；自定义表同样有字段、权限、预算、上下文和导出规则。

完整与最小模板都含初始化、新增、更新、归档、删除的明确说明。已完成计划、死亡 NPC、已发生事件不自动消失或复活；默认优先保留记录，删除另受权限、关系影响与提交校验约束。

## 3. 身份、结构与版本

- 表 ID、字段 ID、SQL 表/列映射与显示名分开；显示改名不改变已有行身份和引用。
- 行以 `tableId + rowId` 标识。姓名只是显示值，同名 NPC、组织和其他表不会据此合并。
- 行系统元信息与业务字段值分开；业务字段不能伪装成行 ID、可见性、锁、来源或提交系统字段。
- 规范化 JSON 模板是结构唯一来源。T3 由它生成并核对 SQLite schema；不维护另一份能独立修改的 DDL。
- 模板协议版本、业务模板版本、数据载荷版本分别记录。完整提交链、锚点、幂等及聊天存档协议由 T4/T10 定义，不能把 T2 数据载荷当成已保存的正式世界。
- 未知协议、不支持的类型/配置、重复身份/SQL 映射、悬空字段/表关系在校验时拒绝，并定位到具体范围。

T2 只识别变化；类型、引用、必填、删除字段、表组、SQL 映射等可能影响旧资料的变更要进入 T6 迁移预览。即使只改规则或参数，也必须有可核对的启用版本；不能绕过运行时冻结检查。

首版格式固定为 `world-evolution-template` / `world-evolution-data`，两者的 `schemaVersion`、`dataVersion`
都为 1；默认业务 `templateVersion` 为 1。它们是重构的新协议，不是把 alpha.11 旧数据版本改为 1，也不会自动接管旧库。

稳定 ID 采用最多 64 字符的小写字母、数字、连字符和下划线，必须以字母开头；拒绝 `constructor`、`prototype`
等危险身份。SQL 表名以 `we_` 开头，业务列名以 `f_`
开头，不通过中文显示名拼接 SQL。字段 ID 在表内唯一，行 ID 在表内唯一；不同表可以有相同的字段/行 ID。

系统列固定为
`__we_row_id`、`__we_locked`、`__we_locked_fields`、`__we_archived`、`__we_visibility`、`__we_source`、`__we_created_revision`、`__we_updated_revision`、`__we_presence`。它们不能作为普通业务列映射，也不能借普通业务写入解锁、改身份或伪造来源。

## 4. 字段值与物理编码原则

| 类型       | JSON 值与输入                                    | SQLite 物理原则          | 硬性边界                               |
| ---------- | ------------------------------------------------ | ------------------------ | -------------------------------------- |
| 文本       | 字符串；单行/多行输入                            | TEXT                     | 长度；空串不是缺失或 NULL              |
| 整数       | 安全整数；整数输入                               | INTEGER                  | 超过可无损范围拒绝，不截断             |
| 普通数值   | 有限数；数值输入                                 | REAL                     | 不支持 NaN/Infinity 或任意精度财务数   |
| 精确小数   | 固定精度规范字符串；十进制输入                   | 按精度缩放的安全 INTEGER | 不先转浮点再四舍五入；精度不符拒绝     |
| 布尔       | true/false；开关                                 | INTEGER 1/0              | false 不当作缺省；不接受字符串冒充布尔 |
| 枚举       | 已声明的字符串选项；选择器                       | TEXT                     | 未定义选项拒绝                         |
| 字符串列表 | 字符串数组；列表输入                             | 规范 JSON TEXT           | 元素类型、长度、重复规则检查           |
| 单引用     | 稳定目标表/行身份；引用选择                      | 按规范编码为 TEXT        | 目标表/行与删除影响由应用校验          |
| 多引用     | 稳定引用数组；多选引用                           | 规范 JSON TEXT           | 成员重复、目标与删除影响逐项检查       |
| 世界时间   | calendarId、ordinalMinute、display；世界时间输入 | 规范 JSON TEXT           | 同纪元逻辑分钟比较；不强转现实 Date    |

单元格转换必须保留“未提供”的标记；未提供值、NULL、空串、false、0、空列表互不替代。恢复和整库验证不填默认值；只有明确新增行时才按静态默认值准备草稿，已有值绝不因 falsy 判断被覆盖。

首版精确小数声明 `precision` 1–15、`scale` 0–precision，JSON 必须为对应固定小数位的字符串。例如 `precision=10, scale=2`
时，`"12.30"`
对应物理整数 1230；`12.3`、`"12.3"`、指数写法、负零和多余小数位都拒绝，不自动舍入。这个边界不是任意精度数据库；后续精度扩大要显式修改协议和迁移，不可偷偷改存为 TEXT。

`required` 表示必须存在此键，`nullable`
单独决定能否为 NULL，二者不代表自动证明任意字符串内容真实、完整。单引用默认只允许 NULL，多引用默认只允许空数组，不能在结构模板中凭空引用一个不存在的业务行。新行准备后仍须整批检查目标存在性和提交权限，不等于已经保存。

首版时间仅支持模板声明日历内的逻辑分钟比较和持续时间。不同日历不能直接比较；display 是显示说明，不用自由文字反推日期。未支持的纪元换算、真实日期解析或超精度计算明确拒绝，后续不能悄悄换算。

列表和复杂引用的 TEXT 编码不等于 SQLite 已对每个成员自动建立外键。T3 执行后的整批验证仍要复用同一套应用约束。

资源保护是拒绝条件，不是承诺容量：纯 JSON 最多 100000 节点、64 层、累计约 4000000
UTF-16 字符；单字符串最多 1000000 字符，复杂单元格编码最多 256000 字符。未声明上限的文本/列表分别默认最多 20000 字符/1000 项，世界时间 display 最多 160 字符。数据载荷每表至多 5000 行、总计至多 10000 行，同时仍须满足上述 JSON 限制；尚未做大规模宿主性能验收。

## 5. 权限、可见性和生命周期

| 规则                      | 控制什么                       | 不会隐含做什么                       |
| ------------------------- | ------------------------------ | ------------------------------------ |
| 用户/演变 AI/主 AI 可见性 | 分别控制读取和投影             | 宏观/微观组不自动决定可见性          |
| 人工/AI 操作权限          | 分别控制新增、更新、归档、删除 | 人工入口不能绕过类型、引用或提交校验 |
| 关闭自动更新              | 禁止本轮 AI 修改               | 可读道路等仍可作为 NPC 行动条件      |
| 表/行/字段锁              | 阻止对应修改，解锁要明确操作   | 不抹掉允许读取的事实和关系           |
| 隐藏列                    | 纯 UI 显示选择                 | 不自动保密、不改变演变或投影权限     |
| 归档/死亡/完成            | 业务生命周期                   | 不自动删除、排除全部历史或复活       |

读取结果必须同时满足表、字段、行的权限；运行候选可读集与可写集分开。秘密值不能借标题、关键词、索引或可读字段间接投影出去。T2 定义矩阵和纯判断，完整 SQL 读集合授权、上下文及投影过滤分别在 T3/T7/T12 实施。

业务说明是提供给 AI 和用户的规则，不是执行网页代码。类型、权限、数量和稳定引用能硬校验；不能宣称校验器证明了任意剧情文本的全部语义正确性。

## 6. 配置继承、频率与预算

配置采用全局→阶段→表的单一继承链；表级界面和 API/投影总页面读同一份模板配置。

- “继承”采用上级有效值；“关闭”显式停用对应能力；“具体值”使用经过校验的数值或设置。不用负数或零暗指不同含义。
- 频率按合格剧情轮次计数，不按消息数组索引、请求次数或失败重试计数。起点、周期、上次成功处理标记要可核对。
- 成功但无业务变化仍可记录处理进度；此标记随有效提交更新。失败、重试及恢复不自行推进计数，实际账本更新由 T4/T8/T9 实现。
- 未到频率的宏观表仍提供最新已提交条件，不为了显示两段进度强行请求 AI。
- 行修改、新增、上下文、批次与发送预算分别配置。表级/阶段配置不能扩大整轮硬上限；所有真实发送、重试和备用路由共用总额度。
- API 配置只保存预设引用与继承关系，不复制 API Key、端点凭据或现有配置。实际预设是否存在和能连接由 T7 检查。
- 上下文和导出仅使用已验证的字段身份/关系与受限制表达；不接受任意 SQL、JavaScript、EJS 或未验证的网页模板执行。

本阶段可解析设置、解释继承、判断频率条件；不执行候选调度或发送请求。整轮先冻结来源、模板和总预算；微观候选在宏观完成后确定并冻结，仍受同一剩余额度限制。

频率具体语义：达到 offset 后的首次合格轮可以处理；成功后再间隔 every 个合格剧情轮。首次因前置等待而延后，不以模运算错过初始化；同轮失败可重试，成功后同轮不得再处理。成功标记属于 T4/T8/T9 的有效提交记录，T2 函数不保存标记。

表级具体设置可以覆盖阶段某个单项的“关闭”，但不能重新启用 `phase.enabled=false`
的整个阶段。数值 0 表示对应额度确实为零，不代表“无限”或“继承”。解析时新增行预算不能超过总修改行数，上下文字数同时受本表有效预算和整轮硬上限约束。整轮剩余总额度的分配/扣减仍由后续调度器实现，不能把逐表解析当成已完成全链预算执法。

## 7. 只读模板预览与输入控件

预览按宏观、微观展示表格，选择表后显示：用途说明→字段及控件→必填/可空/默认→读取和修改权限→生命周期说明→继承后的频率/预算/API/上下文→世界书导出设置。

输入映射由字段类型统一提供：文本、整数/普通数值、精确小数、布尔、枚举、列表、稳定引用、世界时间各用对应控件描述。模板不允许字段修改时显示只读原因；缺值、NULL 与用户清空操作在 T5 的真实编辑控件中分别表达。

T2 样例没有新增行或保存按钮，不把模板预览冒充已完成填表。正文、说明、默认值和错误均按文本渲染，恶意 HTML 不执行。新样例不挂载当前酒馆；真实页面、焦点和缩放待后续指定验收。
