# T9：微观阶段与整轮统一保存

日期：2026-10-08。范围：本地隔离雏形；不是酒馆真机验收或发布。

## 1. 本阶段交付

宏观阶段仍使用 T8 的冻结输入、前置证明和有序私有 SQL。T9 在同一个触发队列和同一个 T7 运行对象里接续：

1. 等待所有必要前置，完成宏观暂存。
2. 用本轮宏观暂存、上一份微观资料及冻结剧情，确定微观候选和读写范围。
3. NPC、组织、计划等微观表按模板顺序处理；后表读取前表已经通过校验的私有结果。
4. 整轮复核，再用 T4 重放已确定 SQL 形成一个提交；不重新询问模型。
5. 模拟 JSON 存档在唯一原子写入点确认宏观、微观、时间与进度一起保存。
6. 从序列化模拟存档重建同一个世界和进度；不调用模型，不自动重做本轮。

核心文件：

- `src/世界演变/rebuild/t9-round.ts`：整轮协调、微观演算、统一提交、取消/冲突、续跑与回执确认。
- `t9-ledger.ts`：保存于同一 T4 提交内的时间、成功轮次、轮转、请求计数和冻结输入指纹。
- `t9-sandbox.ts`：显式模拟工厂；共用 T5/T6/T7 服务，注册真正匹配模拟输入的消息锚点。
- `T9RoundWorkbench.vue`、`T9WorldWorkbench.vue`：整轮工作台和资料/演变导航。

没有 `index.ts` 或 live
entry；不注册酒馆监听器，不使用默认 fetch，不读写旧 alpha.11 数据库，不生成共享 bundle 或导入包。

## 2. 微观行为与用户 DIY

### 2.1 候选、关联与有序批次

- 始终用 `tableId + rowId` 区分对象。同名 NPC、同名组织不是同一个对象。
- 宏观影响沿用户可读、演变可读的稳定引用图扩展，包含删除宏观对象的旧边；可影响没有被剧情点名的驻地 NPC、组织和计划。
- 按用户指定、剧情、关联、宏观影响、到期及后台轮转筛选，受整轮剩余对象/新增额度限制。
- 微观候选在宏观完成后冻结；有序刷新只更新后批上下文，不重选前批对象，也不让刚新增对象再得到一次独立行动批次。
- 首版每表一个有序请求；同路由合批优化未实现，也不把自定义表自动分配到另一个接口。
- 不到频率的宏观表继承正式状态；没有宏观请求也可继续处理到期微观表。
- 读写集分开。归档、锁定、只读、不可见或终态对象不会获得行动写入权限；合法的可读历史仍能成为条件。

### 2.2 不依赖固定字段显示名

- 剧情名称匹配使用模板 `export.titleFieldId`；没有配置时兼容旧 `name` 字段。标题用途不代表允许导出或写世界书。
- 新增可选字段用途
  `semantic: none | deadline | fact-time`。期限字段用于到期候选；事实时刻不能晚于冻结的本轮时间，也不能在本轮时间未知时凭空填写。
- 旧模板可省略用途；旧 `deadline` 保留兼容匹配。新增字段可通过结构页选择用途，不按中文显示名称猜测。
- 新增可选枚举约束
  `terminalValues`，须为枚举候选子集。AI 不能自动离开终态，也不会被分配终态对象的主动行动写入；人工更正仍可通过原有人工提交完成。
- 新默认 NPC 的死亡、计划的完成/失败/取消被标为终态。计划不会因完成自动删行，原有历史与归档仍保留。
- 默认 NPC 上下文字符预算由 16000 调整为 20000，相关 SQL
  schema 使用明确的紧凑字段别名。只影响本次新建默认模板；既有用户模板的显式额度不被扩大，超限仍阻断。
- 高级 JSON 与规范附注 DDL 同样保留这些属性；用途不改变 SQLite 物理类型，终态约束仍被模板指纹覆盖。

能机械证明的是类型、引用、权限、锁定、候选范围、预算、终态和明确的时间约束。不能用 SQL 证明所有自然语言剧情事实、资源守恒或认知合理性；提示词规则不等于额外授权。

## 3. 一次保存包含什么

T4 提交增加可选 `evolution` 账本，旧 T4–T8 存档仍可不含它：

- 协议版本、冻结输入指纹（包含本轮来源与基准状态）。
- 合格剧情轮次和本轮世界时间；本轮未知时不自行推进已知时间。
- 各表上次成功轮次与后台轮转位置。
- 本轮真正完成的表和两阶段累计发送次数/硬上限。

T4 同一个提交内保存固定宏观/微观 SQL、授权、参数、完整模板/数据快照、上述账本及指纹。宏观日志必须在微观之前；完成表必须对应阶段日志。所有表没有请求时允许严格的无业务变化提交，不制造假请求或伪造 SQL 变化。

成功处理但没有变化仍只推进一次 revision，并保存成功标记，避免同一剧情重复处理。频率、轮转和时间不会在预览、失败、取消或仅查看历史时提前推进。T9 从已保存账本取进度，不相信调用方随意给出的成功计数；同历法时间倒退须先有明确的历史恢复，不能在普通生成中悄悄倒退。

统一保存前会检查准备结果与整轮私有结果完全一致。最后的模拟 CAS 内还执行同步授权检查：基准提交、完整冻结剧情/前置、分支、触发所有权、权限、取消与有效期必须仍有效。检查和模拟赋值之间不跨异步边界。此保证只覆盖本地模拟网关；T10 必须验证真实宿主的等价边界。

## 4. 失败、续跑与结果未知

| 情况                                      | 正式模拟世界     | 后续行为                                |
| ----------------------------------------- | ---------------- | --------------------------------------- |
| 微观网络假响应失败                        | 不保存宏观或微观 | 用户可用剩余额度显式续跑同一运行        |
| SQL/JSON/类型/引用/锁定/时间/生命周期失败 | 不保存           | 不盲目重试模型                          |
| 剧情、前置、模板、基准、分支或权限变化    | 不保存           | 暂存失效，不拼接新旧轮次                |
| 取消或有效期届满、迟到结果                | 未过写入点不保存 | 不继续下一批，不能续跑失效暂存          |
| 明确保存失败                              | 保留原正式世界   | 仅重试同一准备提交，不重新生成/执行 SQL |
| ACK 丢失或写后无法读回                    | 回执待确认       | 仅查询存档；不盲目生成、覆盖或重复保存  |
| 取消发生在实际写入之后                    | 以已确认回执为准 | 不宣称已经回滚或免除服务商费用          |
| 刷新模拟运行时                            | 从权威 JSON 恢复 | 零模型调用，未保存暂存不自动恢复/续发   |

续跑仅在同实例、同轮、同基准/模板/分支/冻结来源且未过期时可用。复用已经校验的宏观和已完成微观批次，沿用原 API/提示词配置及发送计数；客户端重试、跨阶段和显式续跑共用一个硬额度。普通 API/提示词修改只影响下一轮，不切换本轮模型或拒绝本轮旧配置结果。

已保存消息锚点记录会随模拟 JSON 重开保留。同剧情重新点击开始可识别为历史重复，不调用模型，不再推进 revision。历史恢复同步恢复该检查点进度，而不是保留未来轮转。未知回执即使其后出现人工提交，也能识别原整轮已保存，不覆盖后续编辑。

真实接入后已发出的超时/取消请求可能收费；本阶段均为假传输、零联网/费用，“结果未知”用于验证这类状态，不能理解为已撤销服务商调用。

## 5. 页面与资料一致性

- 显示前置/宏观进度、微观顺序、受影响对象、入选原因与跳过理由。
- 显示实际安全输入、请求指纹、API 路由、两阶段累计发送额度。
- 显示宏微观原值/暂存值/保存结果、单次回执和无变化状态。
- 四类动作：开始模拟整轮并自动保存、取消、显式续跑/重试保存、仅查询未知回执。
- 普通区域淡绿、危险/失败区域淡粉；作用域 CSS、窄屏换行/横向表格滚动及键盘焦点。
- 确认保存后资料工作台采纳同一正式结果，不必刷新整页；不会清掉用户后来开始的草稿或把历史查看切回当前页。
- 页面切换保留子组件内存；未保存暂存跨刷新不保留，说明不承诺已落档。
- Vue 安全文本插值，恶意 HTML/SQL/模型数据不会变成网页脚本；Key 不进入预览、SQL 日志、存档或恢复资料。
