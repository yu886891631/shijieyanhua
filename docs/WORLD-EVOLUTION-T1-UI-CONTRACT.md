# 世界演变重构 T1：页面结构与交互契约

日期：2026-10-05。依据：SQL/UI 总实施计划 T1、T0 基线与宿主能力报告。

范围：固定页面、作用域、服务分工和状态语义；新增未接入旧入口的沙盒导航/组件样例。不是表格编辑器、SQLite、正式存档或真实生成交付。

## 1. 本阶段交付和隔离约束

- 本文给出全部九页面、表级子页、首次使用流程、动作范围和状态表。
- `src/世界演变/rebuild/t1-ui-contract.ts`：纯页面/动作契约与沙盒导航模型。
- `src/世界演变/rebuild/T1SandboxWorkbench.vue`：最小 Vue 样例，展示导航、页头、范围、状态、空态、阻断和草稿离开确认。
- 对应 `.test.ts` 验证模型行为及组件编译/渲染结构；验证结果在第 12 节收口记录。
- 没有新增自动加载的 `index.ts`，没有改旧控制台、API 页面、数据库入口或 dist；不生成酒馆导入包、不提交/推送 Git。
- 不读取旧设置/凭据/IndexedDB，不把当前聊天作为样例来源，不导入旧 engine/store/默认世界书网关。
- 样例写明“仅内存沙盒；未写当前聊天；不调用 API 或世界书”。制造/清除示例草稿仅改变导航模型，不假称写了世界资料。
- T1 的生产状态策略用于说明禁用原因和确认后果，不是生产授权或执行器。所有生产服务以后仍须独立复查身份、基准、权限和能力，不能信任前端传来一个 `allowed: true`。

## 2. 页面路由和层级

采用内存路由，不修改宿主 URL、浏览器历史或当前聊天绑定。路由校验不接受未知页面/子区，也不以表显示名代替稳定身份。

| 页面 ID | 中文名称 | 导航组 | 上下文 |
| --- | --- | --- | --- |
| overview | 总览 | 工作台 | 当前世界/分支的有效头与运行摘要 |
| data | 世界资料 | 工作台 | 当前表与数据/结构参数子页 |
| history | 楼层记录 | 工作台 | 运行记录或选中的只读历史版本 |
| worldbook | 世界书投影 | 工作台 | 当前有效提交的投影预览/账本 |
| api | API 配置 | 演变配置 | 全局→阶段→表的路由与下一轮配置 |
| evolution | 自动演变 | 演变配置 | 统一运行状态、触发条件和预算 |
| prompts | 填表提示词 | 演变配置 | 草稿、启用版本和实际发送版本 |
| backup | 备份与迁移 | 演变配置 | 选定来源和目标的预览/恢复向导 |
| appearance | 外观与显示 | 设置 | 仅显示设置，不改变世界状态 |

世界资料内部层级：

```text
世界资料
├─ 宏观世界 / 微观世界
│  └─ 选择一张表（tableId；显示名可以改）
│     ├─ 数据 records
│     └─ 结构与参数 parameters
│        ├─ 字段与关系 schema
│        ├─ 填表规则 lifecycle
│        ├─ 演算参数 runtime
│        ├─ 上下文 context
│        ├─ API 继承 api
│        ├─ 世界书导出 export
│        └─ 高级查询/结构 advanced
└─ 未选表 / 空表 / 历史只读状态
```

用途、排序、表组等基本信息放结构与参数页首；不再开第三份模板编辑器。表级上下文/API/导出配置在顶层相关页面只是同一份配置的汇总入口。

路由的 tableId 是不透明的 UI 关联值；正式表/字段/世界身份在 T2/T4 固定。T1 样例不把七个默认类型硬编码成自定义表的唯一范围。

## 3. 共用外壳和布局顺序

统一居中外壳延续既有私有样式和语义 token；不回退已修复的宿主定位行为。

各页区域顺序固定为：

1. 常驻模式和范围：沙盒/真实、当前世界/分支、当前或历史版本、保存状态。
2. 页头：标题、简短用途、关闭入口和页面主操作。
3. 必要状态/阻断说明：缺什么、在哪修复，不只显示“未就绪”。
4. 主要内容：列表/表格/表单/运行记录，始终标记读取来源。
5. 辅助预览与详情：变化、来源、SQL/内部 ID 等可折叠信息。
6. 明确目标的操作区：保存数据、保存模板等分别命名，未实现/无权限时给出原因。

侧栏和内容滚动分别可达，页头与关闭按钮不被长表挤掉；100/110/125% 和窄区约束继续保留。T1 样例只有基础布局，不声称已重验宿主缩放、真实聚焦或所有主题。

配色延续奶油/淡绿普通区域、淡粉危险区域和琥珀警告；状态必须同时有文字，不能仅靠颜色。正文和导入内容按文本展示，不能渲染成可执行 HTML。

## 4. 各页内容与动作蓝图

| 页面 | 主要内容顺序 | 主动作及后果 | 空态/阻断重点 | 实际接入阶段 |
| --- | --- | --- | --- | --- |

| 世界资料·数据 | 两组表导航→表说明→搜索/列/分页→类型化行编辑→差异→保存区 | 保存当前世界资料；新增/归档/删除均先草稿与校验 | 未选表、空表、锁定、无权、历史只读、保存失败 | T5，人工初始化同阶段 |
| 世界资料·参数 | 表基本信息→子区→草稿/启用版本→迁移预览→保存范围 | 保存当前聊天模板，或另存全局默认；不运行 AI | 类型/引用错误、不兼容变更、旧数据冲突、无锚点 | T2 定协议，T6 实现 |

| API 配置 | 路由列表→全局/阶段/表来源→预设→模拟/真实测试分开 | 保存配置只影响下一轮；真实测试会联网 | 缺模型/端点/凭据；模拟成功不证明 Key 有效 | 保留既有界面思路，T7 接新服务 |
| 自动演变 | 触发与前置→频率/预算→运行前检查→进度→结果/故障 | 启用/手动运行/取消/重试/恢复分别说明 | 前置失败/未知、请求额度不足、费用未知、过期运行 | T8/T9 基础，T11 收口 |
| 填表提示词 | 层级规则→草稿→启用版本→最终上下文→差异 | 保存草稿不启用；启用新版本单独操作 | 微观未确定标预估；保密/授权规则不可关闭 | T7 |
| 备份与迁移 | 来源/目标→只读预览→冲突→备份/确认→报告 | 导出、导入、旧版迁移、恢复、清空各有独立范围 | 未知版本、损坏引用、旧历史不等价、目标已有数据 | T13 |
| 外观与显示 | 主题→字号/密度/缩放→预览→说明 | 仅改显示，不保存世界、不使运行过期 | 长文本、键盘焦点、错误对比度、窄区可达 | 基础组件持续处理，T14 收口 |

打开备份/迁移或历史页面不自动执行导入、清空、旧库读取或世界重建。服务使用用户选定的来源和范围，不在导航 mounted 钩子里串起写入链。

历史材料始终只读。“恢复”先预览过去版本和目标，回到明确的当前世界提交上下文后才申请写回；不能在历史查看实例上直接保存。独立的 API、全局默认和显示配置不属于历史材料，仍可进入各自的配置上下文，不因此将整个应用一并冻结。

## 5. 作用域与服务职责

### 5.1 每一个“保存”都说明目标

| 作用域 | 归属/生效范围 | 不允许的隐含行为 |
| --- | --- | --- |
| 当前世界数据 | 当前世界/分支，绑定有效基准与助手锚点 | 不改其他聊天、全局模板或凭据；不因导航自动提交 |
| 当前模板 | 当前世界使用的启用模板及版本 | 不只换指针而跳过数据迁移；不默认覆盖其他世界 |
| 全局默认模板 | 未来明确采用它的新世界 | 不覆盖正在游玩的世界；应用到已有世界另走迁移 |
| 运行配置 | 未来运行的路由、普通参数、触发/预算等 | 不改本轮冻结 API 配置；不把配置保存当模型调用 |
| 历史材料 | 指定分支/提交的不可变查看实例 | 不把“查看”变“恢复写回”；不套当前 schema 改旧资料 |
| 世界书投影 | 当前有效提交→经确认的角色卡 primary | 不反推权威世界，不覆盖用户或其他插件条目 |
| 本机显示 | 主题、密度、列显示等 | 不推进世界、改变保密权限或触发生成 |

配置面板、结构面板和预览读取同一服务视图。不能每页单独拼接世界状态、模板或候选，也不能各存一份同名导出规则。

### 5.2 读写服务端口

T1 固定职责与命令语义；载荷/schema/提交回执在 T2/T4 定稿。下列不是本阶段已连接的真实方法：

| 端口职责 | 提供的能力 | 边界 |
| --- | --- | --- |
| 世界/模板只读查询 | 当前有效资料、表结构、范围及启用版本 | 不补种、不迁移、不将缓存视为最新权威 |
| 历史只读查询 | 指定版本与其历史模板、差异和依赖 | 不改变当前头或投影 |
| 运行状态查询 | 前置、阶段、已发送请求数、错误与冻结配置 | UI 关闭再打开仍读取同一后台任务，所有权不依附页面 |
| 上下文/投影预览 | 同一服务计算的可发送内容和托管差异 | 可预览不等于允许真实调用/同步，预估和最终版本分开 |
| 统一世界提交 | 保存资料、初始化、模型结果和恢复写回 | 暂存→校验→权威确认→切正式视图；不直接写 SQLite/缓存 |
| 模板迁移/默认配置 | 当前模板原子迁移、另存默认、路由等更新 | 根据作用域分别提交，不把几类保存混成一条 |
| 运行控制 | 开始、取消、重新演算及允许的续跑 | 前置证据/冻结身份/预算/权限复查；没有从 UI 直连 fetch 的旁路 |
| 世界书写入 | 确认范围后的同步、仅投影重试/重建 | 只消费有效正式提交，写前复查目标/隔离，不重新演变 |
| 备份与导入 | 只读导出、隔离预检、明确目标的导入/清空 | 先验证和恢复材料，凭据不混入模板/世界备份 |

所有可写入口，包括快捷键、高级 SQL/JSON、菜单和面板按钮，最终走相同服务门槛。T1 的策略函数只解释 UI 状态，生产服务不能将它当作互斥/CAS 或权限证据。

## 6. 按钮与后果契约

| 操作 | 改当前世界 | 调模型 | 写世界书 | UI 要求 |
| --- | --- | --- | --- | --- |
| 切页、查看资料/历史、预览上下文/投影 | 否 | 否 | 否 | 草稿离开保护；不自动执行后续动作 |
| 保存资料/初始化确认 | 是 | 否 | 不由这一点击隐含执行 | 明示当前世界/分支、锚点和差异，成功才称已存聊天 |
| 保存当前模板/结构迁移 | 数据与模板可能一起改变 | 否 | 否 | 迁移预览、冲突、备份；不兼容变更明确确认 |
| 另存全局默认模板 | 否 | 否 | 否 | 写清只影响未来采用它的世界 |
| 保存 API 普通配置 | 否 | 否 | 否 | 下轮生效，保留本轮冻结配置说明 |
| 保存提示词草稿 | 否 | 否 | 否 | 显示未启用，不假称已进入生成 |
| 保存显示设置 | 否 | 否 | 否 | 仅本机外观；不改 API、启用模板或保密权限 |
| 启用提示词/模板新版本 | 改启用版本，可能需迁移 | 否 | 否 | 与草稿保存分开；影响当前运行时显示过期/取消路径 |
| 本地模拟测试 | 否 | 仅假模型 | 否 | 不验证网络/Key，不冒充真实演变 |
| 真实连接测试 | 否 | 会联网，可能收费 | 否 | 独立命名，范围/请求上限/费用边界明确 |
| 开始/重新演算 | 成功后才提交 | 是 | 独立投影步骤 | 运行前检查、费用提示；两阶段暂存不是已保存 |
| 恢复已保存状态 | 明确恢复写回才是 | 否 | 独立对账/同步 | 先预览有效祖先/影响；不自动收费追平 |
| 同步/仅重试投影 | 否 | 否 | 是 | 标明 primary 和托管差异，过期任务不写 |
| 导出 | 否 | 否 | 否 | 来源/范围可选，脱敏；查看源的读权限仍检查 |
| 导入/迁移/清空 | 依明确目标而定 | 否 | 不隐含同步 | 范围、恢复材料和危险确认，不动其他插件 |
| 关闭面板 | 否 | 不发新请求、不取消现有请求 | 否 | 有草稿提示；后台任务独立，不等同停止脚本 |
| 取消运行/禁用运行权限 | 禁止该运行后续提交 | 阻止后续发送，不能撤销供应商已处理请求 | 不启动新同步 | 明确取消对象，迟到结果无效，费用可能未知 |

自动投影如果日后启用，也是提交确认之后独立的、有权限检查的后台步骤。保存资料的按钮不能隐藏“立即同步世界书”的行为；相关任务与后果在状态区可见。

T1 样例仅提供导航、示例草稿和离开确认。保存、真实测试、生成、恢复、同步、迁移和清空显示未接入/阻断；不会调用上述生产服务，也不会用假成功通知冒充正式结果。

## 7. 状态模型与允许动作

状态维度分别保存，不能用一个 `ready` 布尔值包办：

| 维度/状态 | 中文解释 | 允许/阻断原则 |
| --- | --- | --- |
| 内存沙盒 | 示例只在开发运行内存 | 可以导航/模拟，不能宣称已存聊天/已写世界书 |
| 正式模式 | 用户选择的真实世界，能力仍逐项检查 | 模式名称不授予写权限或 API 权限 |
| 未初始化 | 已选模板或没有世界资料 | 引导人工/来源导入/明确 AI 补全，不自动创建人物 |
| 无锚点/身份未知 | 缺有效助手消息或不能绑定世界/分支 | 保留草稿；禁止正式提交，不写 unknown_chat 共用分区 |
| 加载/恢复中 | 正在读取有效资料 | 禁止用旧缓存抢先当正式值；安全导航仍可用 |
| 历史只读 | 正在查看指定历史版本 | 不直接编辑或保存；恢复/建分支另开意图与确认 |
| 未保存草稿 | 页面内编辑，尚未确认提交 | 显示范围；离开有选择，不自动保存 |
| 世界已保存 | 权威提交确认且身份/版本匹配 | 正式视图可切换，投影状态另列 |
| 提交失败 | 明确未保存 | 保留有效草稿与错误，不推进版本，不回退旧库 |
| 确认未知 | 已发保存但应答/读回不明 | 先对账；禁止盲目重应用或再生成 |
| 前置等待/失败/未知 | 某个必要来源未完成或无法证明 | 不自动放行，展示来源与原因 |
| 宏观/微观运行 | 两阶段在私有世界处理 | 正式世界仍是旧提交，微观名单在宏观完成后冻结 |
| 宏观已暂存 | 可供微观使用，未正式保存 | 不能显示“世界已更新/已存聊天” |
| 无变化 | 有效处理但没有业务字段差异 | 中性反馈，不编造事件；若需记录处理标记/时间，由真实提交协议说明 |
| 取消/过期 | 运行权限撤销或输入/基准变化 | 不再发送/提交该运行；查看诊断仍可用 |
| 费用/结果未知 | 已发模型请求未取得确定结果 | 不承诺零费用；不自动重发或续付费 |
| 待同步/投影失败 | 世界已保存但投影未完成 | 世界结果保留；仅投影重试，不重复 AI 或推进时间 |
| 存档损坏/依赖不明 | 不能证明有效状态 | 只读诊断/备份，禁止猜补后正式写入 |

错误定位按阶段、表/字段、来源和具体原因展示；技术 ID 和 SQL 放高级详情，普通用户不用理解 revision 等词才能处理问题。

T1 纯策略把保存确认分为不适用、已确认、未知。未知时仍能查看诊断，但重复保存、恢复、再生成和世界书同步均被阻断；“查看保存确认状态”只是只读意图，T4/T10 才实现实际对账。已发 AI 请求的结果未知单独标记为中断，不自动重发。

## 8. 首次初始化、无锚点与作用域切换

初始化向导：选择范围/模板→人工或选定只读来源→字段/来源映射→冲突/差异→有效锚点检查→明确首次提交。

- 采用默认模板不等于导入旧数据或加入演示 NPC。
- AI 补全是另外的生成动作，明确请求范围和费用；不因进入向导而执行。
- 已确认剧情事实与已有/锁定资料冲突时报告，不按“最后收到”静默覆盖。
- 没有助手锚点只能保留草稿；后来出现锚点不自动提交，要重新核对输入、范围和差异。
- 人工修改、初始化和结构迁移承载在当前分支末端的有效助手锚点；历史只读不能借“保存”修改过去。
- 真正切世界/分支/角色卡之前保护草稿，取消或失效旧绑定；不把旧草稿带进新世界，也不把旧运行结果写到当前新目标。
- 首版样例是单个沙盒绑定，不实现真实聊天切换/初始化；这些流程在 T5/T10 接服务后验收。

## 9. 草稿、关闭和运行中变更

### 9.1 草稿离开策略

- 无修改或仍在相同路由，不重复确认。
- 有示例草稿时切页/关闭进入待确认；选择“留在当前页”保留路由与草稿，或“明确丢弃并继续”。不默认保存，不自动丢弃。
- T1 最小模型只管理一个示例草稿。另一个作用域的草稿不能静默覆盖它；多对象草稿管理留给 T5/T6 的真实编辑服务。
- 生产草稿必须按世界/分支/编辑目标隔离；保存失败保留仍有效草稿，不同基准的草稿不能自动重用。
- 样例和首版默认不提供跨刷新持久草稿。常驻说明刷新/销毁会丢失内存草稿；支持跨刷新恢复若后续添加，不成为正式权威。
- 关闭 UI 不等于取消任务或停止脚本。任务所有权在后台服务；重新打开正式面板应读同一任务，不重启一轮。

### 9.2 运行中的修改分类

| 修改 | 本轮影响 |
| --- | --- |
| API 路由/模型/普通参数保存 | 下轮生效，本轮继续冻结配置；不静默切模型 |
| 提示词/模板尚未启用的草稿 | 不影响正在运行的启用版本 |
| 当前数据或启用模板的正式提交、剧情/分支变化 | 使旧运行过期，不提交迟到结果 |
| 取消、禁用或明确撤销运行权限 | 立即禁止该轮后续发送/提交 |
| 主题、密度、列宽、纯显示隐藏 | 不使运行过期、不改变读取保密策略 |

常规本地编辑可先成为草稿；当前世界数据/结构的正式保存默认要求先取消活跃演变，避免用户在同面板制造冲突。其他实例或外部输入改变仍由提交前版本检查拒绝，不能仅依赖 UI 禁用按钮。

## 10. 权限与能力门控

| 标记 | 含义 | 不是 |
| --- | --- | --- |
| 只读视图/来源 | 不允许从此入口修改 | 删除该对象或排除全部上下文 |
| 关闭自动更新 | AI 不更新该表/对象 | AI 不能按读取权限参考它 |
| 锁定行/字段 | 按权限阻止指定修改，解锁是明确操作 | 丢失关系、历史或允许读的事实 |
| 隐藏列 | 仅 UI 展示选择 | 自动成为秘密或自动解锁 |
| 可见性/读取权限 | 用户、演变 AI、主 AI 投影分别限定 | 可以被高级入口绕过的提示词建议 |
| 归档/死亡/停用 | 生命周期规则，可能保留历史/引用 | 自动删除、不可读或复活 |

能力状态至少区分有效身份/锚点、宿主保存确认、并发范围、模板有效、API 路由、逐前置证据、primary 绑定、投影隔离。T0 未验证的生产能力默认不能放行。

API 就绪不代表存档就绪；primary 解析成功不代表世界书隔离通过。能力不足按操作显示具体原因：仍可只读/预览，真实保存或投影分别阻断。

确认弹窗不能补足缺失能力。既有旧脚本风险没有因为 T1 页面状态模型而修复；本阶段不执行其启动恢复路径。
