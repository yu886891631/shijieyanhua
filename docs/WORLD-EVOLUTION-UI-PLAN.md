# 世界演变工作台 UI 规划

## 目标

把现有“右下角小浮窗 + 自动演变 / 数据库两页签”改成居中的完整工作台。页面先围绕用户实际要处理的事情分类，而不是沿用实现模块名称；数据库继续作为世界状态事实源，世界书继续作为可重建投影。

## 页面分类

| 页面 | 负责什么 | 主要操作 |
| --- | --- | --- |
| 总览 | 当前聊天的关键状态与最近楼层活动 | 快速跳转到资料、运行记录、投影、提示词 |
| 世界资料 | NPC、组织、地点、社会、环境、事件、计划 | 分类查看、搜索、新增、编辑、删除 |
| 楼层记录 | floor run、revision、checkpoint | 查看状态与错误、创建检查点、确定性重建 |
| 世界书投影 | 当前角色卡 `primary` 世界书的托管条目 | 检查、同步、修复漂移、完整重建 |
| 自动演变 | 自动触发、手动运行、数量限制和运行选项 | 控制运行行为；真实 API 测试另行确认 |
| 填表提示词 | 多消息角色提示词草稿 | 调整角色、顺序、正文；JSON 导入 / 导出 |
| 备份与迁移 | 当前聊天数据的备份保护与旧版迁移 | 导入 / 导出、迁移预检、清空当前聊天 |
| 外观与显示 | 控制台主题和阅读缩放 | 浅色、深色、奶油风、地雷色；100%、110%、125% |

## 本轮 UI 基线

- 控制台改为居中大工作台，左侧分类导航，右侧独立页面内容区。
- 总览展示当前聊天的 NPC、组织/地点、楼层记录和世界书投影摘要。
- 数据库页面按“世界资料、楼层记录、世界书投影、备份与迁移”拆分，数据库写入仍复用既有 repository 和事务。
- 提示词页提供多消息编辑器、角色选择、排序、添加 / 删除、JSON 导入 / 导出；样例只作为本地草稿，不改变当前 `buildWorldEvolutionPrompt` 真实请求。
- UI 外观设置仅用于工作台显示，不修改角色卡、世界状态、聊天历史或酒馆预设。

## 提示词样例处理

`acu-form-fill-prompt(4).json` 用于参考多消息提示词的编辑结构，不作为世界演变提示词直接执行。其内容包含要求绕过安全边界、移除年龄限制的指令，因此本轮不原样复制；工作台内只放置了与世界演变数据库 operations 对齐的中性样例草稿。后续确认提示词规则后，再决定哪些角色消息和上下文槽位进入实际 AI 请求。

## 后续建议

1. 在 SillyTavern 中检查居中工作台的尺寸、滚动、窄屏导航和内嵌数据库组件样式。
2. 按用户给出的实际表格提示词，逐条映射到 `baseRevision + operations`，不兼容的旧式 tableEdit 命令不直接执行。
3. 先用模拟 AI 验证提示词组装和 operations 校验，再决定是否进行单轮真实 API 验收。
4. 用户确认字段布局后，再把数据库 JSON 字段编辑逐步升级为面向 NPC、组织、社会和环境的表单编辑器。
