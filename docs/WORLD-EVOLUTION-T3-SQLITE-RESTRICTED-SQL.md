# T3：SQLite 内核与受限 SQL

日期：2026-10-07。范围：新架构的隔离执行服务，不替换 alpha.16 当前聊天数据库。

## 1. 本阶段解决什么

T2 定义的默认七表、环境＋NPC 最小模板及自定义业务表，现在可以从合法 JSON 建立真实 SQLite 内存表，执行受限查询、新增、修改、删除，再严格导出待提交 JSON。

SQL 是更新指令，SQLite 是临时执行和检查引擎，JSON 仍是后续正式存档的格式。执行成功只产生私有草稿，不代表已经保存聊天、增加 revision、同步缓存或更新世界书。

不修改当前酒馆设置、API
Key、剧情、旧数据库和角色卡世界书；没有真实 AI 请求、迁移、清空、生产构建、导入包、Git 提交或推送。可填写工作台仍在 T5，统一保存/版本冲突/幂等在 T4，实际宿主保存在 T10。

## 2. 固定依赖和浏览器加载

- `sql.js` 精确版本为 `1.14.2`，类型包为 `@types/sql.js@1.4.11`。
- 浏览器构建选用包的 browser 导出，不把 Node 文件系统加载器带入 Worker。
- WASM 内嵌为 data URI，解码后校验长度、头部、WebAssembly 有效性和 SHA-256，随后通过 `wasmBinary`
  初始化；没有从网络补载 WASM 的回退。
- WASM：658,410 字节，SHA-256 `38c14f6e379210bc942bdc4ebca44e7bfdb4318ecc1c72ca666a28fdce96670a`。
- 此固定包在本机报告 SQLite `3.49.1`；不是运行时追随 CDN 的 latest。
- 缺资源、指纹不符、WebCrypto 不可用、Worker 启动失败均拒绝执行，不改用假 SQL。

参考项目的 JSON/SQLite 分工；本阶段没有复制其业务表或任意 SQL 执行器。加载与卸载依据
[sql.js 官方仓库](https://github.com/sql-js/sql.js) 和
[Database API](https://sql.js.org/documentation/Database.html)；每个临时数据库最终都调用 `close()`，每个 prepared
statement 都释放。

注意：目前只验证隔离的内存 webpack 构建。仓库共享 webpack 仍会将部分 npm 模块外置，不能直接假设生产脚本已经包含 WASM。最终入口要采用本阶段验证的 browser/inline 规则；本轮未改共享构建、旧 dist 或导入地址。实际酒馆 iframe 的 Worker、CSP、WASM/WebCrypto 许可仍需后续指定验收，模拟通过不等于该项真机通过。

## 3. 模板到 SQLite 的映射

- 模板是唯一结构来源。表名使用模板的 `we_*`，业务列使用 `f_*`；中文名字只用于显示。
- 采用真实 `STRICT` 表、稳定文本主键、物理类型/范围/枚举/JSON 约束。
- 九个 `__we_*`
  元数据列由代码管理：身份、锁、锁定字段、归档、读取可见性、来源、创建/更新版本、字段存在性。普通 SQL 不得写它们。
- 用户可显式读取 `__we_row_id`，用它选择目标；不能读取其他元数据、SQLite 隐式 rowid 或系统表。
- `__we_presence` 保存实际提供的字段 ID，区分缺失值与显式 NULL，不用 NULL 猜测是否需要默认值。
- 导入已有行不补种、不覆盖；新增行才在缺失处应用 T2 静态默认值。
- 精确小数按 T2 的缩放整数存储，外部仍是精确文本；复合值用 JSON TEXT，但导出时必须再校验完整引用图。
- 同名角色不合并，引用使用 `tableId + rowId`，不是角色姓名。
- 每次导出核对精确 sqlite_schema、列、主键索引；拒绝额外表、视图、触发器、索引、临时对象和附加数据库。没有任意 SQLite 二进制导入入口。
- 原始 TEXT 的 NUL 或孤立 UTF-16 代理会导致 sql.js 有损编码，因此明确拒绝；合法中文、emoji、引号和已转义复合 JSON 保留。旧资料载入还执行完整往返等价检查，发现损失就关闭临时库。

数组内多引用并非由 SQLite 外键自动保证。本服务在整批结束时调用 T2 全图校验：引用对象缺失、类型错误、未知字段或无效元数据都会使整批失败。

## 4. 首版允许的 SQL

只支持 SELECT、INSERT、UPDATE、DELETE。先按 token 解析完整批次为受限 AST，再由代码编译允许的标识符和绑定值；不会直接把用户原 SQL 传给 SQLite。

```sql
SELECT __we_row_id, f_name, f_weather
FROM we_environment
WHERE __we_row_id = ?
ORDER BY __we_row_id ASC LIMIT 20;

UPDATE we_environment SET f_weather = ?, f_risk = ?
WHERE __we_row_id = ?;

INSERT INTO we_npc (f_name, f_identity, f_condition)
VALUES (?, ?, ?);

DELETE FROM we_npc WHERE __we_row_id IN (?, ?);
```

以上是语法示例，不自动授权、执行或删除当前资料。默认 AI 无物理删除权限；引用、锁和具体预算还要校验。

规则：

- SELECT 必须明确列，单表查询；省略 WHERE 时也只能读取授权名单，不是全库。始终按稳定行 ID 升序，LIMIT 在 SQLite 过滤现存行后生效。
- UPDATE/DELETE 必须用 `WHERE __we_row_id = 值` 或 `IN (值,...)`
  明确选行。无 WHERE、按姓名匹配、`1=1`、OR、范围表达式均拒绝。
- INSERT 一次新增一行，必须显式列名，不允许模型分配元数据 ID。
- 单引号文本、有限且无静默舍入的数值、TRUE/FALSE、NULL、位置参数 `?` 可作值；类型检查不把 `'false'`
  当布尔，不把字符串数字任意转成数值。
- 位置参数贯穿整个批次，缺少或多余参数均拒绝；不支持命名参数或 `?1`。
- 复合字段可传严格 JSON 参数或合法 JSON 文本；其中引用和世界时间仍须符合 T2 协议。
- 注释按 token 处理，字符串中的分号/注释/攻击文本只是数据；不是用分号正则拆 SQL。
- 不带引号的 ASCII 名称按小写规范化；双引号标识符必须已经是规范小写名称。
- 不支持
  `*`、函数、算术、字段复制表达式、子查询、CTE、JOIN、聚合、UNION、RETURNING、UPSERT、多行 VALUES、任意排序/分页和 DEFAULT 表达式。
- 不支持 CREATE/ALTER/DROP、PRAGMA、ATTACH、VACUUM、事务控制和系统表。结构编辑/受支持 DDL 映射属于后续 T6 受控迁移，不能从常规数据 SQL 绕过去。
- 当前不开放任何非确定函数，包括随机数和当前时间。世界时间必须是调用方提供的固定业务值。

## 5. 冻结权限和阶段

`T3Policy` 由可信调用方生成，独立于模型的 SQL 输出，不允许 AI 自己申报授权：

```text
actor: manual 或 ai
stage: manual 为 null；ai 为 macro 或 micro
read: 每表的可读 rowIds 和 fieldIds
write: 每表的可写 rowIds 和 fieldIds
insertTableIds: 可新增的表
```

- 读集与写集分别验证；能读不等于能改，能改不等于能从秘密列查询。
- 查询同时满足表/行/字段对 user 或 evolutionAi 的可见性以及本批 read 授权。
- 写入同时满足本批冻结候选/字段、T2 人工或 AI 操作权限、表/行/字段锁、只读和归档规则。
- 新增时自动补入的业务默认值也必须获字段写授权；固定日志记录物化后的默认值。仅用户可写的 NPC 备注不再自动填空串，改为可缺失字段，AI 新增角色不替用户填写，已有显式备注保留。
- 单/多引用查询还检查目标表、行和冻结读集；不公开不可读目标的 ID 或数量，遇到不可读目标拒绝本查询批次，不偷偷改写真实关系。UI 的用户预览另外遮蔽不可见引用，不能把 UI 遮蔽代替服务授权。
- AI 只能修改当前阶段组；微观可以读取允许的宏观条件，但不能反向改写宏观表。
- 关闭自动更新、阶段或频率不会抹掉允许读取的道路/天气事实；但 AI 修改仍拒绝。预算明确关闭或为零也不能写。
- 不支持从秘密列复制到公开列的 SQL 表达式或子查询；整个语法层直接拒绝。
- 删除不会自动解锁、自动清引用或自动级联。只有同批经过授权的显式更新解决引用，整图校验后才能接受删除。
- 删除移除的是整行，须对实际存在的所有业务字段具备写权限；不能靠空字段授权或只读字段绕过。不存在的可选字段不要求虚构删除权限。
- 解锁、归档、来源和版本属于后续受控业务意图，不在普通 SQL 中修改。

`createT3LocalPolicy`
是隔离示例/人工 UI 的便捷工厂，不是生产候选选择器。T7/T8 必须传入实际冻结的候选范围；T3 低层可以执行可信调用方的受限上下文查询，后续模型更新入口仍只收允许的 DML，不把查询授权连同 SQL 交给模型自行扩张。

## 6. 新增身份与固定日志

- `batchId` 是可信运行链分配的稳定输入，最多 32 字符；不是 SQL 的随机表达式。
- 第 N 条 INSERT 分配 `new-<batchId>-<从0开始的语句序号>`，碰撞拒绝，不偷偷改 ID。
- 同批目标/引用可用 `@new:N` 表示第 N 条 INSERT；代码先建立全部分配计划，再转成固定 ID。未知、跨表或非 INSERT 别名拒绝。
- 新行之间可有前向引用；不是每条 INSERT 都要求所有目标已存在，但整批结束必须完整一致。
- `log` 保存规范 SQL、已物化逻辑参数、模板身份/版本和批次；新增 ID 和来源描述由固定输入导出，不依赖实际执行时间。
- 接受结果前重新解析规范日志，超出文本/token 限制或参数不匹配时整批拒绝，不能产出无法通过自身限制的日志。
- `replayT3Log` 使用同一模板、基底、政策、限制和日志，无需 AI，输出相同待提交资料。模板身份/版本不匹配拒绝。
- `statements`
  是执行诊断，含允许业务列的 SQL/物理绑定及影响行；INSERT 的该字段是业务投影，不是完整含保护元数据的实际 INSERT，也不是恢复入口。恢复只使用独立
  `log`。

本阶段不是历史保存系统：日志未写聊天，不含正式提交链或快照截止位置。基准指纹、完整模板冻结、冲突、幂等、日志防重复、跨阶段统一额度和新 revision 由 T4 及后续运行器负责。不能把一次在同一基底重放成功理解为可对任何现状再次追加。

## 7. 事务和资源限制

每次执行建立独立临时库。完整批次先解析，通过后 BEGIN
IMMEDIATE；权限、实际影响行数、类型、预算、导出/结构/引用或日志检查任一失败，ROLLBACK 并关闭数据库，不返回部分草稿。成功导出后 COMMIT 并关闭；原 template/data/policy/参数始终不修改。

默认限制：SQL 20,000 字符、4,000
token、32 条语句；每条目标最多 100、业务列最多 256；本批不同受影响记录最多 50，新增最多 10；每条查询最多 100 行，全部查询结果累计最多 256,000 字符。

`maxQueryRows`
是每条查询窗口，不是整批总行数；全批另受语句数和累计结果大小限制。受影响记录按稳定表/行身份去重，重复改同一记录不重复占行配额；新增后删除不退还新增额度。实际超出模板硬上限或 AI 表级有效预算会拒绝，限额不能扩大模板硬上限。

执行线程：每个请求独占一次性 Worker，Worker 默认总超时 10 秒（包含初始化，不含发送前的纯请求校验）；配置范围 1–60,000
ms。超时或 AbortSignal 触发立即 terminate，不等 SQLite 同步查询返回。迟到结果丢弃；成功/失败也终止 Worker，清理监听、计时器、Blob
URL。主线程没有同步回退。

测试专用入口使用真实 SQLite 大规模递归查询证明执行中被终止；该入口不由实际 worker 模块或生产入口导入，常规解析器也不接受递归 SQL。

这里保证的是输入/行/结果限制和可硬终止的执行时间，不是浏览器内存绝对上限。固定 sql.js 构建没有本阶段可配置的严格 heap 配额，不能宣称已经实现按 MB 的硬内存沙箱。
