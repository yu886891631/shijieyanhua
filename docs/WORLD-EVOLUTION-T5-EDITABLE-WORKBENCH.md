# T5：可填写的表格工作台（隔离本地雏形）

日期：2026-10-07。阶段范围：T5；不自动进入 T6。代码基线仍为 alpha.16，没有变更正式导入入口。

## 1. 本阶段交付

用户可以通过类型化表单新增 NPC、填写身份与目标、选择所在地点，随后暂存、检查前后差异、确认保存。实际执行受限 SQLite
SQL，结果由 T4 模拟存档网关统一提交和读回；不是只改表格显示。

实现位于 `src/世界演变/rebuild/`：

| 文件                                     | 职责                                                          |
| ---------------------------------------- | ------------------------------------------------------------- |
| `T5TableWorkbench.vue`                   | 宏观/微观导航、资料表、行详情、表单、导入映射、差异与保存按钮 |
| `t5-workbench.ts`                        | 页面状态、草稿、搜索分页、权限前检及 T4 服务调用              |
| `t5-form.ts`                             | 类型化输入和参数绑定 SQL 编译                                 |
| `t5-controls.ts`                         | 行锁、字段锁、归档的人工受控操作                              |
| `t5-import.ts`                           | 只读识别 SPDB 二维导出、显式列映射和逐行冲突报告              |
| `t5-sandbox.ts`                          | 显式本地测试工厂、空世界、模拟锚点和模拟存档导出/重开         |
| `t5-workbench.test.ts` / `t5-ui.test.ts` | 实际 SQLite、控制器、挂载按钮、类型/样式及恢复回归            |

组件通过 `workbench` 属性接收隔离服务，没有读取宿主、实际聊天、API 设置或世界书。没有新建会被共享构建扫描的
`index.ts`，没有接入旧入口。当前酒馆页面不会因这些本地代码自动更新。

## 2. 不需要写 JSON 的手动路径

1. 在“宏观世界 → 地点”点击新增，填写完整名称，必要时补充通行状态等字段。
2. 点击“加入暂存修改”。此时既没有提交，也没有改旧记录。
3. 点击“校验并预览差异”，检查范围与前后值，再勾选确认。
4. 点击“保存模拟存档”，等待写入及读回确认。
5. 在“微观世界 → NPC”新增角色，填写名字、身份，选择已保存的地点，再按同样流程保存。
6. 编辑已有 NPC 时，输入会自动切换到“填写”；没有动过的字段保持原值。

七张默认表为空，不补种演示角色。没有 MVU 或 SPDB 时，手动建立环境与 NPC 的路径仍可使用。

有区别的输入状态：保持原值/使用默认值、明确 NULL、空字符串、0、false、空列表。数字和精确小数严格校验，不把错误数字改成 0，不把 NULL 改成默认值。完整名称不可只填空白。

支持文本/长文、整数、普通数值、精确小数、布尔、枚举、逐行字符串列表、单/多引用和模板纪元时间。引用选择显示表名、对象名与稳定 ID；重名不合并。纪元时间仍按 T2 的分钟序号与显示文本填写，未知可保留 NULL，不伪造现实时间转换。

## 3. 页面与编辑状态

- 左侧宏观/微观表组，显示当前表说明、可见记录数量。
- 搜索可见字段内容；筛选未归档/已归档/全部/行锁定，每页 20 条。
- “显示列”仅改变本次浏览显示，不修改模板或资料权限；隐藏 UI 字段本阶段不能通过此按钮重新公开。
- 行详情包含类型化输入、字段描述、当前值/默认值和字段错误定位。
- 当前填写和暂存操作跨表导航保留；未完成填写时再次打开编辑器会要求先暂存或取消。
- 对同一行的多次暂存更新合并为一个修改；不会因后一条只改位置而抹去之前暂存的目标。
- 暂存列表可逐项移除。取消填写、核对结果、删除其他行不会偷偷丢掉未保存填写。
- 每次新的修改、重新校验或失败均清除旧同意，不沿用另一批次的保存确认。
- 保存中禁用编辑，浏览/搜索不触发提交。保存失败保留草稿；确认丢失时先核对，不盲目重发 SQL。
- 并发更新或共享服务的基准变化阻止覆盖。用户须明确放弃草稿、载入新版本后再比较，不自动重基合并。
- 历史快照和行详情只读。查看不会回滚；返回当前世界后才能填写。

跨表保留只限本次工作台实例。关闭/刷新没有自动持久草稿；模拟存档导出的 JSON 必须由测试宿主持有，再传入工厂才能重开。本阶段不使用浏览器缓存冒充聊天权威。

## 4. 行锁、字段锁、归档和删除

普通 SQL 仍不能写系统元数据。本阶段给 T4 通用提交协议增加可选
`controls`，仅允许已知的行锁、字段锁、归档字段及 before/after 布尔值。

- 仅人工提交可用，不能与业务 SQL 混在同一提交；模型、迁移或恢复不能夹带这条新路径。
- 权限对原始基线判断，不因列表里先解锁而让后续归档绕过原锁。
- 解锁需先单独保存，再提交资料修改/归档/删除。
- 不允许任意快照替换、来源改写、业务字段或额外属性。
- 校验按基线重新应用精确控制操作，必须与私有快照完全一致；重新计算指纹也不能夹带业务变化。
- 控制操作同样有差异、统一版本戳、CAS、消息锚点、读回、快照恢复与固定重放。
- 旧提交缺少 `controls`
  时仍按原规则验收；不补默认字段改变旧指纹。旧代码不能读取新增控制提交，不能把沙盒文件直接交给旧运行版。

归档保留关系和历史；删除须经过粉红色确认区。仍被引用、行锁/字段锁、权限禁止时拒绝，不做级联删除，不泄露隐藏引用细节。当前雏形要求先明确修改引用并保存，再提交删除；没有隐式清空引用。

## 5. 只读来源与首次映射

当前支持用户主动提供 SPDB 导出样本中的
`sheet_*.content`：第一行为表头，其余为二维数据行。来源缺失或格式未知时明确拒绝，仍可人工建立世界。

页面可选择 JSON 文件或粘贴导出，选择来源表、目标表及各列的映射；没选中的字段不导入。文件/文本和解析后的结构均受大小限制；内容不作为 JavaScript、HTML 或 EJS 执行。

- 42 行角色样本识别为 42 条预览，不把表名当成一个 NPC。
- 中文、自定义列名按列位置映射；枚举、数值、引用须符合目标类型，不按列名猜类型或姓名关系。
- 每行显示类型/范围/必填错误及已导入冲突；不自动覆盖已有/锁定数据。
- 来源身份＋表身份＋稳定行序号生成确定身份；保存、重试、JSON 重开后不重复建人。
- 同名独立来源不因名字相同被合并。来源行顺序发生变化时，不宣称仍能自动匹配，须人工核对来源。
- 每次最多明确选择 10 条新增，未选行不导入；大来源分批处理。受 T3/T4 总预算约束，没有绕开上限的后台自动全量导入。
- 导入预览不写任何存档；选中后仍走同一套 SQL → 整批校验 → 差异 → 确认保存。

本阶段没有读取当前酒馆的前置插件。角色卡、原始世界书、MVU 和当前宿主具体导出的读取/适配还在 T7/T10；没有用固定样本通过声称所有宿主版本已兼容。后续世界书来源需排除本插件
`WorldEvolution-*` 投影，避免反馈。

## 6. 可见性与安全

只展示允许用户查看的表、行和字段；隐藏内容不会参与搜索、计数或引用选项。涉及未公开目标的引用字段保留原值并只读，不把隐藏身份放入编辑输入，也不在重新选择时无提示删除隐藏关系。

所有表格文字经 Vue 文本插值转义。SQL 只使用规范模板标识符和绑定参数。错误反馈使用固定文案，不把 SQL、模型正文或秘密错误原文显示出来。

行锁/字段锁仍在后端复核，不仅靠灰色按钮。工作台没有获得任意 snapshot 写权限，局部错误或整批引用错误不改变已确认的正式模拟世界。

## 7. 速度与样式

已校验快照建立一次可见数据/引用索引；搜索、分页、列切换、普通键入不重复整图校验。一次 200 行 fixture 的 100 次搜索＋可见页读取约 34.6 毫秒（完整并发回归期间），仅说明本地缓存浏览路径，不是手机或酒馆保证。

T4 新增单条、完整内容相等的成功验收结果缓存。不是按 revision 或 head 盲信；内容不同、损坏、访问器、超限仍重新验收/拒绝；返回重新解析的独立副本。只有已校验成功内容会缓存，失效输入不会覆盖成功结果。网关 CAS、当前消息锚点和新提交权限仍在写边界检查。此缓存不作为存档权威，不会在刷新后留下。

单独运行同一容量测试的结果：

| NPC 数 | JSON UTF-8 字节 | 私有准备/SQL ms | 保存＋读回 ms | 同进程重开 ms |
| -----: | --------------: | --------------: | ------------: | ------------: |
|      2 |          48,655 |          128.71 |        112.75 |          7.63 |
|     50 |         117,269 |          461.05 |        485.53 |         16.30 |
|    200 |         332,175 |        2,714.22 |      4,641.91 |        132.28 |

重开计时可能命中同进程内容缓存，不代表浏览器冷刷新或新进程恢复速度。并发全套回归中 200
NPC 的准备约 13.2 秒、保存读回约 7.7 秒；两种测试不可直接与 T4 并发计时作性能结论。大世界提交仍慢，T10/T15 必须继续剖析存档体积、长历史和设备表现，不能省略验证求快。浏览器执行器接入时应使用 T3
Worker；本组件只注入执行器，不在 UI 直接加载 SQLite。

界面为淡绿底、深绿文本、粉红危险区；私有 scoped 样式、可收缩网格、表内横向滚动、850/600 像素断点和可达的粘性编辑按钮。不使用
`100vw`、固定宿主定位或黑色块。

## 8. 验证与边界

T5 新增 33 项测试，合并此前阶段及旧运行/数据库模块共 506 项。覆盖实际 SQLite 保存/重开、模拟失败/ACK 丢失/并发、锁定/归档/删除重放、42 行来源映射及防重复、各类型/空值、隐私和注入、Vue 严格编译/SSR/scoped 样式及挂载按钮交互。

挂载交互用合成渲染器触发实际组件事件，包括新增、输入、表单提交、差异确认、保存和首次错误焦点；不是直接改 controller 后把按钮存在当成功。CSS 断点检查不是几何测量，100%/110%/125% 实际浏览器布局、手机及宿主样式仍待后续实页验收。

未执行共享生产构建。旧两份 dist 和 alpha.16 导入包 SHA-256 均不变，既有 UI 计划书的未提交修改保留。本阶段没有修改实际聊天、旧数据库、MVU、世界书或 API 设置，没有真实 AI 调用，没有 Git 提交/推送或发布包。

下一步为 T6：结构参数、DIY 与原子迁移。需用户明确开始后，再开放字段/表结构、表级规则、迁移差异及确认提交；当前只是资料工作台，不把结构按钮做成不生效的假编辑器。
