# T11：总览、自动演变与楼层记录收口

日期：2026-10-09。范围：新 SQL 表格工作台的本地实现与模拟验收，不是 alpha.16 已发布页面升级。

## 1. 本阶段实现什么

新增 `T11DailyWorkbench.vue` 与
`t11-controller.ts`，三个日常页面共享注入的同一个 T9 整轮调度器、T4 提交服务和 T4/T10 存档网关。没有另建计时器等待前置、第二套演变器或第二套请求额度。

- 总览：世界/分支、模板版本、正式版本、宏观/微观公开记录数量、准备检查、最近运行、最近公开差异和独立的投影状态。
- 自动演变：自动开关、手动整轮、取消、显式同轮续跑/仅重试保存、只查询回执，以及表级频率、API 路由、候选理由、跳过原因和上下文/请求额度。
- 楼层记录：运行尝试与正式提交链分开；可只读查看双阶段差异、固定 SQL/参数、模板、世界时间、父提交、恢复来源和检查点。可预览并确认恢复到选定历史；失效尾部和影响范围单列。

背景说明统一用中文，常规区淡绿、危险恢复区粉色。CSS 限定组件作用域；窄屏表格在自己的滚动区内，不影响宿主页面。

## 2. 状态必须来自服务，不由按钮猜测

总览和历史显示 T4 已确认的版本，不把 T9 的宏观暂存当成正式世界，也不把失败、取消、重试当成新版本。

T4 增加只读状态订阅和 `busy`
状态：人工编辑保存后，日常页收到通知并查询历史，三个页面保持一致。提交准备中还没有生成草稿时，也会阻断新的整轮，避免空窗竞争。通知函数失败不能改变提交结果。

页面“检查准备情况”只读取存档、构建 T7 预检计划；没有模型请求、SQL 执行、保存或世界书写入。输入、模板、提示词、API 配置变化后，旧预检自动失效。

已知的微观路由缺项在宏观发送前阻断；微观候选与批次仍须等待本轮宏观交接，不伪造最终计划。频率直接读取已封存 T9 成功账本，展示合格剧情单位、起点、上次成功、下次到期。失败不推进频率；无公开变化但成功处理会推进成功标记。

读取存档失败时，不把缓存历史称为当前有效世界。T10 可以证明有效祖先时，显示其版本与待处理尾部；坏链不会自动重放 SQL 或续发 AI。原来已经保存、现在依赖失效的运行显示“原提交已确认，当前依赖失效”，而非当前有效版本。

投影状态与提交结果独立。未注入新投影服务时固定显示“未接入，T12 接入”，不报“世界书已同步”。注入回执读取函数也不授予写世界书的权限。

## 3. 自动、等待、取消与续跑

自动开关默认关闭，仅在本实例保留。开启开关、打开页面、切换页签和刷新存档都不启动生成。

可信事件适配器可显式调用 `trigger('assistant-completed')` 或
`trigger('prerequisite-changed')`。它和手动按钮通过同一个 T9/T8 队列领取触发；本轮各前置独立证明，仍由 T8 等待和检查。重复事件、旧 swipe、失败前置不能双发或绕过等待。实际酒馆事件监听器本阶段未注册。

关闭自动会取消正在等待/运行的自动任务，不会取消手动任务。暂停中的同轮私有结果不能被“开始新一轮”替换；可显式续跑，或取消暂存。人工草稿存在时不会被运行/历史查看丢弃。

- 微观网络中断：仅同实例仍拥有触发权、同输入/基准、未过期且有剩余额度时可显式续跑。
- 明确保存失败：重试相同提交，不再请求模型，不重置发送额度。
- 保存回执未知：只查询已保存记录；不能盲目重新生成或覆盖。
- SQL/类型/引用/业务错误：不能自动整轮重试。
- 取消/超时：未确认提交不算已保存；已发真实请求可能收费，不能承诺撤销供应商请求。当前传输仍是本地假响应，不收费。

T10 的“存在未完成持久运行记录”会阻断新会话写入。已有同实例可显式续跑的会话使用可信 `session.canContinue()`
授权，检查驱动能力、会话失效状态和队列拥有者；刷新后的新控制器没有该权限。打开历史不恢复私有宏观/微观结果，不自动发送。

关闭一个 Vue 页面只卸载页面订阅，不取消其他页面共用的运行。只有根运行宿主关闭时调用控制器/会话的
`close()`，停止新任务并阻断迟到保存。

## 4. 楼层查看与恢复的后果分开

| 动作                                 | 后果                                                           |
| ------------------------------------ | -------------------------------------------------------------- |
| 查看运行、提交、固定 SQL、历史检查点 | 只读，不执行 SQL，不保存，不调用 AI                            |
| 重新载入正式资料                     | 重新确认当前存档；不产生新提交，不生成剧情                     |
| 预览恢复到所选检查点                 | 计算公开差异和当前分支后续范围；不生成提交                     |
| 勾选确认后恢复                       | 通过同一 T4 服务和网关追加一条恢复提交，原历史保留；零模型请求 |
| 恢复回执未知后的查询                 | 只核对已写入的提交身份，不重新执行/保存                        |
| 查看删楼/重算影响范围                | 只预览后续提交与消息；不删除实际聊天、不重算                   |

恢复的是完整检查点：数据、模板结构与成功进度一起恢复，包含未公开字段；界面只展示公开差异，确认文案明确其完整影响。正式修订号在当前头之后追加，不回退提交头、不抹除原历史。

确认前和原子写入点再次检查输入、世界/分支、当前头、会话权限和草稿归属。预览后出现人工提交、剧情变化、其他编辑草稿或异步锚点捕捉期间的冲突时，不能覆盖新资料。已准备恢复保存失败后只重试原负载；回执未知时只查询。

分支/复制底层仍采用 T10 既有独立目标身份、当前聊天绑定和有序锚点映射契约。T11 展示父提交/恢复来源和影响边界，不增加猜测目标的“分支”假按钮，不支持合并分支。重生成、清空聊天或批量删楼也未在此页自动实现；这些需明确目标与后续集成，不混成一个“恢复”操作。

## 5. 历史与错误显示的安全

`t11-history.ts`
从已校验存档生成公开历史，不直接把完整 JSON 或 SQL 权限对象塞进页面。历史必须同时满足旧版本和当前版本的表/行/字段可见性；当前撤销权限后，不从旧快照泄漏原值。

公开差异继承 T4 的引用遮罩与截取规则。日志若涉及隐藏表、隐藏字段、隐藏行、私有引用、系统列或已知 API
Key，整批 SQL/参数不展示，原存档保持不变。已知凭据还会从所有页面显示数据中遮罩；模板/资料含凭据时预检阻断。

新增 `t3-diagnostic.ts` 将真实本地 `T3EngineError`
的受信类别、公开字段、已确认的语句索引（转为从 1 开始）传给 T8/T9，再显示到日常页。没有提供坐标、解析失败、字段不可见或 Worker/供应商只是普通错误对象时不猜测；始终不展示错误原文或拒绝的单元格值。

行、字段、模板、SQL、提示词和外部材料用安全文本插值。没有 `v-html`、任意脚本/模板执行、API
Key/headers 或原始供应商错误日志。

运行展示最多保留本实例 64 项；跨刷新只读取 T10 已存安全记录。历史公开差异/检查点最多展示 100 行，明确提示截取；完整存档不因此删除。历史投影按不可变存档/正式头缓存，避免每次状态通知重复构建所有检查点；缓存不作为权威。

## 6. 接线契约与实现文件

和运行配置读取函数。宿主模式还须注入独立持久恢复检查；未验证宿主保持只读。T10 会话需使用其
`canRun`/`canContinue`，不能把用户 JSON 开关当作权限。

`restoreSpec`。未提供时仅允许预览，不显示假保存。外部资料/API/提示词页跳转由宿主注入
`navigate`；未挂载导航时按钮明确禁用并解释。
