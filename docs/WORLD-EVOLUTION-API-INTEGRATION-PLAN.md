# 世界演变控制台内置 API 计划书

> 版本：A0.1.0 API 内置化计划  
> 日期：2026-09-30  
> 状态：S1 基线与隔离、S2 API 配置数据层、S3 API 客户端与模拟请求、S4 控制台 API 页面、S5 路由与工作流助手兼容已完成；下一阶段为 S6 接入世界演变引擎
> 适用范围：世界演变控制台、世界演变数据库、工作流助手兼容桥接

## 1. 目标

将 API 配置从“必须依赖工作流助手”调整为“世界演变控制台可以独立配置和调用”，同时保留对现有工作流助手 API 预设的兼容。

最终用户只需要打开世界演变控制台，就可以完成：

- 配置 API 地址、API Key、模型；
- 选择 OpenAI 兼容接口或其他受支持的协议；
- 配置主 API 和备用 API；
- 测试连接；
- 查看配置状态；
- 执行手动或自动世界演变。

工作流助手仍然可以独立运行，不被删除，也不再是世界演变运行的硬性依赖。

## 2. 目标架构

```text
世界演变控制台
  ├─ 内置 API 配置与安全存储
  ├─ 主 API / 备用 API 路由
  ├─ 连接测试与错误诊断
  ├─ 世界演变触发与运行状态
  └─ 可选读取工作流助手 API 预设

世界演变数据库
  ├─ 楼层账本
  ├─ NPC、组织、社会、环境等事实表
  ├─ revision 与事务提交
  └─ WorldEvolution-* 世界书投影

工作流助手
  ├─ 六阶段工作流
  ├─ 自己的 API 预设
  └─ 可选向世界演变提供兼容桥接
```

调用优先级固定为：

1. 世界演变控制台内置主 API；
2. 世界演变控制台内置备用 API；
3. 工作流助手桥接中的主 API；
4. 工作流助手桥接中的备用 API；
5. 没有可用路由时停止并提示配置。

默认不直接调用 SillyTavern 当前全局 API，避免用户误以为控制台已经使用了某个全局预设。

## 3. 配置数据模型

### 3.1 API 预设

```ts
type WorldEvolutionApiPreset = {
  id: string;
  name: string;
  provider: 'openai-compatible' | 'custom';
  endpoint: string;
  apiKey: string;
  model: string;
  enabled: boolean;
  timeoutMs: number;
  maxRetries: number;
  createdAt: string;
  updatedAt: string;
};
```

API Key 只用于本地请求，不进入：

- 世界演变数据库业务记录；
- 世界书；
- 楼层日志；
- 主 AI 上下文；
- UI 日志和错误消息。

### 3.2 路由设置

```ts
type WorldEvolutionApiRouting = {
  primaryPresetId: string | null;
  fallbackPresetIds: string[];
  preferBuiltin: boolean;
  allowWorkflowAssistantBridge: boolean;
  testBeforeRun: boolean;
};
```

`preferBuiltin` 默认开启。旧版仅保存 `apiPresetName` 的设置需要自动迁移到新的 preset ID。

## 4. 页面与 UI 计划

在当前“自动演变”页面中增加独立的“API 配置与路由”区域，不把 API 配置藏在数据库页面或工作流助手页面。

### 4.1 API 预设列表

显示：

- 预设名称；
- 服务商类型；
- 模型；
- 主/备用标记；
- 启用状态；
- Key 是否已配置；
- 最近测试结果；
- 最近更新时间。

不显示完整 Key，只显示“已配置 / 未配置”。

### 4.2 编辑表单

字段：

- 预设名称；
- API 协议；
- Endpoint；
- API Key；
- 模型名；
- 超时；
- 重试次数；
- 是否启用。

按钮：

- 保存；
- 测试连接；
- 删除预设；
- 复制为新预设；
- 清除 Key。

### 4.3 路由面板

提供：

- 主 API 下拉框；
- 备用 API 多选和排序；
- 是否优先使用内置 API；
- 是否允许读取工作流助手桥接；
- 是否在正式运行前自动测试。

### 4.4 状态与诊断

只展示安全摘要：

```text
主 API：已配置 / 未配置
模型：xxx
备用路由：2 个
工作流助手桥接：已连接 / 未连接
最近测试：成功 / 失败
```

错误信息需要脱敏，禁止把 Key、完整 Authorization 请求头或敏感响应原文写入日志。

## 5. API 调用层

新增统一的 `WorldEvolutionApiClient`，数据库和 UI 不直接拼装 HTTP 请求。

调用流程：

```text
读取路由设置
    ↓
按顺序解析内置主 API、内置备用 API
    ↓
若允许，再解析工作流助手桥接
    ↓
构造受限请求
    ↓
解析文本或 JSON 响应
    ↓
返回统一结果
```

统一结果格式：

```ts
type WorldEvolutionApiResult =
  | {
      ok: true;
      presetId: string;
      model: string;
      text: string;
      requestId?: string;
      durationMs: number;
    }
  | {
      ok: false;
      presetId?: string;
      code: 'CONFIG' | 'NETWORK' | 'HTTP' | 'TIMEOUT' | 'PARSE' | 'ABORTED';
      message: string;
      retryable: boolean;
      durationMs: number;
    };
```

备用路由只在可重试错误时切换，例如网络失败、超时、429、5xx。认证失败、请求格式错误和本地校验失败不应盲目重试。

## 6. 与现有世界演变流程的衔接

内置 API 只替换“AI 调用入口”，不改变已经完成的数据库事务设计：

```text
剧情楼层完成
    ↓
读取楼层账本与相关数据库表
    ↓
组装世界演变上下文
    ↓
内置 API 路由调用
    ↓
AI operations 本地整批校验
    ↓
baseRevision 冲突检测
    ↓
数据库 revision 事务提交
    ↓
精确投影 WorldEvolution-* 世界书
```

API 调用失败时：

- 不提交数据库 revision；
- 不更新世界书；
- 保留失败记录和可重试状态；
- 不重复消耗已经成功提交的操作。

## 7. 工作流助手兼容策略

兼容桥接保留，但降级为可选来源：

- 旧版工作流助手配置不需要立即迁移；
- 控制台可以读取预设名称、模型和配置状态；
- 不读取或显示原始 Key；
- 用户选择内置 API 后，世界演变不再依赖工作流助手；
- 删除工作流助手后，内置 API 仍可运行；
- 只使用工作流助手时，继续支持旧版行为。

迁移提示应明确告诉用户当前使用的是：

```text
内置 API
工作流助手桥接
未配置
```

## 8. 实施阶段

> 稳定实施原则：不直接改写正在使用的 alpha.11；所有内置 API 改动先进入独立的 alpha.12 开发线。每个阶段完成后先做本地模拟测试，再进入下一阶段。除最后的真机验收外，不调用真实 API，不消耗额度。

### 稳定里程碑总览

为降低一次性改动范围，API-1 至 API-6 再拆为以下 8 个可独立验收的里程碑：

```text
S1 基线与隔离
  ↓
S2 API 配置数据层
  ↓
S3 API 客户端与模拟请求
  ↓
S4 控制台 API 页面
  ↓
S5 路由与工作流助手兼容
  ↓
S6 接入世界演变引擎
  ↓
S7 事务、投影与恢复测试
  ↓
S8 真机验收与 alpha.12 发布
```

### S1：基线与隔离

- 保留 alpha.11 代码、导入包和 CDN 地址不变；
- 建立 alpha.12 开发版本；
- 确认旧数据库、楼层记录、世界书和工作流助手数据不被迁移过程覆盖；
- 为后续失败测试准备可恢复的本地快照。

验收：只导入 alpha.12 测试包不会改变 alpha.11 的运行结果。

### S2：API 配置数据层

- 增加 API 预设、主路由和备用路由的数据结构；
- 保存 API 地址、Key、模型、超时和重试设置；
- 增加配置版本号和旧版设置迁移；
- 增加导出时的脱敏规则。

验收：配置可以保存、读取和迁移；导出数据不包含明文 Key。

### S3：API 客户端与模拟请求

- 实现统一的 OpenAI 兼容请求客户端；
- 增加超时、取消、错误分类和重试；
- 使用模拟 `fetch` 覆盖成功、超时、429、5xx、认证失败和非法响应；
- 暂不连接真实 API。

验收：所有模拟请求都返回统一结果，错误不会写入敏感信息。

### S4：控制台 API 页面

- 增加 API 预设列表；
- 增加新增、编辑、删除、复制和连接测试；
- 增加 Key 的“已配置 / 未配置”状态显示；
- 增加主 API 和备用 API 的编辑入口；
- 增加清晰的保存成功和失败提示。

验收：不调用真实 API 时，页面上的配置操作和模拟连接测试均可完成。

### S5：路由与工作流助手兼容

- 内置 API 默认优先；
- 支持备用 API 顺序调整；
- 工作流助手桥接作为可选来源；
- 支持仅内置、仅桥接、双来源和无来源四种状态；
- 不回退到未明确配置的 SillyTavern 全局 API。
- 统一由 `api-routing.ts` 解析有效来源和实际尝试顺序；
- 内置 API 复用 S3 的主/备用路由、重试和错误分类；
- 只有网络、超时、429/5xx 等可重试失败才允许跨来源继续尝试；
- 认证错误、请求格式错误、解析错误和取消不会盲目切换来源；
- 工作流助手只通过 `AcuPostProcessAPI.callApi` 桥接，不读取或复制 API Key；
- 控制台显示有效来源与实际路由顺序；
- 增加 11 项纯模拟路由测试，未调用真实 API。

验收：四种配置状态都能显示正确的来源、优先级和错误提示；`api-routing.test.ts` 全部通过。

### S6：接入世界演变引擎

- 将世界演变的 AI 调用统一切换到新 API 客户端；
- 接入现有上下文组装流程；
- 接入 operations 本地校验；
- 接入 `baseRevision` 冲突检测；
- API 失败时不提交数据库 revision。

验收：模拟 API 下可以完成“读取上下文—调用—解析—校验”，但仍不触发真实自动运行。

### S7：事务、投影与恢复测试

- 测试成功提交、失败重试、revision 冲突和取消运行；
- 测试删除楼层后的确定性重建；
- 测试数据库提交成功后才更新 `WorldEvolution-*` 世界书；
- 测试世界书投影失败不会破坏数据库；
- 测试已成功提交的结果不会因重试而重复写入。

验收：数据库、revision、世界书投影和恢复流程保持一致。

### S8：真机验收与 alpha.12 发布

- 导入 alpha.12，但默认关闭插件和自动触发；
- 先验证页面打开、配置保存和模拟运行；
- 再用低额度测试预设进行一次手动连接测试；
- 最后测试一次手动世界演变；
- 根据结果决定是否开放自动触发；
- 发布固定 commit 的 CDN 地址和独立导入包。

验收：不删除聊天、旧脚本、数据库或世界书；出现问题时可以关闭 alpha.12 并恢复 alpha.11。

### API-1：配置存储抽象

- 增加 API preset schema；
- 增加路由设置 schema；
- 增加版本化迁移；
- 对 Key 做最小必要的本地存储封装；
- 增加导出时的脱敏规则。

验收：旧设置可以读取，新设置可以保存，导出文件不含明文 Key。

### API-2：内置 API 客户端

- 实现 OpenAI 兼容请求；
- 实现超时、取消和重试；
- 实现统一响应解析；
- 实现错误分类与脱敏日志；
- 暂不接入真实自动触发。

验收：使用模拟 fetch 覆盖成功、超时、429、5xx、认证失败和非法 JSON。

### API-3：控制台 API UI

- 加入预设列表；
- 加入新增、编辑、删除和复制；
- 加入连接测试；
- 加入主 API / 备用 API 路由；
- 加入桥接来源状态。

验收：所有表单操作可在本地模拟环境完成，不调用真实 API。

### API-4：运行流程接入

- 世界演变引擎改用统一 API 客户端；
- 将响应接入 operations 校验；
- 接入 `baseRevision` 冲突检测；
- 保证失败不提交 revision；
- 保证成功后才触发世界书投影。

验收：模拟 API 下完成一整轮“读取—调用—校验—提交—投影”。

### API-5：兼容与迁移

- 读取旧版工作流助手桥接；
- 迁移旧的 `apiPresetName`；
- 明确内置 API 优先级；
- 提供恢复旧路由的选项；
- 验证 alpha.11 数据不会丢失。

验收：旧配置、仅桥接配置、仅内置配置和双来源配置均能正确运行。

### API-6：真机安全验收

- 先导入但保持插件关闭；
- 检查 Key 脱敏显示；
- 使用低额度测试预设进行一次手动连接测试；
- 再测试一次模拟世界演变；
- 最后才决定是否开启自动触发。

验收时不得删除聊天、数据库或旧脚本；若失败，先关闭新路由并恢复旧版控制台。

## 9. 测试矩阵

| 场景 | 预期 |
| --- | --- |
| 只有内置主 API | 正常调用 |
| 内置主 API 失败、备用成功 | 自动切备用 |
| 内置主 API 认证失败 | 不盲目切换，明确提示 |
| 只有工作流助手桥接 | 兼容运行 |
| 内置与桥接同时存在 | 按路由优先级运行 |
| 没有任何 API | 不运行，提示配置 |
| API 成功、operations 非法 | 不提交 revision |
| API 成功、baseRevision 冲突 | 不提交，要求重建 |
| 数据库提交成功、世界书失败 | 保留待投影状态 |
| 删除旧楼层后重建 | API 不重复调用历史已提交结果 |

## 10. 版本与导入策略

新版本建议使用：

```text
A0.1.0-alpha.12
```

发布时同时提供：

1. 控制台独立测试导入包；
2. 控制台 + 世界演变数据库合并导入包；
3. 工作流助手旧版兼容导入包；
4. 固定 commit CDN 地址；
5. 不使用仅依赖 `@main` 的缓存不稳定地址。

alpha.12 默认：

- 插件关闭；
- 自动触发关闭；
- 不自动调用真实 API；
- 仅允许打开页面、保存配置和运行模拟测试。

## 11. 明确不做的事情

- 不把世界演变数据库改成 MVU；
- 不把 API Key 写进世界书；
- 不把 API Key 写进楼层记录；
- 不强制删除工作流助手；
- 不直接修改 shujuku 的业务表；
- 不在没有用户确认时开启自动演变；
- 不在测试阶段消耗真实 API 额度。

## 12. 完成标准

满足以下条件后，才认为内置 API 版本可以进入真机验收：

- 控制台可以独立保存并读取 API 预设；
- 主 API 和备用 API 路由可配置；
- 工作流助手桥接仍兼容；
- Key 不出现在 UI 日志、数据库和世界书；
- 模拟测试覆盖主要失败路径；
- `pnpm build`、ESLint 和现有测试通过；
- 真实世界演变仍遵守 revision 事务和世界书投影流程；
- alpha.12 导入包默认关闭并带明确版本号。
