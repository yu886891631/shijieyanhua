世界演变控制台总说明书
适用版本：世界演变控制台 A0.1.0-alpha.16（数据库格式 A0.1.0-alpha.11）

这份说明书尽量用日常说法介绍控制台。平常使用时，不需要理解 JSON、revision、operations 等技术细节；如果不确定某个按钮会不会改数据，先不要点，查本说明书对应章节。

一、它是做什么的

简单说，世界演变负责记录“主角视线之外的世界后来发生了什么”：例如 NPC 自己采取行动、组织发生变化、社会或环境变化，以及这些事情带来的事件和后续计划。

大致流程如下：

剧情楼层完成
    ↓
读取本轮消息、可用的 MVU/前置工作流摘要，以及当前聊天已有的世界资料
    ↓
按候选角色和数量上限，请已配置的 AI 生成一组受格式限制的变更
    ↓
本地检查变更，再保存到“当前聊天”的世界演变数据库
    ↓
若开启自动同步，把已保存的内容投影到当前角色卡的主世界书

数据库是这套功能的正式资料来源；角色卡世界书里的 WorldEvolution 条目是供酒馆按需读取的副本。它们不是同一份东西：数据库保存世界演变记录，世界书负责让需要相关资料的剧情能够读到投影内容。

这不是在改剧情正文，也不是直接改 MVU 变量。AI 给出的变更须通过本地校验，才会进入世界演变数据库。

二、最重要的安全区别

1. “模拟连接测试”
   这是本地假响应，不会访问网络、不验证真实 API Key/网址/模型，也不会产生 API 费用。它只能说明页面本地的模拟流程能走通，不能证明真实 API 已经连通。

2. “手动运行一轮”“重试最近失败楼层”
   这两项会调用配置好的真实 API，可能产生费用；结果通过校验后会写入当前聊天的世界演变数据库。页面会再次弹出确认。未准备好付费或不想改数据时，按“取消”，不要继续。

3. 自动触发
   插件启用且自动触发开启并保存后，工作流成功完成时会排队处理，等楼层内容稳定后再运行。自动失败重试也可能再次调用真实 API、增加费用。

4. 世界书同步/重建
   这一步本身不调用 AI、不产生模型费用，但会修改当前角色卡“主世界书”中由世界演变管理的条目。它与数据库提交分开：数据库已保存但世界书同步失败时，数据库不会自动回滚。

5. 数据库编辑
   世界资料页里的新增、编辑、删除不是预览或草稿，会立即修改当前聊天的数据库并留下版本记录。若自动同步开着，手动修改后也可能同步到角色卡主世界书。

三、打开后先看哪里

左侧显示当前聊天、页面入口、最近运行状态和版本号。先确认“当前聊天”是你准备操作的聊天。世界演变数据库按聊天区分；角色卡主世界书则属于角色卡，可能被这张角色卡的多个聊天共用。

总览页是状态面板，主要看：
- API 路由是否准备好；
- 插件是否开启、当前是手动还是自动；
- 世界书投影是否正常；
- 当前资料、楼层处理和投影的大致数量；
- 最近一次楼层运行结果。

总览上的“重新读取”只是刷新显示，不会调用 AI 或修改记录。

右上角的“数据版本 r数字”叫 revision，可以理解为当前聊天数据库的变更序号。它不是软件版本，也不是楼层编号。

四、每个页面是做什么的

【1. 总览】
只查看当前状态和最近活动。通常从这里判断下一步该去 API 配置、演变运行，还是世界书投影。查看和刷新不会改资料。

【2. 世界资料】
查看和维护当前聊天的七类记录：
- NPC：人物；
- 组织：团体、势力或机构；
- 地点：场所；
- 社会：群体、风俗或社会结构；
- 环境：世界环境、局势或条件；
- 事件：已发生的事；
- 计划：尚待发生或推进中的事。

搜索和切换分类是查看操作。新增、编辑、删除会直接写入数据库；删除前会要求确认。字段 JSON 是给每条记录填写额外资料的高级区域，普通使用者不需要随意改它；不要把 id、key、chatKey、table 或 revision 填进去。

“提供范围”控制资料的可见范围：
- 后台：作为世界演变内部资料，不等于主角已知；
- 提供给 AI：可作为 AI 处理/读取的资料；不自动表示主角知道；
- 主角已知：标记为主角已经知道；
- 已公开：标记为已公开的信息。

如果只是想让 NPC 在后台行动，不确定该选什么时，先保留原值或选“后台”，不要把秘密误设成“主角已知”。

【3. 楼层记录】
查看每个剧情楼层有没有排队、成功、失败、跳过或重试，以及它影响了哪些资料和版本。这里的楼层运行记录不是聊天正文本身。

“检查点”是数据库某一时刻的备份点，用来帮助之后重建；创建检查点会写入数据库记录。

“按楼层重放/跳过该楼层”会用已有操作重新计算数据库，并让受影响的版本标记为过期；它不会删除聊天楼层，也不会重新调用 AI，但会改变当前数据库结果。没确认影响前不要操作。

【4. 世界书投影】
检查世界演变数据库与当前角色卡主世界书中的托管条目是否一致。

- 重新检查：只查看差异，不修改世界书；
- 同步并修复差异：确认后补上缺少内容、更新不一致内容，并清理重复或孤儿的世界演变托管条目；
- 完整重建：先删除可识别的世界演变托管条目，再根据当前聊天数据库重新生成。

普通用户条目、shujuku 条目和其他没有世界演变托管标记的插件条目不属于清理目标。但非常旧的世界演变条目可能没有聊天归属标记，系统无法确认它属于哪个聊天，修复或重建时可能把它一起清理。操作前先导出数据库备份并仔细看确认框；不确定就取消。

【5. API 配置】
这里设置 AI 服务的连接资料和调用顺序。

- 预设名称：给这套连接起个容易认的名字；
- 协议：通常选“OpenAI 兼容”，只有服务商明确要求时才选自定义；
- Endpoint：服务商提供的完整 API 接口地址；
- API Key：服务商给你的密钥，不要发到聊天、截图或公开仓库；
- 模型：服务商要求的模型名，照服务商的写法填写；
- 超时：最多等服务响应多久；
- 重试次数：单次连接失败时额外尝试几次，次数越多也可能增加请求；
- 允许作为内置路由：不勾选就不能作为本插件的内置调用来源。

保存预设只保存连接配置，不代表已经调用真实服务。API Key 不写入世界书，也不包含在数据库备份中。

建立预设后还要在“主 API”中选它，再点“保存路由”；只创建预设而没有选作主路由，运行时仍可能显示未准备好。备用 API 是主路由失败后按顺序尝试的其他服务，刚开始可以不设置。

“优先使用内置 API”和“工作流助手兼容桥接”属于高级路由选择；如果你已在本页配置自己的 API，初次使用可先保留默认值。桥接旁显示“已检测到”只表示读到了工作流助手配置，不表示 Key 一定正确或服务已通过验证。

本页“模拟连接测试”不会真的连到 Endpoint。想验证实际账号/密钥，必须发起真实运行请求；那可能扣费并修改数据库，请先备份并读完“手动运行”说明。

【6. 自动演变】
这里控制什么时候运行、处理多少候选对象，以及是否自动写角色卡世界书。

- 插件启用：允许本插件监听并执行。关闭时不会执行世界演变；
- 自动触发：配合“插件启用”开启后，才会在前置工作流完成、楼层稳定后自动排队；
- 每轮最多 NPC/其他对象：限制一轮最多处理多少人和其他对象；数字越大，输入和可能的费用也可能越多；
- 手动候选 NPC：可写角色全名，多个名字用逗号或顿号隔开；这是候选提示，不保证每轮都会处理；
- 失败重试次数/间隔：控制失败后的再次尝试；自动重试可能多次请求 API；
- 楼层稳定轮询/连续稳定次数：等待正在生成的楼层不再变化，通常保留默认值即可；
- 自动同步世界书：数据库提交后是否自动更新当前角色卡主世界书中的世界演变条目。

改开关和数字后要点“保存设置”。手动运行会先保存当前设置，再调用真实 API。它会处理当前/最新可用楼层，不是单纯的预览；运行前会弹出费用和写库确认。失败重试同样会重新调用真实 API。

【7. 填表提示词】
这是多消息提示词的草稿编辑器，可导入、排序、启停、编辑和导出提示词 JSON。

重要：alpha.16 里这个页面仍是独立草稿区，保存只把草稿写到世界演变脚本设置中，不会放进聊天数据库，也不会参与真实 AI 运行。导入文件或载入样例只会替换编辑区；点“保存草稿”后才保存草稿，但即使保存了也不代表已接入实际运行。暂时可以只查看，不要把它当成决定真实演变行为的主设置。

【8. 备份与迁移】
- 导出数据库 JSON：下载当前聊天的世界演变数据库备份。包含资料表、楼层运行、版本操作、检查点和投影账本；不包含角色卡世界书正文、API Key 或提示词草稿。建议任何真实运行和危险操作前先导出；
- 选择数据库备份：先预览，确认后会整库替换当前聊天数据库，不是合并或追加。普通导入不会改世界书；导入后如需同步，需要另到投影页处理；
- 旧版备份迁移：先预检再确认。只在确实要迁移旧版本资料时使用；
- 清空当前聊天数据库：危险操作，只删除当前聊天的本地世界演变数据库，不删除聊天正文，也不删除角色卡世界书条目。清空后世界书可能留下孤儿条目，且数据库清空不能靠普通撤销恢复。除非已导出备份并明确要重置，否则不要点。

【9. 外观与显示】
选择主题和 100%、110%、125% 界面缩放。只改变控制台的显示，不改变世界资料、API 或酒馆预设；设置保存在本机浏览器，不随聊天切换重置。

五、第一次使用建议按这个顺序

第 1 步：确认当前聊天和角色卡正确。先只看总览、世界资料、楼层记录，不做新增或删除。

第 2 步：到“备份与迁移”导出一份当前聊天数据库备份。保存到你自己找得到的地方。导出的是数据库，不是 API Key，也不是世界书正文。

第 3 步：到“API 配置”填写服务商给你的 Endpoint、Key 和模型，保存预设；再选为主 API，保存路由。不要把 Key 截图或贴给别人。

第 4 步：可点“模拟连接测试”熟悉界面，但不要把“成功”理解成真实联网验证。此操作不扣费。

第 5 步：在“自动演变”里先保持自动触发关闭。如果暂时只想看界面，也保持插件关闭。确认自动同步世界书是否开启；若你暂时不想改角色卡世界书，就先关闭它并保存。

第 6 步：只有当你准备好进行一次可能收费、会写入当前聊天数据库的真实运行时，才启用插件并选择“手动运行一轮”。确认框出来后再决定是否继续。运行后到“楼层记录”和“世界资料”检查结果；不满意先停下，不要连续重试。

第 7 步：确认数据库结果正确后，再决定是否开启自动触发和世界书自动同步。自动触发不是无成本开关：之后符合条件的剧情楼层会自动发起 API 请求。

说明：alpha.16 测试导入包中的初始开关声明为关闭自动运行/插件，并关闭自动世界书同步；但如果酒馆保留了此前脚本的本地设置，实际开关可能沿用旧值。请以你当前页面里看到的开关为准。

六、常见词语翻译

- 当前聊天数据库：这张聊天专属的世界演变资料库；换聊天会读取另一份资料。
- 角色卡主世界书 / primary：当前角色卡指定的主要世界书；投影目标由酒馆当前角色卡决定。
- 投影：把数据库中适合供剧情读取的资料复制/整理成世界书条目，不是数据库本身。
- revision / 数据版本：每次数据库变更的编号，用于审计和重建。
- operations：AI 提交的“新增/修改/追加/更新状态”等操作清单；不需要手工填写。
- 候选对象：本轮可能需要演变的角色或其他世界对象，不代表它们一定会被选中。
- 工作流助手桥接：尝试复用工作流助手的 API 配置来源；是可选兼容方式，不是世界演变本身。
- 检查点：数据库某一时刻的恢复参考，不是聊天记录存档。
- 孤儿条目：世界书里还存在、但当前聊天数据库已经没有对应资料的世界演变托管条目。

七、当前版本状态与提醒

alpha.16 已有控制台页面、数据库查看/编辑、API 配置与路由、手动和自动运行入口、事务保存、世界书投影、备份迁移等实现。之前做过本地页面和布局检查，但“模拟连接测试”不是实际 API 测试；真实 API 在你的酒馆里完整跑一轮、确认资料和世界书结果，仍需要你在做好备份、确认可能费用后决定是否验收。

JSON 中若看到 world_evolution_api_test_mode: local-simulation-only，它只是测试包的标记信息，不会把真实世界演变请求自动变成模拟请求。真正的边界是：API 页的“模拟连接测试”走本地假响应；“手动运行”、自动触发和失败重试会走已配置的真实路由。

拿不准时的安全原则：先只读查看；先导出备份；不要点“手动运行/重试”；不要打开自动触发；不要点“完整重建/清空/确认替换数据库”。
