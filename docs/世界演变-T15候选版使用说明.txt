世界演变 A0.1.0-alpha.17-T15.1 候选版使用说明
日期：2026-10-09

先说清楚
这是可以操作的“隔离功能测试版”，不是正式游戏运行版。
可以填写表格、调整结构、运行真实 SQLite 校验、模拟宏观和微观流程、保存/恢复本地测试资料、预览模拟世界书。
它不会读取你的聊天，不会调用真实 API，不会修改角色卡世界书。
真实 API、酒馆存档、剧情/前置事件与角色卡世界书的最后接线和验收仍未完成。
不用在这份候选包中填写真实 API Key；API 页只检查编辑器，用假 Key 即可。

一、怎么导入
1. 导入“酒馆助手脚本-世界演变-A0.1.0-alpha.17-T15.1-隔离功能候选版.json”。
2. 这是酒馆助手的脚本 JSON，不是正则 JSON，不是表格模板或工作区存档。
3. 默认关闭；开启后从魔法棒菜单的“世界演变 · alpha.17-T15.1 · 隔离测试”或脚本按钮打开。
4. 只导入这一个包，不要拆成多个脚本。包内已经有固定的代码和 SQLite/WASM，不依赖未上传的 Git 链接。
5. 原 alpha.16 不要删除。建议测试时先停用旧世界演变脚本，减少入口混淆；此包不会迁移或删除旧数据。

二、最简单的填写测试
1. 世界资料 → 数据填写 → NPC → 新增 NPC。
2. 输入角色全名。其它字段可按你的需要填写，默认值可以先保持。
3. 点击“加入暂存修改”。这一步还没有保存。
4. 点击“校验并预览差异”。会真正运行包内的 SQLite，核对字段类型、引用、权限和修改范围。
5. 看前后差异，勾选仅保存到独立模拟存档，然后保存。
6. 保存成功后，NPC 表和楼层记录应显示同一条记录和版本。
7. 宏观世界的社会、环境、地点也是同样填写方法；微观世界还包括组织、计划和事件。

三、结构参数和 DIY
世界资料 → 结构与参数，可以增加自定义表、字段、改显示名、频率、预算、上下文、权限和导出方式。
修改先预检，再查看迁移影响、确认、保存。资料填写草稿与结构草稿不能同时混写。
“保存为新世界默认模板”只修改此隔离工作区的独立默认模板，不会替换已有酒馆世界。
表名只是显示；程序用稳定表 ID、行 ID 定位，不会把同名角色合并。

四、模拟演算
自动演变页中先采用本地剧情，再明确确认并“启用模拟路由”。
启用路由会保存当前测试模板的路由变化，不会发送 API。
之后可点击手动运行整轮：先宏观，后微观，最后统一校验和保存。
默认假响应是“没有变化”的 SQL，因此不会凭剧情自动编出行动或新 NPC。它是用来检查流程和限制的，不是实际 AI 生成。
默认请求上限为五次，具体需要几次由到期表、候选和新增权限决定。超过时要由你调整预算或表频率；程序不会偷偷增加额度。
此包没有接真实酒馆完成事件，自动触发开关不可开启。
失败不等于保存成功。显示保存结果待核对时先查询，不要重新生成。

五、世界书投影
先保存资料，再到世界书投影点“检查与预览”。
你可以看到 WorldEvolution-NPC-角色名等条目，确认后同步到“本地模拟角色卡世界书”。
它不是真实角色卡的世界书，不会影响主 AI。
模拟书不包含在完整工作区文件里，重载后重新检查和同步即可；正式世界资料仍以存档为准。

六、什么叫“保存”
本候选的保存是写入当前脚本内存中的测试账本，并读回确认。
收起窗口会保留本次内存；停用脚本、重载、刷新酒馆或关闭酒馆会丢掉没有导出到磁盘的内容，包括已在内存保存的资料。
因此退出前请点顶部“导出完整隔离工作区”，确认下载文件确实在磁盘。
注意：本轮内置浏览器只确认了导出请求提示，未确认磁盘下载结果。先用虚构资料核对下载文件及重开；没确认前不要在这里录入需要长期保留的重要资料。
下次用顶部“打开隔离工作区文件”，可恢复资料、结构、历史、已保存提示词和外观。
未保存填写草稿、运行中的私有结果、API 配置/Key不会导出或恢复。
“备份与迁移”页导出的世界备份与顶部的完整工作区文件不是同一种格式，不能混用。
损坏文件或身份不符合的文件会拒绝，原工作区保留。不要手改文件指纹。

七、其它页面
总览：查看当前资料和准备情况，不会开始演算。
楼层记录：查看保存链。恢复所选历史会追加新版本，旧历史保留；不是把模型再调用一次。
填表提示词：先保存草稿，需要正式采用时再启用。工作区导出同时保留已保存草稿与启用版本。
备份与迁移：在隔离世界内预览和确认范围；不会自动读取你的实际旧库。
外观与显示：淡绿、奶油、淡粉、深色及字号/密度。外观可随完整工作区文件保留。
API 配置：复用原编辑器，但这里的配置只存本次内存，不供此包演算使用。请勿把它当真实游戏 API 设置入口。

八、怎么回退
先导出需要保留的隔离资料，再停用此候选脚本；原 alpha.16 文件与旧数据未被它修改。
不要把此隔离文件直接塞入旧版数据库。真实旧数据迁移必须另外确认范围和备份后进行。

九、下一步还缺什么
缺真实酒馆存档/删楼恢复接线、真实模型请求接线、MVU/数据库本轮完成事件，以及角色卡主世界书接线与真机验收。
所以现在可以试“填写、DIY、保存/恢复和模拟流程”，但不能声称已经能正式自动演变整个游戏。
没有推送 GitHub，也没有需要你照填的未上传 CDN 链接。
