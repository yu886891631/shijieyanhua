# T8：宏观阶段与必要运行控制

日期：2026-10-08

状态：本地模拟实现完成。不是 alpha.16 更新包，也不代表真实酒馆端到端验收完成。

## 1. 本次完成了什么

T7 只负责准备、冻结、预览与假传输；T8 接上真正的宏观执行协调：

本轮触发 → 排队/去重 → 分别等待必要前置 → 冻结结果 → 按序模拟宏观表 → 解析 SQL JSON →
T3 私有 SQLite 与结果校验 → 宏观整体暂存 → 交给后续 T9。

宏观不会单独调用 T4 保存服务，也不会单独提高 revision、推进世界时间、成功处理轮次或后台轮转位置。正式世界一直保留上一次已保存状态；某张表失败，前面成功的宏观表也不会成为可用的半份世界。

## 2. 输入、前置和触发所有权

- 开始时复制正式资料、模板、启用提示词、API 配置、世界时间、选择规则和预算。仅接受明确的 sandbox 聊天身份。
- 排队和等待期间，消息/chat/swipe/世界/分支/剧情/时间及必要来源声明不能换；前置状态和选定来源结果可以由模拟适配器补齐。
- 启用的必要来源分别校验本轮身份、来源提交、结果指纹及要求的保存证明。MVU 成功不能掩盖数据库失败；旧 swipe 的信号不能放行新一轮。
- 必要来源明确停用或按频率跳过，需要本轮匹配证据与原因；不会读取它的旧结果。可选失败来源不阻断，但其资料不能进入模型输入。
- 前置失败、无法验证、未安装却被声明为必要、成功但未满足落盘证明，都会停止。等待超时是失败，不是成功。
- 全部必要前置就绪后冻结整份来源结果；此后任何结果、消息或正式世界变化使本轮失效。
- 共用 `createT8Queue`
  的入口串行执行，以聊天、世界/分支、消息/swipe 与输入指纹去重，不以 runId 去重。终态记录也保留，防止重复信号自动重发。
- 每一次模拟发送，包括客户端重试，先检查触发所有权和有效输入，再消费统一额度。所有权撤销后不发送下一次。

重要限制：这是显式传入、共用同一个对象的内存队列和测试证据，不是宿主跨 iframe/脚本锁、可信身份认证或持久运行账本。两个完全独立的队列不能保证互斥；真实前置证据与旧入口接管仍由 T10 接入和验收，当前没有注册真实监听器。

## 3. 宏观执行与后批最新条件

- 保留 T7 编译出的表顺序、候选行身份、路由、规则、权限和额度；宏观候选不因前批的结果扩张。
- 首版每表一个请求，有序处理；同路由多表合批是后续优化，不声称已经实现。
- 模型只能返回合法 JSON：`{"sql":"受限 SQL","parameters":[]}`。禁止代码围栏、额外字段、缺字段、错误参数类型或过大响应。
- 真正的 T3 SQLite 执行仍是授权和类型/引用校验者。冻结的 read/write policy 不来自模型，不能通过提示词或 SQL 申请越权。
- 每份结果再次通过 `normalizeT3Result` 与准确的冻结请求比对，拒绝伪造身份、元数据、微观/隐藏字段变化及不一致日志。
- 后一张宏观表的 messages 从已校验的私有世界重新组装；例如市场表能够读取本轮刚更新的环境风险，而不是旧风险。
- 已完成表不重新分配，允许的删除也不会让其已删除行被后批再次处理。微观表此阶段不可写。
- 不到频率、明确关闭或无可操作对象的表继承正式状态，不制造空宏观模型调用。
- 缺失 API 或必要上下文不完整是阻断，不显示成“无变化成功”。跳过、阻断理由可以查看。
- 不自动种示例记录；允许的模型 INSERT 使用 T3 稳定分配 ID、新增配额与完整图校验。

自然语言“是否符合剧情”不是 SQL 能完全证明的事实。代码能校验类型、引用、授权和明确预算；不会把结构合法误称为叙事事实已验证。

## 4. 预算、取消和过期

- 整轮发送额度由冻结的模板默认与 hardLimits 限制，客户端重试与每表发送共用计数；表级额度也独立检查。
- 后续微观沿用同一个 T7 私有运行，不能重建计数器来重新获得完整发送额度。
- 宏观完成时把校验结果中的实际目标行数/新增数交接，未使用的预留对象、新增额度可以供微观使用。UPDATE 即使写相同值，也可能算一条实际操作目标；无变化 SELECT 为零。成功标记、轮转建议仍未提交。
- 前置等待、模拟 HTTP、SQL 和下一张表都有取消检查。HTTP 包括客户端自身的请求超时；SQL 传递 AbortSignal 并设置独立超时。
- 即使坏掉的模拟适配器忽略取消，其迟到结果也被隔离；真正终止同步 SQLite 要由 T3 Worker
  runner 实现，普通同步本地 executor 只能保证不接受迟到结果。
- 明确撤销运行权限、正式资料/模板或消息/分支变化，都会阻断后续发送和交接。普通 API 配置或未启用规则草稿不改变本轮冻结配置。
- 失败、取消或过期后清除可用 handoff 和有效差异；已完成的批次指纹只作为诊断，不是保存成功。
- 已模拟发送但整轮终止时显示结果不可继续使用，并解释真实请求未来可能存在“结果/费用未知”。本阶段模拟没有网络或费用。

不做自动整轮重试、不自动换 API 或备用路由。同一触发的失败记录继续去重；本阶段没有强制重跑/续跑按钮。刷新丢失本地暂存，重新创建运行时不会自动发模型请求。T9/T10 再定有效续跑、持久运行记录和真实费用边界。队列最多 64 条（测试可指定 1–256）；满后阻断，不淘汰旧去重记录以偷偷放行重复请求。

## 5. UI 与数据交接

`T8WorldWorkbench.vue` 在共享的 T4–T7 工作台旁增加“宏观演算”页签，切页保留内存组件。

该页可以：

- 开始本地模拟、查看排队/等待/演算/暂存/失败/取消/过期状态。
- 查看每个必要来源、正式/模板/提示词版本、世界时间与发送额度。
- 查看宏观表顺序、路由、实际 messages、请求及执行前后指纹、变化行和新增数。
- 查看可见字段的前后差异、跳过理由、错误类别和中文说明。
- 取消本轮、检查暂存是否仍有效；无保存世界或上传世界书的旁路按钮。

淡绿底、粉红阻断提示、scoped 样式和安全文本插值；恶意 HTML 仅显示文本，API
Key、认证头和端点不进入预览。初始状态不会假称结果已经暂存；完成后明确标记“宏观结果暂存中，尚未正式保存”。

`handoff()`
是给 T9 的可信内部接口，交接前再校验有效性：同一个私有运行、基准世界、最新宏观、冻结输入、固定 SQL 批次与实际用量。它不是 Vue 展示接口，不能把含隐藏字段的全世界直接放进页面或备份。T9 每次发送及最终提交仍须复查所有权/输入，并使用 T4 一次保存整轮。

`createT8Sandbox` 复用已有正式状态/模板/提示词和 SQL
executor，不再建另一份正式世界。起始的未保存资料、结构、规则或未确认 T4 操作阻止冻结；运行中普通未启用草稿不会误使旧启用规则过期。本地配置、队列、日志与暂存仍只是内存，刷新会丢失；本次没有提供真实聊天持久化。
