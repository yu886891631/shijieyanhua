# H2：自动运行接线、触发所有权与去重

日期：2026-10-10。

对应用户请求：“开始第 2 项：自动运行接线、触发所有权与去重”。沿用 H1 边界：不调用收费 API，不读写实际聊天/世界书，不覆盖当前测试包，不增加服务端，不提交或推送 Git。

## 1. 结果与发布边界

新增来源通知驱动的自动检查器、同页触发账本，以及逐回复重新捕获原生会话的生命周期组合。手动/自动仍进入同一个 T11 控制器、T9 整轮执行器、T8 队列与 T4/T10 提交服务；没有第二套模型执行器、预算或保存流程。

接线代码已在假酒馆、假网络与模拟存档中验证。没有在用户实际酒馆调用这些工厂；H1 数据库补丁未安装，新工厂未接现有隔离导入入口。当前 alpha.16 和固定 alpha.17-T15.1 测试包不因此成为正式运行版。

九页布局保留。仅在真实会话的原有自动演变区补接线状态，并将 API 授权说明改为“手动及已开启的自动运行”，避免用户误以为勾选后只有再次点击按钮才可能请求。

## 2. 代码连接

- `t15-source-signals.ts`：可清理的订阅、实时目标与分类唤醒；候选重复应用幂等，但仍检查当前性。旧数据库缺整轮协议时不放行。
- `t15-db-completion-adapter.ts`：先更新候选，再通知订阅者。普通更新不能完成关口。
- `t15-automatic.ts`：本回复的来源 → 独立保存复核 → T11 自动入口。忙碌或有草稿时不抢占编辑器。
- `t15-trigger-ownership.ts`：父窗口共享单活动入口及本页触发账本；手动/自动共用身份，关闭或取消不清掉已领取记录。
- `t11-controller.ts`：预检通过后、`round.start()` 前同步领取；同轮续跑另设能力；跟踪派发/续跑收口，供交接等待。
- `t10-session.ts`、`t15-host-workspace.ts`：初次执行须持有效领取能力；未领取时连预算保存也不执行。同实例续跑仍依赖原队列、暂存与剩余额度。
- `t15-automatic-lifecycle.ts`：每个新回复重新捕获会话；收口旧实例后接管新实例。有草稿、暂停或未知保存结果时保留页面并停下。
- `t15-native-workspace.ts`：显式组合 API 配置、来源、所有权与原有工作台。逐回复工厂要求已有初始化存档，不自动种演示角色、初始化空库或迁移旧库。
- `T15HostWorkspace.vue`：仅接线状态及准确授权说明，没有重做 UI。

## 3. 自动契约

1. 默认关闭。构造、打开页面、勾选自动/API 授权、查看或刷新都不回放旧完成通知，不请求模型。
2. 新通知只唤醒检查。必要 MVU/数据库候选须匹配当前聊天、原消息对象、swipe、正文及事件版本；无论哪侧先完成，都等另一侧。
3. 数据库失败、取消、缺协议或无效终态不启动。明确停用/频率无任务按 H1 终态处理，不据超时猜测跳过。
4. 候选通过后独立读取保存结果。默认最多 8 次、间隔 250ms 的读回；定时器只查证据，不把时间经过当完成。用完仍不发模型，等新保存通知或人工处理。
5. 普通更新可唤醒读回但不能生产完成候选。无前置来源的路径，只接受明确 assistant 完成事件，再验证当前已保存有效回复；任意表格变化不能开始。
6. 保存确认后进入 T11 唯一整轮入口，复用宏观 → 微观 → 整批校验 → 一次保存。每次发送仍检查来源、有效领取、预算保存与 API 授权。
7. 关闭自动、撤销 API、来源失效或输入变动会停止领取并取消所属运行；迟到返回不能进入下一阶段/提交。
8. SQL 失败、取消、未知结果和反复通知不自动重跑。人工同轮续跑须原实例、原 T9 队列、原暂存与剩余额度，并重新激活本轮领取；不重跑宏观或重置预算。

## 4. 所有权与限制

触发键由存档 scope（聊天/世界/分支）及稳定锚点（messageId、swipeId、输入指纹）组成，不用楼层数字或姓名冒充身份。

- 同一父窗口只允许一个新触发所有者。各会话及手动/自动共享账本，同轮最多领取一次。
- 默认保留本页最多 256 个身份；满额停止，不淘汰旧记录后自动重发。
- 完成/失败记录继续保留；本页关闭后重开同轮也不能重新领取。正式成功另由 T10 持久记录跨刷新去重。
- 关闭撤权，已有派发句柄收口前不移交租约。取消不证明服务商已停止计算或不收费。
- 原生工厂在取得权限和后续发送检查时，只读核对全局、预设、角色卡脚本清单。只排除精确当前脚本 ID；其他启用的已知世界演变入口会阻断，不自动关闭它。
- 清单不可读/不支持时阻断。名称、已知路径/设置标记不是任意代码行为证明；无法识别所有改写脚本或外部程序。仍须明确停用旧写入脚本，不只是关自动开关。
- 这是单活动页面、前置串行保存的纯前端兼容方式，不是服务端 CAS，不是跨标签页/设备/全部插件的锁。

## 5. 逐回复交接

生命周期须先明确授权，再等新通知；刷新/重载不自动恢复收费权限。新目标重新独立捕获，关闭并等旧控制器派发/续跑收口，再建新会话。`onWorkspace`
由嵌入方复用现有面板，不擅自覆盖已有容器。

旧页面的资料/结构/提示词草稿、历史编辑、暂停暂存、世界书/备份操作或未知保存结果阻止交接并保留页面。处理后须明确重新启用，不丢草稿或自动重跑。

聊天/角色切换（包括 A→B→A）、停止生成或 API 配置改变撤销自动授权；旧候选不能重新开启。配置比较值仅存内存，不进日志、运行记录、世界书或备份；发送仍复核目标/配置。

pagehide/close 清理观察、定时器和会话。原生来源工厂后续注册失败时，也注销已接数据库观察器及表更新回调，避免隐形监听。
