## 1. 最终要交付什么

交付一个独立的世界演变插件，打开后就是统一的居中工作台。用户可以在里面填写资料、修改表格结构、配置演变规则和 API、查看演变结果、恢复历史，以及管理角色卡世界书投影。

完整范围包括：

1. 真实 SQLite 内核与受限制的 SQL 更新。
2. 默认宏观、微观表组；社会、环境、地点、NPC、组织、计划、事件七张起始表。
3. 单元格/行编辑与用户自定义表格、字段、说明和规则。
4. 宏观、微观顺序演变，读取上轮状态，整轮一次提交。
5. 明确可预览的 AI 上下文及真正生效的填表提示词。
6. 已有 API 页面与客户端的复用、阶段/表级路由继承。
7. 随聊天保存的 JSON 快照、SQL 日志、模板历史及分支身份。
8. 无需重新调用 AI 的恢复，以及删楼、重生成、swipe 后的依赖处理。
9. 当前角色卡主世界书的精确投影、按行导出、关键词、常驻索引与秘密过滤。
10. 旧数据迁移、备份、导出、清空和回退说明。
11. 总览、世界资料、API、自动演变、提示词、楼层记录、投影、备份、外观页面的完整适配。
12. 已讨论的淡绿色普通区域、淡粉色危险区域、主题一致性和缩放适配。
13. 模拟测试、指定范围的真机验收、单入口候选导入包和用户说明书。

UI 是必做交付，不是可选附录。数据、交互、布局和状态反馈随功能一起实施，最后再做全局视觉收口。

本次不是重新设计主游戏或改写现有 MVU、SP·数据库；世界演变继续增强后台世界体验，用户可以独立启用或关闭。

## 3. 全程不变的核心规则

### 3.1 SQL、SQLite、JSON 与缓存

| 层             | 负责什么                                 | 不能绕过的边界                       |
| -------------- | ---------------------------------------- | ------------------------------------ |
| 工作台 UI      | 填写、配置、预览、状态和确认             | 编辑走统一提交服务，不直接写底层     |
| JSON 模板      | 表、列、规则、上下文、预算、导出配置     | 模板不是实际世界数据；版本与世界绑定 |
| SQL            | 描述允许的查询和业务更新                 | AI 不操作宿主、系统历史或其他插件    |
| SQLite         | 查询、临时执行、约束和事务检查           | 内存修改不代表聊天已经保存           |
| 聊天 JSON 存档 | 正式状态快照、提交链、模板历史和固定操作 | 生产模式唯一持久化权威               |
| IndexedDB 缓存 | 加速和可重建视图                         | 不能在宿主保存失败时独自推进世界     |
| 世界书         | 主 AI 可读取的知识投影                   | 不能反向猜补、覆盖权威世界状态       |

只允许一条正式写入链。生产环境不出现“聊天、SQLite、缓存各自宣称最新”的三套状态。

T4–T9 使用明确标记的沙盒 JSON 存档适配器作为模拟权威。沙盒有独立世界 ID 和存储范围，不读写 alpha.11 当前库，不在失败时回退到真实宿主。此模式与生产存档明确分开。

### 3.2 宏观、微观及时间

本轮宏观 = 上轮已提交宏观 + 本轮剧情/前置结果 + 相关历史影响。

本轮微观 = 上轮已提交微观 + 本轮最新宏观条件 + 本轮剧情/前置结果。

- 两阶段在同一个私有暂存世界内执行，最后只保存一个正式提交。
- 宏观阶段不单独保存、也不单独推进一次时间。
- 同一运行 ID 的重试、重复响应和恢复，不能重复行动或推进时间。
- 不变资料继承原值，不强求每表每轮变化。
- 一般先完成宏观请求再处理微观请求；微观可按预算分批，不固定逐 NPC 调用。
- 组织/事件对宏观的反馈默认进入下一轮宏观输入，不做无限往返循环。
- 剧情已确认事实是约束，后台演变不能随意改写伤亡、位置或已发生结果。
- 世界时间可使用自定义纪元，不强行按现实公历解释所有世界。

### 3.3 版本、身份和原子提交

- 表 ID、字段 ID、行 ID、世界 ID、分支 ID 和提交 ID 都使用稳定身份；显示名称可以修改。
- 冻结基准提交、模板/schema、输入、提示词、模型和参数，提交前复查是否过期。
- 普通 API 路由/模型参数修改只影响下一次新运行，本轮继续使用已冻结配置；世界数据、已启用模板、输入或分支变化使本轮结果过期。明确取消、禁用或撤销运行权限也立即使本轮失效。
- 每次更新先在临时世界执行并校验，再保存权威存档；确认成功后才切换正式视图。
- SQLite 与酒馆保存不是一个物理事务；必须用暂存、幂等提交和读回确认协调，不能声称天然跨系统 ACID。
- 保存确认丢失时先核对提交 ID，不能盲目再次应用 SQL。
- 读回确认不是互斥。T0/T10 须验证宿主原子版本检查或可靠跨实例写锁，并声明支持的并发范围；不能实现时强制可验证的单写入实例或阻断正式保存，不能只靠保存后对账承诺零覆盖。
- 完整提交后快照记录已包含的 `throughCommitId / throughSeq`
  和前后状态指纹。恢复该快照时不再执行它已包含的 SQL；增量只从截止位置之后回放，并检查每步基准与结果指纹。
- 模板默认值/种子数据只在明确初始化或迁移时应用，不能每次恢复都重新补种。
- 模板改变要有迁移计划；schema、数据和模板一起成功，或一起保持原状。

### 3.4 安全、可见性与历史

- 普通 AI 只提出允许的 INSERT/UPDATE/DELETE；查询入口与写入入口分开。
- DDL、系统表、历史、凭据、前置数据库和跨组越权写入禁止进入常规 AI 更新。
- SQL 语法、目标记录、实际影响范围、锁定、引用、数量和业务规则均由代码硬校验。
- UPDATE/DELETE 有 WHERE 不等于安全，仍需拦截全表条件和超候选修改。
- 未支持的语法失败关闭；参数绑定，标识符规范化；不只靠正则黑名单。
- 受限查询有结果和执行预算，耗时查询应能在受控执行环境中终止；具体实现由 T3 验证。
- 上下文、正文、标题、关键词和索引共用可见性策略，秘密不能从另一条路径泄露。
- 恢复使用已保存状态/固定操作，不调用 AI，不依赖当前模板、当前时间或新的随机结果。
- 删楼/改楼/重生成使依赖它的后续提交失效；恢复有效祖先，不无提示保留依赖错误事实的后续状态。
- 重放有效历史与重新让 AI 演算是两种操作，后者另有费用和授权。

### 3.5 消息锚点与共享世界书

- 自动提交绑定实际处理的助手消息及当前 swipe 的稳定身份。
- 初始化、手动编辑和模板迁移追加到当前分支末端的有效助手锚点；同一锚点可有多次有序提交。
- 历史查看只读；历史修改须明确回退或建分支。
- 无有效助手消息时世界资料是草稿，不能假称已存聊天；不自动造剧情消息或改用旧缓存作为事实源。
- 全局默认模板保存不等于当前世界初始化。
- 世界书默认写当前角色卡主世界书，只操作本插件托管范围，不覆盖整本。
- 同角色卡多聊天/分支共用一本书时，只有当前有效世界的投影可进入本次主 AI 上下文。
- T0/T1 提前核对请求级过滤能力；若只能全局激活则定义单活策略和并发限制。不能可靠隔离时明确阻断投影，不靠条目名不同来假装隔离。
- 若切换本插件投影激活标志，说明范围；不能修改用户或其他插件条目的激活状态。
- 投影任务绑定世界、分支、源提交和目标书；执行/重试前复查目标，过期任务不得重新激活旧世界。
- 主 AI 捕获上下文时必须使用同一个已验证投影版本。部分同步失败不得注入混合版本；使用请求级一致快照、版本化暂存切换或阻断本插件投影注入，具体能力须提前验证。
- 单活策略的互斥范围包含主 AI 捕获上下文期间，不仅包含世界书写入期间。首版不承诺多设备协同写入，任何支持范围之外的并发限制须明示。

## 4. 用户最终使用流程

### 首次使用

1. 导入一个世界演变脚本包，打开同一个工作台。
2. 采用默认模板，或导入自己的表格模板。
3. 在世界资料页填写/导入起始资料；也可在条件满足后由初始化流程补全允许生成的资料。
4. 配置 API；查看宏观、微观继承哪条路由。
5. 检查自动演变、数量预算和世界书配置。
6. 在指定测试聊天运行并查看变化，验收后再用于正常游戏。

### 每轮运行

```text
剧情及启用的前置阶段完成
        ↓
冻结本轮事实、旧世界和实际生效配置
        ↓
宏观生成 → 检查并应用到私有暂存世界
        ↓
微观读取最新宏观 → 生成行动与更新
        ↓
整轮校验 → 一次保存 → 正式表格刷新
        ↓
当前角色卡主世界书的受控投影
```

### 用户 DIY

进入世界资料的结构与参数子页 → 增加字段/表 → 查看旧数据迁移预览 → 保存当前聊天模板 → 预览下一次 AI 发送内容。

模板变更真正影响读取、生成、校验、展示和所选导出。保存为全局默认只影响未来采用它的世界。

## 5. 完整 UI 页面蓝图

顶层保持一个工作台与清楚的导航；表级配置集中在世界资料子页，不复制成多份互不相通的表单。

### 5.1 共用外壳与组件

- 左侧：品牌、当前聊天/分支、按用途分组的页面导航、版本与运行摘要。
- 顶部：页面标题、简短说明、当前数据版本、沙盒/实际存档标识、关闭入口。
- 主体：稳定内容宽度、统一卡片间距，侧栏与内容滚动可达；保留既有定位修复。
- 通用状态：未配置、未初始化、草稿、加载、无记录、无结果、运行中、过期、失败、恢复中、待同步。
- 通用组件：类型化字段输入、引用选择、状态徽标、预算输入、规则编辑器、差异预览、范围确认、错误定位。
- 编辑草稿跨页时提示未保存；没有更改则不反复确认。保存按钮显示具体作用范围。
- 关闭面板不等于停止后台任务；停止脚本、取消任务和关闭面板分别说明。
- 标题和操作使用易懂中文，内部 ID、SQL 和提交信息放高级详情，可复制但不占满主页面。

### 5.2 总览

内容：当前世界/分支、模板名称和版本、有效提交、宏微观表计数、最近一次运行与变化摘要。

准备检查：存档是否就绪、API 路由、前置状态、模板有效性、投影目标与隔离能力。

操作：进入世界资料、API、自动演变、错误详情；导航不偷偷启动生成。

状态：空世界引导、沙盒示例、待配置、已就绪、正在演变、提交失败、存档损坏、投影待同步。

完成标准：普通用户一眼知道现在是什么世界、有没有保存、能否运行、下一步去哪里。

### 5.3 世界资料：数据子页

- 左侧按“宏观世界”“微观世界”列出表名、记录数、锁定/停用状态。
- 主区显示当前表说明、数据版本、搜索、筛选、列显示和分页。
- 直接编辑文本、数字、枚举、布尔、时间和引用；长文本用可展开编辑区。
- 新增行、手动添加角色、编辑行、归档、受控删除、行/字段锁定。
- 引用选择显示名称和表名，底层保存稳定 ID；无目标引用给出明确错误。
- 初版支持单字段/行编辑及批量确认；批量修改仍受预算与整批校验约束。
- 编辑先成为草稿，保存时预览变化；成功后显示正式版本，失败保留草稿以便修正。
- 历史表格只读；修改过去需要回退/分支，不把历史查看当编辑当前世界。
- 高级 JSON 是补充入口，不再是普通用户唯一填写方式。

完成标准：不懂 JSON/SQL 的用户也能填写一个 NPC，并可靠保存、看到记录及修改结果。

### 5.4 世界资料：结构与参数子页

表级子页统一包含：

| 区域         | 可修改内容                                | 生效/安全要求                        |
| ------------ | ----------------------------------------- | ------------------------------------ |
| 基本结构     | 显示名、分组、排序、用途、字段列表        | 稳定身份受保护，结构变化走迁移       |
| 字段与关系   | 类型、必填、默认、范围、枚举、引用、锁定  | 输入控件、SQLite 与应用校验一致      |
| 填表规则     | 初始化、新增、更新、归档/删除条件         | 提示词规则与硬限制分开说明           |
| 演算参数     | 启用、频率、批次、对象上限、阶段继承      | 明确继承/关闭/具体值，不让用户猜负数 |
| 上下文       | 楼层范围、旧行数、字段、相关查询、预算    | 可预览，不能越过读取权限与可见性     |
| API 继承     | 使用阶段路由或允许的表级覆盖              | 仍走统一客户端，不另存一套 Key       |
| 世界书导出   | 整表/按行、标题、关键词、常驻、索引、正文 | 与全局投影页面共享同一配置           |
| 高级 SQL/DDL | 只读查询、支持的建表结构                  | 数据写入/改表须检查、预览和提交      |

保存范围：当前世界数据、当前聊天模板、全局默认模板分别表达。不能一键同时隐含改结构、运行 AI 和写世界书。

完成标准：新增业务字段或自定义表后，旧数据不被丢弃，新字段真正进入运行及导出链。

### 5.5 API 配置

- 保留独立页面与现有客户端、凭据管理和预设能力。
- 显示全局 → 宏观/微观 → 表级的继承来源与最终模型，不只显示一个模糊“已配置”。
- 允许两个阶段共用 API；不同配置也走统一错误、超时、取消和预算机制。
- “本地模拟测试”明确不验证网络或 Key；真实连接/生成测试单独标示后果。
- 运行中改配置只影响下一次新运行；本次冻结的配置可查看。
- 日志、上下文预览、模板和备份不泄露 Key；不因为 API 页面改版清空旧凭据。

完成标准：用户清楚哪条 API 用在哪个阶段，以及哪个按钮会真实访问网络。

### 5.6 自动演变与运行

- 分组显示触发条件、已启用前置阶段、频率、对象/事件/请求预算、重试和取消。
- 运行前检查展示缺失条件、选中表、上下文概况与预计请求范围。
- 阶段进度：等待前置、宏观、宏观已暂存、微观、整轮校验、保存、投影。
- 宏观已暂存不是正式保存成功，页面必须写清。
- 手动运行、自动运行、重新生成、仅恢复、仅重试投影分别命名。
- 本轮无变化给出中性结果，不假报生成失败，也不制造多余修改。
- 失败显示阶段、具体表/字段/语句、可修正原因；高级日志可展开。

完成标准：用户知道现在做到了哪步、结果是否保存、取消/重试会有什么后果。

### 5.7 填表提示词与上下文

- 全局规则、宏观规则、微观规则、表级说明有明确层级和继承关系。
- 草稿、已启用版本、本轮实际使用版本清楚区分。
- 展示实际将发送的剧情楼层、相关旧记录、最新宏观摘要、字段说明和前置输入来源。
- 可查看记录数和估算大小；能够调整范围，但不能关闭硬性保密和授权检查。
- SQL 输出协议由系统保护，不要求用户自己补全核心字段。
- 提示词导入有预览和版本，不默认覆盖正在运行的一轮。

完成标准：调整一条表级更新规则后，在下一次发送预览及模拟演变中真正生效。

### 5.8 楼层记录与历史

- 运行日志与正式提交分开：失败运行不伪装成一个世界版本。
- 列表显示消息、分支、来源、状态、宏/微观影响数量和错误。
- 详情显示前后差异、已执行 SQL、固定参数、模板版本、世界时间和提交祖先关系。
- 查看过去、恢复版本、创建分支、重新生成、清除本插件数据是不同操作。
- 删楼/重生成影响范围可预览；依赖失效的结果标记过期而非继续显示为有效。
- “恢复已保存数据”不调用 AI；“重新演算”可能调用真实 API，有明确说明。

完成标准：能看懂一次演变改变了什么，并在明确范围内恢复，而不是被技术状态码淹没。

### 5.9 世界书投影

- 显示当前角色卡主世界书、当前世界/分支和投影隔离策略。
- 表级导出规则引用同一模板配置，避免与结构页重复维护。
- 预览正文、标题、关键词、常驻索引和逐行拆分效果，包含可见性过滤后的最终结果。
- 展示应新增、更新、删除、激活/停用的托管条目及原因；区别账本与实时检查。
- 同步、检查、重试、修复、完整重建分开，范围确认不含其他插件条目。
- 同步失败保留已保存世界；重试不重新生成、不重复提交。
- 无主世界书或无法安全隔离时明确阻断，不随意换书。

完成标准：用户能预览哪些资料会被主 AI 读取，并确认只影响当前世界的本插件投影。

### 5.10 备份与迁移

- 世界数据、模板、历史审计可分别导出，默认剔除凭据。
- 导入先检查来源版本、目标世界、ID/引用、可见性、结构与历史。
- 新模板、新世界数据、旧 IndexedDB 迁移、历史恢复使用不同向导。
- 迁移预览显示映射、冲突、不能自动处理的字段与历史限制。
- 清空提示范围、备份与恢复方式，不清剧情或其他插件数据。
- 旧版回退前说明新格式不能直接被旧插件读取，提供保留新存档/导出办法。

完成标准：用户在确认前知道会改哪份资料，失败时还有完整原始数据和报告。

### 5.11 外观与显示

- 沿用现有主题和语义色 token，统一字段、表格、状态、弹窗和错误区。
- 普通/成功区域淡绿，一般警告淡琥珀，危险区域淡粉＋可读深色文字。
- 选中表、焦点、错误、禁用和锁定不能只靠颜色区分。
- 字号、密度、长文本、列宽和分页在可用范围内调整。
- 100%/110%/125% 缩放、窄工作区、长表与长名称下可达，不破坏已修复的居中定位。
- 侧栏、页头、保存区、关闭按钮及滚动末尾可访问；支持键盘焦点和错误字段定位。

完成标准：编辑密集页面仍清楚、舒服、可操作，UI 质量与功能一并验收。

结构迁移包括：增加字段、修改显示名称、变更类型/必填、移除字段、改变关系、调整表组。每种都需预检和数据映射；历史值保留在原始快照/备份中。

## 9. 逐阶段详细任务

### T0：基线、隔离与宿主可行性

目标：确定哪些已经做好、哪些必须重构，并保证后续雏形不碰现有世界。

功能任务：

- 记录源码、依赖、入口、版本、数据库格式、现有测试和已知告警。
- 只读核对 API 路由、提示词、store、engine、投影与 UI 的写入入口。
- 核对宿主消息数据合并、保存确认、读回、原子版本检查/跨实例锁、稳定身份、swipe、分支及事件能力；列出可安全支持的并发范围。
- 核对角色卡主世界书解析和请求级隔离能力，列出不能安全实现的阻断项。
- 定义独立世界 ID、沙盒存储和假 API/宿主/世界书适配器；禁止失败回退真实接口。
- 核对实际前置插件的导出形态、完成/落盘证据和触发入口；区分“支持读取”与“能证明本轮完成”，见第 15.1、15.4 节。
- 记录旧数据保留及后续备份方案，不执行真实迁移或清空。

UI 任务：登记既有页面、主题、100/110/125% 定位基线；明确沙盒/真实存档的常驻标识及错误显示。

测试：模拟 API 不联网；沙盒不访问旧库；只读检查不触发生成、保存、世界书同步或配置修改。

交付/完成标准：基线与能力报告、隔离约束、风险列表、后续模块映射；不能把没有证据的宿主保存/投影能力写成已通过。

### T1：页面结构与交互契约

目标：先决定所有页面如何连接，避免后面只塞按钮。

功能任务：

- 固定页面路由、表级子页、读写服务和运行状态模型。
- 明确数据、模板、全局默认、运行配置与历史的作用域。
- 定义初始/无锚点/沙盒/真实/运行/失败/过期/未保存等交互状态。
- 固定查看、保存、改结构、恢复、重新生成、投影的独立操作语义。
- 固定初始化和手动提交承载规则，并把宿主能力不足列为显式限制。
- 定义首次初始化向导、字段冲突处理、草稿保留范围，以及只读/禁更/隐藏/锁定的不同操作含义，见第 15.1、15.3、15.8 节。

UI 任务：各页面的区域顺序、页头、主按钮、辅助入口、空态和危险确认；实现最小导航/组件样例时仅用沙盒状态。

测试：导航与关闭可达、草稿跨页提示、作用范围文案一致；不能从只读入口误触发写入。

交付/完成标准：完整页面蓝图、交互/状态表和共用组件清单。普通用户能区分“看资料”“保存世界”“改模板”“调用 AI”。

### T2：模板协议与默认表组

目标：让所有数据功能和 UI 使用同一份可版本化模板。

功能任务：

- 定义稳定表/字段身份、组、用途、关系、visibility 和系统保护字段。
- 定义字段类型、默认/必填/范围、世界时间表达和前端控件映射。
- 定义初始化/新增/更新/归档/删除规则、锁定、频率与预算继承。
- 定义上下文、API 来源和世界书导出配置的统一数据结构。
- 编写七张默认表和环境＋NPC 最小模板及固定示例数据。
- 定义模板/schema/存档版本和不兼容变更识别，不在恢复时自动补种数据。
- 定稿字段物理编码与空值/精度规范、结构唯一来源、表用途和读写权限矩阵、频率计数与候选身份协议，见第 15.2–15.6 节。

UI 任务：显示字段说明、默认模板预览、继承/关闭/具体数值文案；字段可编辑性由模板决定。

测试：模板序列化往返、无效类型/重名映射/悬空关系、默认值与已存在数据不互相覆盖。

交付/完成标准：规范化模板及验证器、默认表样例、输入控件映射；不是只有列名没有业务规则的空模板。

### T3：SQLite 内核与受限 SQL

目标：建立真正的 SQL 执行和查询能力。

功能任务：

- 接入并锁定 sql.js，验证单文件内联 WASM 或等效可靠加载方式，记录包体与启动成本。
- 初始化、卸载、模板建表、参数查询、JSON 灌入和严格导出。
- 实现允许的 SQL 子集、表/列/记录授权、阶段范围和稳定 ID 分配。
- UPDATE/DELETE 目标条件与实际影响范围硬检查；拒绝 DDL、系统表和未支持语法。
- 使用短事务执行多条更新；约束、导出或业务检查失败整批回滚。
- 验证查询资源限制和可取消执行；不能把同步执行之后的耗时统计冒充超时拦截。
- 分开验证 SQL 读集合与写集合，固定函数/表达式白名单和日志确定性；类型往返与多引用约束不能仅依赖 SQLite 默认行为，见第 15.2–15.3 节。

UI 任务：最小只读表预览、SQL 校验结果和具体语句/字段错误；底层诊断可折叠。

测试：合法增改删、外键/唯一/类型约束、注释/字符串/多语句边界、跨组写入、全表条件、耗时查询、导入导出等价。

交付/完成标准：受限 SQLite 服务可运行，非法混合批次原状态不变；不替换当前用户数据库。

### T4：统一提交与模拟存档

目标：在接真正页面编辑前，先解决“怎么算保存成功”和恢复问题。

功能任务：

- 定义 run/commit/parent、基准版本、模板/schema/参数指纹、消息锚点及变化日志。
- 临时状态执行、整批校验、唯一存档网关、成功确认和正式视图切换。
- 手动、模型、迁移、恢复共享提交检查；模拟消息支持一个锚点多次提交。
- 幂等、取消、保存失败、确认丢失、读回失败和多实例冲突。
- 第一版保存完整 JSON 状态快照及已执行 SQL 日志，验证恢复无需 AI。
- 固定快照截止提交/序号和前后指纹：提交后快照已经包含本次 SQL，不在恢复时再执行一次；压缩增量从截止位置之后开始。
- 设计缓存版本对账，不让缓存成为第二事实源。
- 定义独立复制与单父分支的身份继承、提交来源和依赖范围，避免不同聊天共用可变提交头，见第 15.7 节。

UI 任务：草稿/暂存/已保存/失败标识，前后差异和保存范围确认的通用组件。

测试：同 ID 重试只保存一次、版本冲突零覆盖、失败不前进、关闭并重建运行时恢复同一状态、快照加日志不重复应用、无消息锚点只保留草稿。模拟冲突保证不替代真实宿主锁/CAS 可行性验证。

交付/完成标准：完整模拟保存/恢复链及故障测试。T10 接宿主时复用同一协议，不再补造第二套提交格式。

### T5：可填写的表格工作台

目标：交付第一个用户能直接操作的数据界面。

功能任务：

- 数据工作台接真实 SQLite 和 T4 沙盒提交服务，不能只改页面内存。
- 搜索、筛选、分页、列显示、行详情和类型化编辑。
- 新增 NPC/其他记录、引用选择、归档和受控删除。
- 行/字段锁定、编辑冲突、草稿保留、批量变化预览和保存反馈。
- 历史只读与当前世界编辑分开；结构改变留给 T6。
- 接入人工初始化及导入映射预览；正式空世界不装入演示数据，已有/锁定资料不静默覆盖，见第 15.1 节。

UI 任务：两组表导航、当前表说明、工具栏、表格/窄屏行详情、固定可达的编辑操作区；空表直接给出新增入口。

测试：文本/长文/数值/枚举/引用编辑、错误定位、取消、保存失败、过滤无结果、分页、长名称、键盘焦点和缩放。

交付/完成标准：不写 JSON 就能增加一个 NPC、改位置、保存并恢复沙盒记录。界面常驻说明“未写当前聊天”，不冒充正式存档。

T4 已知接入风险：在 200
NPC 的模拟世界中，重复完整图校验和读回明显偏慢。T5 需继续剖析并减少重复工作、保持编辑反馈可响应，不能为加速省略权限/引用/指纹/版本检查；大世界的生产性能不能由小 fixture 通过替代。

### T6：结构参数、DIY 与原子迁移

目标：开放真正生效的自定义结构和表级规则。

功能任务：

- 新增业务表/字段、显示改名、排序、分组、类型、必填、默认、枚举、引用。
- 表级规则、演算预算、上下文、API 继承、世界书导出配置使用统一模板。
- 高级 DDL 支持范围和规范化映射；稳定身份不能因显示改名变化。
- 每次结构修改生成迁移预览：旧值映射、缺失/冲突、被移除内容、影响引用和历史。
- 临时库验证迁移；模板、数据和版本原子提交，失败保持旧世界。
- 当前聊天模板和全局默认模板分别保存，后者不覆盖已有世界。
- 高级 DDL 是受支持结构的导入/表达入口，不形成第二份 schema；超出规范模板表达能力的语法明确拒绝，见第 15.2 节。

UI 任务：结构与参数子页、字段编辑/排序、规则表单、继承提示、迁移对比、保存范围和高级入口。

测试：加列/表、改类型/必填、删列、改关系/分组、非法 DDL、保存失败、历史旧模板恢复、全局默认不覆盖旧数据。

交付/完成标准：用户增加一个字段后能填写、校验并保存；不兼容修改有报告和恢复材料。基础 schema 迁移在本阶段完成，不推迟到旧版迁移阶段。

### T7：上下文、提示词与 API 继承

目标：将模板变成实际生成输入，而不只是一套配置表单。

功能任务：

- 全局/阶段/表级提示词继承、草稿、启用版本和运行冻结。
- 本轮剧情、前置结果、候选来源、旧记录、关系与到期计划的选择和预算。
- 可见性、锁定及表/列范围用于实际查询和提示词生成。
- 宏观使用旧宏观与相关历史，微观使用阶段提供的最新宏观视图。
- API 沿用现有客户端，显示宏观/微观/表级最终路由；配置变化只作用下一轮。
- 初步实现前置状态适配和冻结契约，供 T8/T9 使用；模拟调用不联网。
- 使用真实外部导出形态的固定样本；先冻结整轮输入/配置/总预算，宏观与微观分别在发送前冻结其候选和批次计划，见第 15.1、15.4–15.6 节。

UI 任务：实际发送预览、来源标记、行数与估算大小、启用/草稿版本、路由继承图示或清单、修改后生效说明。

测试：新增字段/规则真正进入输入、秘密和无关行过滤、预算截取可解释、运行中改模板/API 不改变已冻结请求、Key 不进入预览日志。

交付/完成标准：能查看每阶段实际将发给 AI 的内容；修改规则后下一次模拟请求确实改变。API 和上下文采用同一服务而非 UI 自己拼接。

### T8：宏观阶段与必要运行控制

目标：让宏观变化先形成可靠暂存状态。

功能任务：

- 等待已启用前置处理完成/明确跳过；失败或无法确认时停止自动运行并说明。
- 冻结输入、世界时间、运行身份、宏观候选、模板和整轮请求预算；微观候选在宏观完成后确定，不提前固定为旧世界的名单。
- 调用模拟宏观模型，检查 SQL 后应用到私有世界。
- 生成可追溯的宏观变化摘要，未变化记录继承。
- 排队、重复触发去重、取消、超时/预算、过期输入拒绝。
- 不单独提交宏观世界，不单独推进时间。
- 按本轮各前置来源的独立证据放行；发送前确认触发所有权并消费统一请求额度，取消贯穿等待和网络，见第 15.4、15.6 节。

UI 任务：前置状态、运行前检查、宏观进度、变化预览、取消和错误详情；标明“宏观结果暂存中，尚未正式保存”。

测试：合法天气/通行变化、无变化、非法或越权 SQL、前置超时、重复触发、取消、聊天/模板变化导致过期。

交付/完成标准：宏观暂存结果可读且可供微观使用；正式世界仍保持上一轮状态。运行控制不是留到 T11 才补。

### T9：微观阶段与整轮演变雏形

实施状态：已完成本地模拟，新增 61/61、完整回归 771/771。可信宿主、真实 API、持久未完成运行与角色卡世界书均未在本阶段接入。详见
[T9 报告](WORLD-EVOLUTION-T9-MICRO-WHOLE-ROUND.md)。

目标：验证世界条件真正影响 NPC 行动，并整轮一起保存。

功能任务：

- 微观读取最新宏观暂存、旧微观资料及剧情事实。
- 候选 NPC/组织/计划/事件按用户预算处理，可分批但不各自正式提交。
- 事实、引用、可见性、锁定和生命周期校验；计划结束不随意抹掉历史。
- 整轮复查基准提交、消息指纹、已启用模板、分支和取消/权限状态；沿用本轮冻结的请求配置，不因普通 API 参数更新而改用新配置或拒绝旧结果。

- 重试只复用仍有效的同轮暂存；过期后废弃，不用旧宏观拼新微观。
- 宏观变化后按影响关系扩展微观候选，支持非默认表、公平轮转和有序批次；补全中断续跑与收费未知状态，见第 15.5–15.6 节。

UI 任务：完整阶段进度、宏微观前后差异、受影响对象、单次保存结果、无变化状态及费用边界提示。

测试：环境→通行→NPC 行动；微观失败宏观不保存；同 runId 只推进一次；手动编辑冲突拒绝；模型请求数不超过预算；恢复不重新生成。

交付/完成标准：可查看一个完整模拟世界演变雏形，并在重建模拟运行时后恢复同一世界。仍不宣称酒馆存档/世界书真机通过。

### T10：酒馆聊天存档与确定性恢复

实施状态：本地适配、T4/T9 接线和模拟宿主专项 61/61 已通过；完整回归 832/832。真实酒馆持久读回/CAS 与指定聊天刷新、删楼、分支仍待验收，不以模拟代替。详见

## 12. 权限、实施节奏与安全边界

- 新计划书不授权自动开始 16 阶段；每阶段按用户随后指定的范围实施。
- 用户已分别授权 T0–T15；本轮实施 T15 的统一接线与候选验收，真实写入/费用仍受下面的独立范围限制。
- 用户指定“开始某阶段”后，该阶段的普通本地代码、测试与文档工作按范围执行，不反复询问是否可以做常规实现步骤。
- 真实 API 费用、实际聊天写入/删楼、现有世界迁移/清空、角色卡世界书写入需对应明确授权和目标范围。
- 浏览器只读/安全导航与会保存的按钮区分；不能用点击真实生成来验证纯 UI。
- 未获真实验收授权时保留待办，可继续不依赖它的模拟实现，不反复弹出相同问题。
- Git 提交、推送、默认导入地址切换及正式发布按用户实际要求执行，不由本计划自动触发。
- 每阶段完成报告：改了什么、用户能看到什么、测试结果、未验收项、下一步。
- 实页检查后恢复用户原来的页面/主题/缩放；不得为了测试覆盖 API 或聊天设置。

## 13. 主要风险与回退策略

| 风险                        | 提前处理阶段 | 处理原则                                  |
| --------------------------- | ------------ | ----------------------------------------- |
| 宿主缺保存确认或稳定锚点    | T0–T1        | 不假称持久保存；明确阻断/草稿规则         |
| WASM 404、体积或初始化失败  | T3           | 验证固定加载与失败诊断，不静默换成假 SQL  |

| 宏观先保存或时间重复推进    | T8–T9        | 同一 runId、私有暂存、整轮一次提交        |
| 聊天与缓存各自更新          | T4、T10      | 唯一持久化权威，确认后切换正式视图        |
| 删楼后旧 SQL 仍被当作有效   | T10–T11      | 依赖链失效与有效祖先恢复，不偷跑 AI       |
| 共用主世界书串聊天          | T0–T1、T12   | 请求级隔离或单活限制，不可靠则阻断        |
| 旧数据历史无法等价迁移      | T13          | 保留原档，明确迁移基线和限制，不伪造兼容  |
| 旧新版同时写入              | T0、T10、T15 | 单写入器、独立模式与启动检查              |
| 主题/宿主样式再次冲突       | T1、T5、T14  | 私有样式范围、共用 token、实页缩放回归    |
| 固定链接却载入旧包          | T15          | 校验实际加载版本/内容，保留旧包与更新指引 |

回退不等于删除新资料或直接启用旧写入器。先保留新存档及原始迁移材料，再按已验证的格式/版本兼容路径回退；无法兼容则保持旧版只读或恢复对应备份并提示差异。

### 15.1 首次初始化与真实来源映射

补足“采用模板之后，世界从哪里来”的完整路径：

- 首次入口分为人工建立、只读导入已有资料、明确允许的 AI 补全；不默默执行付费初始化。
- 正式空世界与沙盒演示数据分开。采用默认模板不等于接受样例 NPC，也不等于自动填满七张表。
- 在有效消息锚点存在时，用统一提交服务保存首次状态；没有锚点则仍是草稿，不另造剧情消息。
- 明确角色卡/原始世界书、MVU、SP·数据库和本插件已有数据的来源身份、字段映射、类型转换、缺失项及冲突报告。
- 不把时间上最后收到的资料天然当作权威；来源优先级按字段用途明确配置。剧情确认事实属于约束，手动/锁定值不被后台静默覆盖；冲突进入可见报告与明确处理流程。
- 从角色卡世界书读设定时排除本插件生成的 `WorldEvolution-*` 投影，防止把自己的旧输出再当新来源。
- T0 核对宿主实际版本的导出形态。参考数据库的 `sheet_*.content` 是表头加二维行数组，不用只有 `rows: [{name: ...}]`
  的假样本宣称兼容。
- 导入仅限用户选中的来源、表和字段；只读访问前置插件，不改其数据。来源缺失时仍可人工开始，未知格式明确报告，不能猜成一个角色。
- 初始化使用稳定来源关联，确认后再提交；刷新、重试和恢复不重复补种，也不自动把外部全量数据重新覆盖进来。

必测：真实形态样本的 42 名 NPC 能识别为 42 行，而不是一张表名；中文/自定义列可预览映射；锁定值和重复来源不会被覆盖或重复建人；MVU/数据库未安装仍能建立环境与 NPC；首次提交恢复后一致。

### 15.2 字段物理编码与结构唯一来源

- T2 为每种支持类型列出 UI 输入、SQLite 物理表示、JSON 编码、空值、默认值、精度及校验规则，T3 用同一规则往返转换。
- 区分未提供值、NULL、空字符串、false、0、空列表；它们不能因序列化、默认值或表单判断混为一谈。
- 明确数值支持范围；超过可无损往返范围的值拒绝，或采用已定义的精确编码，不能悄悄截断。
- 世界时间按模板定义纪元、比较与持续时间规则；未支持的比较明确拒绝，不硬转成现实 Date。
- 多引用/受控列表的物理表示在 T2/T3 定稿；若使用 JSON 值，应用层仍检查引用、重复和删除影响，不能声称 SQLite 自动约束数组内所有成员。
- 规范化 JSON 模板是业务结构的唯一描述；SQLite schema 从它编译，并检查一致性。
- 高级 DDL 仅作为受支持结构的导入/表达入口，解析后进入规范模板、迁移预览与统一提交；不保留独立于 GUI 的第二份可变 schema。
- 模板无法表达的触发器、默认表达式、约束和其他语法明确拒绝，不能导入时静默丢弃。显示名变化不能改变表/字段稳定 ID。

必测：所有基础类型含空值往返一致；多引用删除检查有效；超精度值被定位；受支持 DDL→模板→DDL 保持约束；不支持结构零写入；GUI、校验与数据库对同一记录给出一致结论。

### 15.3 读写权限、启用状态与确定性 SQL

定义操作矩阵，而不是把几个开关都解释成“停用”：

- 关闭自动更新：禁止本轮 AI 修改，仍可按读取权限作为世界条件。
- 行/字段锁定：阻止指定修改，不自动删掉该对象的可读关系或历史。
- 隐藏显示：仅影响界面列，不自动改变生成或主 AI 的读取权限。
- visibility：分别约束后台演变 AI、主 AI 投影和用户查看；不能简单用一个界面开关同时控制三者。
- 归档/死亡/停用：明确是否还能成为条件、引用和事件参与历史；不默认消失或自动复活。
- 用户人工修改权限与 AI 修改权限分开，但人工操作仍走类型、引用、版本和提交校验。

SQL 契约补充：

- 查询、DML 表达式及子查询中的读集合与写集合分别授权。只检查 UPDATE 影响了几行，不能防止把禁止读取的字段复制到公开列。
- 首版允许的语法尽量小；不能证明读集合安全的子查询、CTE、函数或表达式直接拒绝，不承诺支持任意 SQLite SQL。
- 固定 SQL 日志只记录可确定重放的操作。随机、当前时间及非确定默认值必须拒绝或在执行前物化为固定参数；恢复时不能重新求值。
- 自然语言规则与代码硬限制分开：类型、配额、权限和明确事实字段可硬校验；不能宣称程序自动证明任意剧情文本的全部语义一致性。无法证明的重要冲突进入报告/人工确认，不假报安全。

必测：道路禁更后 NPC 仍能读取道路受阻；AI 改道路被拒绝；秘密字段经子查询复制被拒绝且整批零写入；相同基底在不同时间重放固定日志得到同一指纹。

### 15.5 候选身份、宏观影响传播与非默认表

- 数据行以 `tableId + rowId` 区分；姓名只用于显示和显式来源匹配，不能作为跨表全局去重键。
- 表用途标记而非显示名决定候选分类和预算；改名后的 NPC 表及自定义业务表仍可参与。
- 候选显示入选原因：剧情直接关联、位置/区域影响、组织关系、到期计划、用户指定或后台轮转等。
- 宏观完成后，依据本轮已冻结来源、变化和关联关系重新扩展微观候选，再冻结微观计划；不临时读取另一轮剧情或新的外部结果。例如暴雨影响城门区域时，驻地 NPC 与有关计划即使剧情没点名也可进入候选。
- 数量受预算约束，未选对象及理由可查看；定义优先级与保留轮转机会，避免永远按姓名截取前几名。轮转位置仅随有效提交推进，重试不跳号。
- 候选可读集与可写集分开；锁定或归档对象仍可能提供条件。关系成员使用稳定 ID，显示/提示时正确解引用。
- 新增对象有独立配额和稳定 ID；同批新增对象之间的引用由依赖排序或整批验证处理，不生成悬空姓名引用。
- 首版同阶段批次有序应用到同一个私有世界；后批使用确定的前批暂存版本。同一对象本轮不重复分配行动写入批次，避免重复行动及相互覆盖。

### 15.6 表级执行计划、统一预算与中断恢复
