# T4：统一提交与模拟存档

日期：2026-10-07。对应总计划 T4；本阶段只实现独立模拟存档，不写当前酒馆聊天。

## 1. 用人话说明结果

SQL 执行完以后，资料先放在暂存区。它只有在存档网关保存成功、重新读取又确认内容一致后，才成为工作台里的已保存世界。

本阶段解决的是“可靠保存和恢复”的底座，而不是发布新的填写页面：

- 保存失败：原世界不变，不会误显示为已保存。
- 不知道保存是否成功：先查询提交编号；不能直接把同一 SQL 再执行一次。
- 两个面板同时修改同一版本：模拟网关只接受一个，另一个报冲突，不覆盖对方。
- 关闭后重新打开：读取完整 JSON 快照，不需要重新调用 AI，也不把快照已经包含的 SQL 再跑一次。
- 没有有效助手消息：只能保留草稿，不冒称已经存进聊天。
- 世界复制或建立分支：各自有独立的可变存档头，继承的来源历史只读。

这些能力在本地沙盒通过验证；当前 alpha.16 页面、旧聊天资料、API 和世界书未改变。T5 才把可填写的表格工作台接到这套服务，T10 才验证真实酒馆保存。

## 2. 文件和唯一权威

隔离模块都在 `src/世界演变/rebuild/`，没有新的自动运行入口，也没有被旧入口导入。

| 文件                                   | 职责                                                                      |
| -------------------------------------- | ------------------------------------------------------------------------- |
| `t4-protocol.ts`                       | 严格存档协议、SHA-256、版本戳、提交链、快照截止位置、历史与身份验证       |
| `t4-store.ts`                          | 唯一模拟 JSON 网关、原子版本比较、故障注入、锚点检查与 JSON 导出/重新载入 |
| `t4-service.ts`                        | 私有 SQL 执行、迁移/恢复提交、保存确认、正式视图切换、缓存对账与复制/分支 |
| `t4-preview.ts`、`T4CommitPreview.vue` | 共用只读状态、公开字段差异、保存范围及仅表达同意的勾选框                  |
| 对应 `.test.ts`                        | 实际 SQLite 测试、协议损坏、失败/取消/竞争、公开显示和容量测试            |

模拟权威是网关内保存的 JSON 字符串。SQLite 是每批独立执行的临时引擎；服务里的正式视图与缓存只是已验证 JSON 的副本。

通用存档标识为 `world-evolution-archive`；外层开发 fixture 标识为
`world-evolution-t4-fixture`。当前协议的 scope、服务和网关都严格只开放沙盒身份，通用名字不会启用真实写入。T10 应在宿主能力通过验证后扩展同一 scope 身份协议和适配器，复用本阶段的提交、快照、日志与指纹字段，不另造第二套提交格式。

`exportStorage()` 导出的是开发 fixture
JSON；重新创建网关会从这个 JSON 读取。它不写硬盘、浏览器本地存储、IndexedDB、聊天变量或角色卡。

关闭服务会丢弃尚未保存的草稿。开发者必须保留网关或其导出 JSON，才能在重新创建时模拟存档恢复；不声称当前网页刷新会自动保留这一沙盒。

## 3. 固定身份与提交格式

每份存档明确保存：

- 运行模式 `t4-sandbox`，独立 `sandbox-*` 聊天身份、世界身份和分支身份。
- 初始完整模板和数据、初始状态指纹；数据 revision 可以继承来源，分支本地提交序号从 1 开始。
- `runId`、`commitId`、单父 `parentCommitId`、本分支 `seq`、`baseRevision` 和提交类型。
- 稳定助手消息/选页身份与输入指纹；不是数值楼层索引，也不是仅凭正文相同判断身份。
- 模板、物理 schema、输入、提示词、模型与参数指纹。
- 固定 SQL、参数、批次身份、历史读写授权和每批执行限制。
- 前后状态指纹、按 `tableId + rowId` 标识的变化清单。
- 完整提交后快照，以及 `throughCommitId / throughSeq`、前后指纹。

提交类型为人工 SQL、模型 SQL、显式模板迁移、用户历史恢复。SQL 不得顺带改模板；迁移需保持模板 ID 并递增模板版本；恢复只允许指定本分支既有提交或初始快照。

运行配置只记录指纹，不接受 API
Key 或整份凭据配置。SQL 参数属于必要的业务日志，显示组件不展开原始 SQL、参数、内部诊断或秘密字段。

指纹采用稳定键序的 JSON 和浏览器 WebCrypto
SHA-256。数组顺序、缺失字段和显式 NULL 保持不同；拒绝 getter、toJSON、循环、不支持的对象和超限资料。指纹用于检测不一致/损坏，不是数字签名，不能证明有人重写完整存档并重算指纹后仍可信。

## 4. 一次提交如何完成

1. 从已确认 JSON 冻结基准世界、提交头、输入身份、模板和调用方授权。
2. 按顺序在私有世界执行一个或多个 T3 批次；每批结果再次经过严格返回验证。
3. 记录实际固定日志及每个暂存步骤的前后指纹。中途失败或取消，整轮不能提交。
4. 对整个结果进行 T2 图校验，生成一次统一版本戳、完整快照和不可变提交载荷。
5. 唯一网关复查基准、提交身份、当前消息/选页/输入、取消状态和完整协议。
6. 模拟 CAS 在一个同步比较及赋值点保存；不把读回当成互斥。
7. 独立读取 JSON，核对提交身份和完整内容，再切换正式视图。

一个锚点可以有多次连续提交。一次提交只增加一个 revision；新增行记录本次创建/更新版本，已有行仅在业务内容或可编辑元数据改变时更新版本，其他行不动。

明确的无变化成功运行（例如 SELECT）也可以记录一个提交、推进一次 revision，但不改变行的版本戳。这为后续成功轮次/频率账本提供确定语义；T8–T9 仍负责真正的频率、候选、跨阶段预算和请求账本，T4 不自行调用 AI 或推进时间。

相同已准备载荷可以重试保存，实际只写一次。新服务遇到已有 run/commit 身份，会在执行 SQL 前阻断重新准备；应读取已有结果，而不是再次演算。

正式视图、提交载荷、传入请求和导出值均与调用方对象分离。跨 await 时冻结 JSON，并捕获同一个取消信号，不能通过修改参数对象换掉当前运行的取消来源。

## 5. 失败、取消与待确认

| 情况                       | 处理                                              |
| -------------------------- | ------------------------------------------------- |
| SQL/类型/权限/引用校验失败 | 零保存；清除本次无效草稿，不能误保存上一份草稿    |
| 保存前取消                 | 零写入；草稿不允许在后续对账中复活                |
| 真实写入后发生取消         | 不能声称撤销；核对实际持久提交再显示结果          |
| 明确保存失败               | 原正式视图保留，已校验草稿可按原载荷重试          |
| 写入成功但确认丢失         | 待确认；禁止盲目重试或准备新运行                  |
| 保存后读回失败             | 待确认；不能用缓存冒充成功                        |
| 对账证明提交存在           | 确认已保存；不重新执行 SQL                        |
| 对账证明没写入且基准没变   | 恢复原载荷可重试状态，不重新演算                  |
| 基准/消息/swipe/输入已改变 | 冲突或锚点错误，零覆盖                            |
| 关闭时尚在处理             | 不使未确认结果成为正式视图；重新打开读已保存 JSON |

相同提交 ID 或运行 ID 对应不同内容时拒绝。对账若发现自己的提交已存在、但后面又有合法的新提交，正式视图以最新权威头为准，不用旧回执覆盖后续世界。

模拟网关还验证初始化/复制失败不留下半份目标 fixture，保存不更改模拟 MVU、第三方数据库及其他选页资料。

## 6. 恢复、缓存与历史

普通恢复直接载入最后一个完整快照。快照已经包含截止提交的 SQL，所以不执行其中的日志，不读取当前新模板、不补种、不调用模型。

另有显式增量重放入口：选择一个已验证截止提交，从其后连续日志开始，使用当时的模板、权限、参数和稳定行身份；检查每步基准/结果指纹，再统一戳版本。迁移/恢复提交直接使用其验证过的完整检查点。

回放不是“重新请 AI 计算”。删楼/改楼后的有效祖先选择、依赖失效及宿主事件接入仍属于 T10–T11，本轮没有擅自实现或执行真实删除。

缓存必须同时匹配 scope、头信息和内容指纹。同 revision 但内容不同仍丢弃；损坏或不可读取的权威存档直接报错，不从缓存、世界书或模型猜补。

独立复制使用新 worldId/branchId；同世界分支保留 worldId、建立新 branchId。两者都保存指定分叉点之前的不可变来源前缀、来源指纹和可核验的消息映射，不能继承分叉点之后的提交或共享可变头。第一版是单父继承，不做合并。

源聊天后来变更不会自动写入已经独立复制的世界。来源历史是只读材料，不是另一套可编辑权威；目标的新提交从自己的 genesis 继续。

## 7. 共用 UI 与边界

新增只读预览组件支持草稿、私有结果、保存中、已保存、失败、待确认、冲突、取消八种状态；初始 fixture 单独显示“模拟起始资料已载入，尚无提交”。

- 固定显示“独立模拟存档，未写当前聊天”，不让“已保存”冒充酒馆成功。
- 公开字段显示修改前/后；隐藏表、行、字段和引用目标按统一可见性过滤，不从计数或引用数量泄漏。
- 保存范围列出模拟聊天/世界/分支与助手消息/选页，不展开输入正文。
- 勾选框只表达用户同意，不执行 SQL、保存、调用 API 或同步世界书；真正按钮和编辑器在 T5 接统一服务。
- 输入替换后重置同意，避免在另一份草稿上沿用旧确认。
- 草稿仅当前服务内保留，关闭/重新创建会丢失的提示明确。
- Vue 安全文本插值、私有 scoped 样式；本轮只做编译/SSR 及状态验证，不声称浏览器几何布局验收通过。
