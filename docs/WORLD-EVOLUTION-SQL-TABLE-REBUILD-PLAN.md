## 1. 这次要做成什么

将世界演变从“固定对象类型＋JSON 字段编辑＋IndexedDB 存储”，升级为：

- 真实 SQLite 执行与查询；
- 宏观世界、微观世界两组表格；
- 可直接填写的表格工作台；
- 可修改字段、说明、填表规则、上下文和世界书导出的模板；
- AI 输出受限制的 SQL，由插件检查并执行；
- 随聊天保存的 JSON 快照和操作日志；
- 宏观先完成、微观读取最新宏观条件，整轮一起提交；
- 可恢复、可回退、有明确删楼与分支规则的世界状态。

这仍然是一个独立的“世界演变”插件，不成为主游戏的必装组件，也不并入 SP·数据库或 MVU。

它的目的不是仅把剧情整理成表格，而是让 NPC、组织、计划等在主角视线之外，根据世界条件和已有事实自主行动。

## 2. 已确认的设计方向

1. 参考数据库的 SQL / SQLite / JSON 分工，不要求用户日常手写 SQL。
2. 默认提供可用表格，同时允许用户 DIY；不是只开放一个大 JSON 文本框。
3. 宏观与微观是同一世界数据库中的两个分组，不是两个独立插件或数据库。
4. 本轮宏观状态是在上一轮已提交状态上增量修改，不每轮重新造世界。
5. 本轮微观行动依据最新宏观状态、上一轮微观状态、本轮剧情及前置结果。
6. 宏观、微观不能并行生成后各自保存；成功后统一提交。
7. 不变的数据原样继承，不为凑表格而制造变化。
8. 默认等待本轮剧情及已启用的前置处理完成，再启动世界演变。
9. 世界书仍写当前角色卡自带的主世界书，只管理本插件托管条目。
10. 先做模拟雏形，再逐段实现、测试；真实 API、聊天写入和迁移另设验收关口。

## 3. 与旧计划的关系

本计划是新的目标设计，不是对旧版本完成状态的重新命名。

旧文档 `WORLD-EVOLUTION-DB-DESIGN.md` 中以下方向将由本计划替代：

| 旧方向 | 本次目标 |
| --- | --- |
| IndexedDB 是业务数据事实源 | 聊天中的本插件 JSON 提交历史为持久化事实源；IndexedDB 如保留，仅作可重建缓存 |
| 固定七类对象、业务字段装在 `data` 中 | 模板驱动的真实 SQL 表；默认七类表，也支持增加业务表与字段 |
| AI 只输出 JSON operations，禁止 SQL | AI 提出受限 SQL；插件负责授权、执行与校验 |
| 世界资料以对象卡片和 JSON 编辑为主 | 分组表导航、单元格/行编辑、独立的结构与参数页 |
| 单次生成一批混合对象更新 | 宏观、微观两段顺序生成，整轮统一保存 |

继续保留的原则：独立插件、只读前置输入、数量限制、稳定身份、版本冲突检测、整批失败不留半成品、确定性恢复、可见性隔离和精确世界书投影。

本轮不改写旧计划；后续开始实施时，应在旧文档增加“相关章节已由本计划替代”的提示，避免新旧规则同时被当作实施依据。

### 4.2 参考代码范围

参考仓库：[AlbusKen/shujuku](https://github.com/AlbusKen/shujuku)。本次静态核对对象是本地 `shujuku-inspect-20260925`，HEAD 为 `599e3580c3106fa234ead38fdfe8625080419143`，其 package 自报 9.2.5。

未核对当前浏览器 SP·数据库 IX 构建与该 HEAD 是否完全一致，不能把本地审计结论无条件套到所有版本。

可借鉴：

- `src/data/sqlite/sqlite-engine.ts`：真实 sql.js 引擎、批量事务、提交前检查、导入导出。
- `src/data/sqlite/sync-bridge.ts`：表格 JSON 与 SQLite 之间的转换和严格校验。
- `src/service/table/sql-table-service.ts`：SQL 写入范围、稳定行身份、schema 冻结与过期检查。
- `src/service/table/storage-frame-v2-*.ts`：JSON 检查点、SQL 日志、楼层恢复和宿主保存。
- 可视化编辑器：数据与结构参数分离、当前聊天模板与全局默认模板分离。

不能误解或照搬：

- 参考代码还有 native 模式；native 常规 AI 填表使用 JSON/DSL，不等于所有路径都是 SQL。
- 底层 `run()` 能执行 SQL，不代表已具备完整安全限制。
- UPDATE/DELETE 的 WHERE 要求不能只写在提示词里，更不能把“有 WHERE”视为不会误改全表。
- 不直接复制其主角、背包等业务表，也不共享其隔离字段或运行状态。
- 不直接复制所有 native/sqlite 双模式、别名及历史兼容层；新核心先保留一条明确的 SQLite 路径。
- 不照搬“任务完成即删除”等生命周期规则，世界演变仍需保留因果历史。
- 若移植实际代码，先检查来源文件及仓库许可，按许可保留必要声明。

浏览器 SQLite 候选采用 [sql.js](https://github.com/sql-js/sql.js)。它的内存运行、导入导出与持久保存是不同职责；实际版本、WASM 打包和体积须在 Q2 验证后锁定。

## 5. 总体分工与数据权威

| 层 | 职责 | 不承担什么 |
| --- | --- | --- |
| 表格工作台 | 展示表格、编辑记录和模板、查看变化与错误 | 不直接绕过提交服务写 SQLite 或聊天 |
| JSON 模板 | 定义表组、字段、规则、上下文、导出设置 | 不等于当前世界的具体业务数据 |
| SQL | 描述读取及新增、修改、删除动作 | 不直接获得宿主、世界书或系统历史的写权限 |
| SQLite | 临时执行、关系查询、结构约束、事务校验 | 不自行保证酒馆聊天已经保存 |
| 聊天 JSON 提交历史 | 保存有效状态、模板版本、检查点和日志 | 不依靠再次调用 AI 才能恢复 |
| IndexedDB 缓存（可选） | 加速恢复、保存可重建视图 | 不在聊天保存失败时独自推进世界 |
| 世界书投影 | 向主 AI 提供允许读取的世界资料 | 不是可反向覆盖数据库的事实源 |

SQL 是操作语言，SQLite 是执行引擎，JSON 是模板与存档载体；三者不是互斥选项。

必须只有一份持久化权威。内存数据库和缓存要能从有效聊天提交恢复，不建立“聊天一套、IndexedDB 一套，各自算最新”的双事实源。

API Key 等凭据继续留在 API 配置所属的安全边界，不进入表格模板、聊天快照、世界书或默认导出包。

## 6. 默认表组与模板能力

### 6.1 默认表格

| 表组 | 默认表 | 典型字段与职责 |
| --- | --- | --- |
| 宏观世界 | 社会 | 区域、制度、秩序、经济、舆论、冲突和持续影响 |
| 宏观世界 | 环境 | 时间范围、天气、资源、灾害、风险及影响区域 |
| 宏观世界 | 地点 | 地理层级、通行条件、设施、控制方、现场状态 |
| 微观世界 | NPC | 身份、位置、状态、认知、目标、关系、行动与限制 |
| 微观世界 | 组织 | 成员、资源、目标、行动安排、立场和关系 |
| 微观世界 | 计划 | 执行者、触发条件、期限、阶段、阻碍与完成状态 |
| 微观世界 | 事件 | 已发生事实、时间地点、参与者、结果和关联对象 |

这是默认起点，不是最终字段硬编码清单。宏观表应覆盖足够丰富的世界条件，但不要求每轮都更新所有宏观表，也不固定宏观一定使用更多 token。

组织和事件也可能影响宏观条件。默认在下一轮宏观阶段读取这些已提交影响，不在同轮无限往返演算；后续如要多轮反馈，另行设计预算与停止条件。

表组表示演算写入阶段，不自动决定资料可见性。NPC 可以有秘密，宏观表也可以有尚未公开的信息。

### 6.2 每张表可配置的内容

1. 基本结构：稳定表 ID、显示名、所属组、显示顺序、用途。
2. 字段：稳定字段 ID、显示名、SQL 列映射、类型、必填、默认值、枚举、范围和字段说明。
3. 关系：目标表、引用字段、删除策略、是否允许为空。
4. 业务规则：初始化、新增、更新、结束/归档、删除条件。
5. 演算设置：是否参与自动运行、频率、批次和单轮修改数量上限。
6. 上下文：剧情楼层范围、旧记录数量、相关查询、输出列和独立预算。
7. 投影：整表/按行输出、标题、关键词、常驻或关键词触发、索引与正文模板。

频率等参数先继承明确的全局默认值，再允许表级覆盖。界面写清“继承”“关闭”“具体数值”，不要求用户猜 `-1`、`0` 的意义。

### 6.3 DIY 的保护边界

- 允许增加业务表和字段，调整显示名称、排序与规则。
- 显示名变化不改变稳定表 ID、字段 ID、行 ID 和已有引用。
- 业务表可扩展，但系统身份、提交祖先关系、来源和可见性语义必须受保护。
- 表组、类型、必填或引用关系的变化属于结构迁移，不能静默套到旧数据。
- 模板与生成的 DDL 要有单一规范化来源；高级 DDL 编辑必须能校验并转换回支持的模板结构。
- 初版只支持已验证的 DDL 子集，不默认允许任意触发器、虚拟表或自定义函数。
- 新字段必须真正进入数据编辑、AI 上下文、SQL 校验和所选投影模板；不能仅出现在配置页面。
- 秘密字段、行锁、字段锁的含义明确，并在执行层生效，不只影响显示。

## 7. 宏观与微观的演算流程

```text
剧情完成 + 已启用前置处理完成/明确跳过
                 ↓
冻结本轮输入、模板和上一轮已提交版本
                 ↓
建立私有临时 SQLite 世界
                 ↓
宏观：旧宏观状态 + 本轮事实 + 相关历史影响
                 ↓
检查宏观 SQL → 执行 → 生成变化摘要
                 ↓
微观：旧微观状态 + 最新宏观条件 + 本轮事实
                 ↓
检查微观 SQL → 执行 → 整轮业务校验
                 ↓
复查聊天、分支、正文、模板与基准提交未变化
                 ↓
保存一次权威 JSON 提交
                 ↓
切换正式运行状态 → 更新表格 → 同步世界书
```

### 7.1 前置等待与上下文

- MVU、数据库、工作流助手仍是可选且只读的输入来源。
- 对已启用的前置阶段，须确认成功、明确跳过或失败；不能用固定等待几秒冒充已完成。
- 失败、超时或无法确认时，自动运行停在待处理状态，展示原因；不静默继续。
- 手动运行可在提示当前前置状态后由用户选择，但仍冻结输入和校验提交。
- 输入包含剧情正文、相关前置结果、候选来源、旧世界记录及表格规则，并可预览。
- 宏观和微观分别显示发送范围、记录数和估算大小，不无差别发送全库。
- 微观可以分批处理候选，但必须使用同一份最新宏观暂存状态，最后只生成一个正式提交。
- 修改对象上限、表格频率和预算由用户设置；不会固定每个 NPC 调用一次 AI。

### 7.2 事实与时间

- 本轮剧情已确认的位置、伤亡、行为和结果是约束，不被后台演算擅自覆盖。
- 每轮确定一个世界时间边界；宏观和微观使用同一边界，不各自重复推进时间。
- 本轮没有宏观变动时，微观读取继承的有效宏观状态，不能读空白状态。
- 新对象必须满足初始化、引用、来源与数量限制；用户可手动添加角色作为基线。
- 事件已经发生时保留事实；计划完成时默认结束/归档，不为减少行数抹去历史。

### 7.3 失败与取消

- AI 请求、SQL、关系、时间或业务校验失败：丢弃本轮临时世界，不提交半轮结果。
- 临时 SQLite 内可以使用短事务；不在等待网络期间占着正式库的长写事务。
- 并行用户编辑、模板变化、聊天切换、楼层重生成或版本变化使当前结果过期，禁止覆盖新状态。
- 缓存刷新失败可以重建；世界书同步失败可以重试；二者都不能导致再次提交同一次演变。
- 微观重试可复用同一冻结输入的宏观暂存结果；输入或版本变化后必须废弃整轮暂存。

## 8. SQL 执行与本地硬校验

AI 只提出更新，插件决定能否执行。初版协议可采用 JSON 信封包裹 SQL 语句和参数，例如 `runId / stage / baseCommitId / templateVersion / statements`；这仍然是真实 SQL 执行，不是把 SQL 文本翻译成旧 operations 的假支持。

必须实现的防线：

1. 独立的只读查询入口和业务写入入口；查询上下文只暴露允许读取的表、列和记录。
2. 初版 AI 写入白名单为支持的 INSERT、UPDATE、DELETE；其余语法未验证前拒绝。
3. AI 禁止 CREATE、ALTER、DROP、PRAGMA、ATTACH、DETACH、触发器、扩展加载及事务控制。
4. 系统表、历史表、凭据和前置数据库不作为可写目标；宏观阶段不能写微观，微观阶段不能反写宏观。
5. 支持的 SQL 用语法解析与标识符映射校验，不能只靠分号切割或字符串黑名单。
6. UPDATE/DELETE 必须有有效目标条件，并复核实际影响记录；`WHERE 1=1` 不能绕过候选和行数限制。
7. 复核字段锁、行锁、对象授权、修改数量、引用、类型和业务范围；执行前后差异超范围时整轮拒绝。
8. 禁止 AI 改写稳定 ID、来源和提交元信息；可见性升级必须有被允许的明确依据。
9. 同时使用 SQLite 约束与应用层规则；SQL 成功不等于世界设定、引用和保密规则已经满足。
10. SELECT 查询也有表范围、结果数和执行预算；高级结构查询不混入 AI 的普通上下文查询。
11. 参数采用绑定；表列名称使用验证过的映射和转义，不拼接任意用户输入。
12. 不支持或不能证明安全的 SQL 失败关闭，不静默放宽、忽略或部分执行。

确定性要求：行 ID、世界时间和需要的随机结果由系统固定或物化后记录。初版禁止回放依赖 `random()`、运行时当前时间、外部查询或非确定函数；不把模型输出的文字“推理过程”当作状态恢复依据。

## 9. JSON 存档、楼层与分支

### 9.1 独立命名空间

聊天附加数据使用本插件自己的命名空间，建议暂名 `WorldEvolution_Storage`；实际宿主字段/API 在 Q1 核对后固定。

不能写入 MVU 的 `stat_data`，不能复用 `TavernDB_ACU_IsolatedData`，不能覆盖其他脚本的消息数据。

使用宿主网关定点合并本插件字段。先确认保存接口、完成确认和重新读取能力，再接真实聊天；不能因为内存对象已修改就报告保存成功。

提交承载规则：

- 自动演变绑定实际处理的助手消息及当前 swipe 的稳定身份，不绑定单独的楼层序号。
- 首次初始化、手动数据编辑、模板迁移，默认追加到当前分支末端的有效助手消息锚点；同一锚点可有多次有序提交，不覆盖前一条历史。
- 查看历史提交默认只读；需要修改历史时先明确建立分支或回退，不直接改写旧快照。
- 空聊天、没有可用助手消息或锚点正在变化时，世界数据只能作为明确标记的草稿，禁止报告正式保存；不自动创建剧情消息，也不退回 IndexedDB 作为权威。
- 全局默认模板可以独立保存，但不等于当前世界已初始化。Q1 必须验证这些锚点是否可稳定保存、恢复及随分支识别。

### 9.2 每次提交需要记录什么

- 存档格式版本、世界 ID、聊天/分支身份。
- 稳定 `commitId`、`parentCommitId`、基准版本及幂等运行 ID。
- 消息稳定身份、内容指纹和 swipe/分支信息；楼层序号仅作显示与定位。
- 本轮采用的模板版本、结构指纹和 SQLite/协议兼容信息。
- 可校验的状态快照或有效检查点引用。
- 宏观、微观的已执行操作日志、固定参数、影响记录与变化摘要。
- 前后状态指纹、世界时间、必要的随机种子/物化结果。
- 运行来源与状态，不包含 API Key 或其他凭据。

模板历史必须能恢复对应旧结构，不能用最新模板直接执行所有旧 SQL。每个当前世界只选择一条有效提交祖先链，不按最大楼层号或时间戳猜最新状态。

### 9.3 保存协议

1. 在临时世界完成执行与整轮校验，生成待提交快照和日志。
2. 提交前复查当前聊天、分支、正文、模板、基准提交及取消标记。
3. 通过唯一保存网关，将状态、历史和模板迁移信息一起写入本插件权威存档。
4. 确认宿主保存成功后，才切换正式内存世界、更新缓存和界面。
5. 之后同步世界书；失败记录待同步，不撤销已成功保存的世界。

SQLite 事务与宿主聊天保存不是同一个物理事务。本计划的“整轮一起保存”通过临时状态、单次权威提交和保存确认实现，不能宣称它们天然拥有跨系统 ACID。

宿主保存失败或确认不明时，重新读取相同提交 ID 判断是否已落盘，不能盲目重做 SQL。启动、重试和多入口写入统一去重；需要验证多实例/多标签并发，无法保证单写者时必须阻止冲突写入。

### 9.4 恢复与删楼规则

- Q4 首先用每次提交的完整 JSON 状态快照实现可靠恢复，同时保留已执行 SQL 日志用于审计。
- 数据量评估后，可增加“检查点＋确定性增量日志”的压缩模式；未验证等价前不删除可靠恢复材料。
- 恢复不调用 AI；从完整快照直接恢复，或在兼容的结构上重放已保存的固定操作并比对结果指纹。
- 缺检查点、缺模板、日志断链或指纹不符时停止并报告，不拿旧缓存或世界书猜补世界。
- 删除、修改或重生成中间消息时，默认使依赖它的后续提交失效，恢复到最近有效祖先。
- 历史重放仅恢复仍有效的已提交链，不能把依赖被删事实的后续 SQL 当作仍然有效。
- 需要重新演算保留下来的后续剧情时，给出待处理范围，由用户启动；不偷偷调用真实 API 追平。
- 切换 swipe、聊天分支或复制聊天时，明确创建/匹配分支身份和继承点，不串用另一分支结果。
- 清空当前世界只清本插件命名空间及缓存、托管投影；先提示备份和影响范围，不删剧情、MVU 或其他数据库数据。

## 10. 工作台与模板保存范围

保留现有居中控制台、独立 API 页面、奶油/淡绿色底和粉红危险区的语义色体系，不另做第二套总面板。

主要重做世界资料页，其余页面随新数据协议适配：

| 页面 | 新目标 |
| --- | --- |
| 总览 | 当前存档、模板、有效提交、宏观/微观状态、待恢复/待同步提示 |
| 世界资料 | 两组表导航，搜索分页，直接编辑单元格/行，增加角色和其他记录 |
| 结构与参数 | 表/列、演算规则、上下文、预算、锁定、世界书配置及迁移预览；可作为世界资料的独立子页 |
| 楼层记录 | 本轮两阶段变化、提交祖先链、失败位置、删楼影响与恢复状态 |
| 世界书投影 | 基于当前有效提交的逐表/逐行投影、关键词、常驻索引和同步状态 |
| API 配置 | 复用当前路由；宏观、微观可继承同一配置，表级覆盖不得绕开统一客户端 |
| 自动演变 | 前置状态、触发频率、对象与请求预算、排队和取消；区分恢复与重新生成 |
| 填表提示词 | 真正生效的全局/阶段/表级规则，发送预览；明确草稿与已启用版本 |
| 备份与迁移 | 独立导出数据/模板、旧库预览、恢复校验、旧版兼容与失败报告 |
| 外观与显示 | 保留现有设置与响应式规范，不在本轮再次重做配色 |

共享角色卡主世界书的隔离规则：

- 只有当前聊天/分支的有效提交投影，才可参与本次主 AI 上下文；条目名称不同、稳定键不同或正文过滤，并不能自动实现这种隔离。
- Q1 核对宿主是否支持请求级条目过滤/注入，优先在每次请求中绑定当前世界，避免修改别的世界业务内容。
- 若宿主只能使用持久化全局激活状态，必须明确采用单活投影策略，验证受托管条目的激活切换及并发限制；无法可靠隔离时停止自动投影并提示，不默认为安全。
- 不删除或覆盖其他聊天的世界资料。若单活策略需要切换本插件条目的激活标志，应在界面说明；不能操作用户或其他插件条目的激活状态。
- 双聊天、双分支及同角色卡并发请求必须纳入验收，不仅测试当前聊天的单次同步。

三个保存动作必须明确：

- 保存数据：修改当前世界的实际记录，产生正式提交；不是修改模板。
- 保存当前聊天模板：修改这个世界的字段和规则，必要时执行有预览的结构迁移。
- 保存为全局默认模板：只影响未来初始化/主动采用的世界，不覆盖现有聊天数据。

高级 SQL 查询默认只读；高级数据修正仍经过预览、权限与统一提交；高级 DDL 编辑经迁移检查后才保存。

修改数据、改结构、运行 AI 和同步世界书显示不同的后果提示，不让一个“保存”按钮同时偷偷执行所有动作。

## 11. 六个实施阶段

阶段名使用 Q1–Q6，避免与既有 M、S、U、D2 编号混淆。每阶段完成后报告实际结果与剩余限制，再进入用户指定的下一阶段。

### Q1：基线与模板、存档协议

目标：先定义各层之间的契约，避免 SQLite、UI 和存档各做一套格式。

修改/调查内容：

- 记录 alpha.16 代码、现有数据格式与 UI 基线；保留未完成真机验证的标记。
- 只读核对宿主消息附加数据、保存确认、消息身份、swipe/分支及事件接口，固定初始化/手动/自动提交的承载规则。
- 核对共享主世界书的请求级过滤或单活投影能力；不具备可靠聊天隔离时，记为投影阻断项。
- 定义模板、字段、关系、可见性、表组和支持的 DDL 子集。
- 定义 commit/checkpoint/log、模板版本、幂等与删除依赖规则。
- 定义 SQLite ↔ 规范化 JSON 的转换接口、存档/缓存网关和模拟模型接口。
- 给出默认完整表格草案及“环境＋NPC”最小测试模板，不改变现有聊天。
- 记录旧文档替代关系及新旧写入路径隔离方式。

交付：协议说明、默认/最小模板样例、接口与字段映射、模拟数据和基线记录。

验收：一个示例世界按协议序列化再恢复，ID、引用、模板版本和可见性完全一致；尚不接真实 AI 或宿主写入。

### Q2：SQLite 内核与受限 SQL

目标：证明这是可用的真实 SQL 数据库，并且不会任意写表。

修改内容：

- 接入并锁定浏览器 sql.js 版本；验证 WASM 加载、CDN/import 与现有 webpack 构建。
- 优先评估单文件内联 WASM；记录包大小、启动时间、失败提示和卸载释放。
- 模板生成真实表格、SQL 查询、绑定参数、JSON 导入导出和结构约束。
- 实现只读查询、授权业务写入、稳定身份分配、短事务和执行前后差异校验。
- 实现语法白名单、表/列/记录范围、行数和资源预算，不承诺任意 SQL 都可执行。
- 私有临时库和正式读取视图隔离；手动编辑与模型更新共享核心提交检查。

交付：SQLite 内核、受限执行器、模板转换和模拟回归测试；不替换现有实际存档。

验收：合法指令修改成功；夹带非法 SQL、越权写入或无效引用的一批指令整体失败，原状态保持不变；导出再导入得到等价数据。

### Q3：宏观 → 微观纵向雏形

目标：先验证世界演变行为，而不是先把全部页面铺满。

修改内容：

- 使用一张环境表、一张 NPC 表，以及最小事件日志/投影预览。
- 复用 API 客户端接口，但测试注入假模型，不访问网络。
- 模拟一次“天气改变 → 通行受阻 → NPC 调整行动”的连续演变。
- 宏观结果只在私有库生效；微观上下文必须读取该最新结果。
- 模拟存档适配器从一开始遵守 Q1 提交协议，而不是另外发明临时格式。
- 统一提交与取消，验证输入/模板过期、数量限制和微观失败不留下宏观半成品。
- 提供最小可视化结果：旧值、新值、所属阶段、来源和单次提交记录。

交付：可查看的小雏形、模拟生成与保存链、阶段日志和测试报告。

验收：看见一轮宏观影响 NPC 的完整结果，只产生一次正式模拟提交；关闭并重建模拟运行时后能恢复同一状态，不调用 AI。

边界：这时是模拟存档雏形，不能声称真实酒馆聊天保存或世界书写入已经通过。

### Q4：聊天 JSON 存档与确定性恢复

目标：把经过证明的雏形接入可靠存档，解决刷新、删楼和分支后的状态问题。

修改内容：

- 实现独立命名空间的宿主保存网关及保存确认，精确合并本插件字段。
- 接入完整提交快照、SQL 日志、模板历史、提交链和指纹校验。
- 确认持久化成功后才切换内存与缓存；处理确认丢失、重复提交及多实例冲突。
- 刷新、聊天切换、缓存丢失、swipe 和分支恢复。
- 删除/修改中间消息时恢复有效祖先并标记依赖结果过期，不自动调用 AI 重算。
- 评估快照存档体积；检查点压缩仅在恢复等价性验证后启用。
- 补充整个当前世界清空、损坏存档报告与备份恢复的模拟测试。

交付：宿主适配器、存档恢复服务、楼层事件协调、损坏报告和恢复测试。

验收：模拟宿主先全部通过；获授权在指定测试聊天写入后，刷新能恢复同一提交，删楼/分支按规则恢复，不产生生成费用。

授权关口：写实际聊天、删测试楼层或清空记录前，需用户明确指定测试范围。未获授权只能完成模拟验收，并标记真实宿主部分待验收。

### Q5：表格工作台与 DIY 模板

目标：让用户真正能填表、改结构和控制 AI 读取范围。

修改内容：

- 世界资料页增加宏观/微观分组导航、行/单元格编辑、搜索分页和锁定。
- 增加结构与参数编辑：列类型、说明、规则、上下文、预算与世界书设置。
- 当前数据、聊天模板和全局默认模板分开保存。
- 接入七张默认表并支持新增业务表；模板实际进入两个阶段的提示词和 SQL 校验。
- 增加发送预览及变化预览；兼容现有 API 路由与提示词配置。
- 实现字段新增、显示改名、类型变化、删列和表组调整的迁移预览与校验。
- 模板迁移绑定新提交；失败不留下“新结构＋旧数据”的半完成世界。
- 保留当前居中、语义色和响应式规则，验收 100% / 110% / 125% 缩放。

交付：可填写的工作台、真正生效的模板编辑器、默认模板、上下文预览和结构迁移报告。

验收：用户增加一个业务字段、填写值并模拟运行后，该字段出现在允许的 AI 上下文、校验和所选投影中；类型不兼容时得到明确报告，不偷偷丢数据。

授权关口：阶段测试默认仍使用模拟模型与模拟/隔离存档；真实请求和现有世界改结构不是本计划书本身的授权。

### Q6：旧数据迁移、世界书投影与发布验收

目标：保留旧数据与已有功能，提供可用且可回退的完整版本。

修改内容：

- 只读解析 alpha.11 IndexedDB 数据与现有 JSON 备份，生成迁移预览。
- 保留稳定 ID、引用、可见性、事件和计划；不支持字段原样备份并报告，不静默删除。
- 旧历史无法证明新协议等价时，保留审计备份并建立迁移基线，不伪造“历史全兼容”。
- 确认迁移新存档可恢复后再切换事实源；旧库保留，不直接删除。
- 更新世界书映射以支持自定义表与字段；复用稳定键、内容指纹、托管范围及失败重试机制。
- 投影只读取正式有效提交，写当前角色卡主世界书；无主世界书时明确提示，不随意换目标。
- 不删除或覆盖同名用户条目、其他聊天的托管业务内容、MVU 和 TavernDB 条目；本插件激活切换仅按已验证的聊天隔离策略进行。
- 对正文、索引、标题和关键词统一执行可见性过滤，禁止后台秘密间接泄露。
- 验证启动隔离、旧版写入停止、新旧包不能同时推进同一世界。
- 运行完整模拟回归、构建、包体/WASM 加载验证、真机清单和导入包检查。
- 编写普通用户说明书，列出数据保存、真实 API、模板修改和世界书写入的区别。

交付：迁移工具与报告、投影适配、完整测试记录、候选导入 JSON、固定版本 bundle、发布说明和恢复指引。

验收：代表性旧世界迁移前后关键数据一致；重新打开能恢复；手动编辑、两阶段生成、存档、投影和恢复能够串起来。

授权关口：迁移实际数据、写角色卡世界书、真实 API 验证，以及 Git 提交/推送均需对应用户授权。模拟通过不替代真机验收。

候选版本号在发布前确认；本计划不自动占用 alpha.17 或覆盖现有 `@main` 导入地址。

## 13. 回归测试矩阵

| 场景 | 必须得到的结果 |
| --- | --- |
| JSON → SQLite → JSON | 结构、ID、关系和业务值等价 |
| 宏观变化后运行微观 | 微观读取暂存后的最新宏观条件 |
| 微观没有变化 | 旧微观资料保留，不输出凑数修改 |
| 微观 SQL 失败 | 本轮宏观也不正式保存 |
| DDL/系统表/跨组写入 | 执行前拒绝，不部分写入 |
| 有 WHERE 但影响全表 | 目标范围或影响行数硬检查拒绝 |
| 行锁、字段锁、秘密信息 | 执行、上下文和投影都遵守同一规则 |
| AI 等待时用户改模板/数据 | 过期结果拒绝提交 |
| 同楼重复触发、保存确认丢失 | 同一运行只形成一次提交，不再次行动 |
| 宿主保存失败 | 正式世界不前进，旧缓存不冒充新存档 |
| 保存成功后页面中断 | 再次打开恢复已落盘提交 |
| 世界书同步失败 | 数据保留；重试只同步，不重新调用 AI |
| 删除/重生成中间楼层 | 后代依赖失效，回到有效祖先，明确显示待处理范围 |
| swipe/复制/切换聊天 | 分支隔离，继承点明确，不串用世界 |
| 空聊天或无有效消息锚点 | 数据明确处于草稿，禁止伪报正式保存或建立第二事实源 |
| 同锚点多次手动编辑/模板迁移 | 追加有序提交，祖先关系完整，不覆盖旧历史 |
| 同角色卡双聊天/双分支投影 | 每次主 AI 请求只读取当前有效世界；不因旧条目仍存在而串扰 |
| 同角色卡并发投影/请求 | 请求级隔离有效，或明确限制并发；不能互相切换到错误世界 |
| 缺日志、模板或检查点 | 显示损坏与恢复路径，不无提示猜补 |
| 新增列/类型迁移/删列 | 有预览、验证和数据保留，失败不半迁移 |
| 全局默认模板修改 | 不覆盖已经存在的聊天世界 |
| 旧 IndexedDB 迁移 | 先备份和验证，保留 ID/引用/可见性 |
| 清空当前世界 | 只影响本插件数据与托管投影，不复活旧缓存 |
| 默认导出 | 不包含 API Key 等凭据 |
| 构建/import/WASM | 固定版本可加载；加载失败可诊断，无残留旧写入器 |
| 页面缩放与长表 | 100%/110%/125% 布局可用；长表有分页/可控滚动 |

所有自动化测试使用模拟模型、模拟宿主和模拟世界书网关；不得因测试脚本默认行为访问真实 API。
